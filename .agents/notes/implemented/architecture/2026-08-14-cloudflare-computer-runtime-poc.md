# Agent Note: Prove the Cloudflare Computer runtime boundary

Status: implemented

English | [中文](2026-08-14-cloudflare-computer-runtime-poc.zh.md)

The broader runtime decision remains current. Its shell-placement and mandatory-Paid conclusions are superseded by [Make the direct Edge shell the free default](./2026-08-17-free-direct-edge-shell.md); its instance-selection and unauthenticated-entry details are superseded by [Single-owner authentication for dsh-edge](./2026-08-16-single-owner-edge-auth.md).

## Problem

The shipped DSH Web application assumes a long-lived Node.js host with access to local files, subprocesses, and a loopback HTTP server. A Cloudflare Workers deployment cannot provide those Node host capabilities directly. Before porting the full agent graph or mirroring the Web UI, the fork needs evidence that one edge instance can durably store workspace files, execute useful shell commands against those files, and carry a native DSH model/tool exchange across that runtime boundary.

## Decision

Add `apps/dsh-edge` as an independent, private Cloudflare application. The entry Worker selects one fixed owner `DshEdgeInstance` Durable Object. Cloudflare Computer's SQLite-backed workspace owns that object's virtual filesystem, and its configured workspace backend runs just-bash commands against the same workspace. The current default is the in-process direct backend; an optional Loader binding selects Worker Shell.

The outer Worker serves ordinary immutable browser assets directly through Cloudflare, while `/`, `/login`, and `/api/*` execute Worker code first. After the single-owner boundary, it routes runtime APIs through the selected Durable Object or the Edge workspace adapter; health and authentication routes remain at the entry Worker. The browser assets are the upstream Web shell plus a build-time graph of upstream `dsh.client` bundles derived from the base and Web bundle configs. The assembler excludes HMR and client plugins whose required host domains are absent; it does not fork browser source. It emits Cloudflare asset headers that prevent the shell from being framed through `/`, `/index.html`, or any SPA fallback alias, including aliases that bypass Worker execution. The Durable Object implements the supported upstream `ApiProxy` methods through the existing WHATWG fetch carrier and implements mux and host downlinks with hibernatable WebSockets. It preserves upstream request and response envelopes, event frames, projections, correlation ids, lazy blank-session creation, and workspace attachment updates. An empty generated-Remote command catalog keeps the upstream command client mounted without advertising commands the Edge preset does not provide.

The diagnostic health, UTF-8 file read/write/delete, synchronous command execution, persistent REST session, SSE turn, and replay routes remain available beside the upstream browser protocol. Inside the Durable Object, the upstream `SessionStore` and `SessionPersistence` services remain responsible for the session lifecycle. A new Durable Object SQL backend implements the six `PersistenceBackend` storage primitives with the same `SessionHeader`/`SessionEvent` column mapping as the upstream SQLite backend, while `PersistenceCoordinator` owns lazy materialization, write-behind, revisions, resume preparation, and crash recovery. Two internal coordinator extensions keep Edge policy out of the public persistence service: `readValidatedPage()` validates a backend-private bounded replay loader, and `abandonUnmaterialized()` discards a failed first batch before session disposal can retry it. The only Edge-owned session table, `dsh_edge_blank_sessions`, retains the upstream header of a still-empty live session across transparent Durable Object hibernation. The first canonical event materializes the standard header/event rows and removes that retained header in the same SQL transaction; a cold prompt first promotes it to a standard empty log for the upstream resume path. No Edge-owned turn or message schema exists. The diagnostic REST create route requires a title so a canonical `session/title` event materializes the upstream session before the HTTP response; upstream `session.create` retains lazy blank-session semantics. Session turns resolve deployment settings before claiming an owner and flush canonical events before broadcasting them through WebSockets or sending them through SSE. During an active turn, protocol `queue` and `steer` requests reuse the live agent and its prepared model, shell, and event observer; they enter the native `next-turn` and `next-step` inboxes respectively. A scoped `agent/pre-step` gate prevents a claimed prompt from becoming model-visible until its inbox mutation crosses the durable flush barrier. If that barrier fails after enqueue has already woken the driver, the RPC remains accepted rather than contradicting the live mutation, the gate blocks model use, and the turn reports the persistence failure through the host channel. Every committed inbox splice emits the upstream full `session/queue` snapshot, and a mux reconnect receives the current pending live inbox after its subscription baseline. The admission gate opens only after the initial runtime bindings are ready and closes synchronously before handle disposal, so a boundary race retries against a fresh owner instead of writing through a stale agent. Replay resumes after an upstream `seq`, and an escaped Edge transport failure errors the response stream instead of presenting a normal end-of-file.

The agent endpoint uses the upstream Cordis-composed `ReactLoopAgent`, `AgentRegistry`, `LlmRuntime`, `ToolRuntime`, and `SystemPrompt`. New sessions are created through the registry and cold sessions resume through its persistence-aware factory. Edge code binds an upstream `DeepSeekAdapter` to the active session for one request and registers a native `ToolDefinition` whose `bash` body executes through the configured Computer workspace backend. The API key comes from a Worker secret or request header, is normalized and validated before an SSE stream is opened, is selected through the loop-stamped session id, and is never persisted. Base URL, model id, reasoning effort, output cap, and stream idle timeout are validated deployment choices before session acquisition; defaults remain the official endpoint, V4 Flash, reasoning off, 8,192 tokens, and 120 seconds. Computer commands also receive a validated deployment default timeout and caller-selectable ceiling, both 120 seconds by default.

This is an explicit edge composition of the native agent loop and Web protocol, not a port of every local host plugin. The supported browser path uses upstream transport and UI definitions directly; Edge code owns only the Worker carrier, runtime implementations, capability selection, and the single-owner login shell. Remaining tools, writable settings, generated host remotes, and compaction remain outside this prototype.

## Alternatives considered

- **Port the DSH graph before proving the runtime:** this would mix Worker compatibility failures with agent and transport integration failures, making the first deployment difficult to diagnose.
- **Copy the DeepSeek HTTP protocol into the edge app:** that would produce a generic DeepSeek client and let provider behavior drift from DSH. Reusing the upstream adapter and content protocol gives the fork a native integration point.
- **Reuse the local bash plugin unchanged:** its subprocess, sandbox, terminal, and job dependencies are host capabilities that Workerd cannot provide. Adapting at the tool execution seam keeps the model contract while stating the smaller runtime honestly.
- **Use a Cloudflare Container as the first backend:** a container more closely resembles the local Node runtime, but it does not test the lower-cost Durable-Object VFS and just-bash design that distinguishes this fork.
- **Modify `apps/web` in place:** the Web shell and browser transport already separate browser code from the host implementation. Building those sources unchanged and adapting the server preserves upstream synchronization; an Edge-specific UI fork would duplicate presentation and protocol behavior.
- **Materialize a synthetic event for blank sessions:** a no-op event would make hibernation durable without another table, but it would change canonical history solely for the Edge runtime. Retaining only the upstream header preserves the empty-log semantics.

## Consequences

- The owner filesystem survives Worker requests and local Wrangler restarts; model-issued shell commands observe writes made through the file API.
- The upstream Web UI boots from Cloudflare static assets without invoking the Worker for ordinary asset requests. `/`, `/login`, and `/api/*` run Worker code first. Asset-layer `frame-ancestors 'none'` and `X-Frame-Options: DENY` headers cover every shell alias, including direct `index.html` and SPA fallbacks. The browser opens the standard HTTP RPC carrier plus mux and host WebSockets; Durable Object hibernation attachments retain the channel and authenticated owner-session expiry, while canonical session and workspace state is reconstructed from upstream persistence. A Durable Object alarm closes each downlink at that expiry, including across hibernation. Mux clients receive durable live queue snapshots and a pending-inbox baseline on reconnect, matching the upstream transient-state contract. Queue edit/remove/steer uses the live upstream Agent inbox and its synchronous mutation as the acceptance point; the persistence coordinator owns later write-behind and retirement retry.
- The Edge workspace adapter stores the upstream workspace-domain global value and `WorkspaceRecord` value under Durable Object keys. It changes the physical backend and constrains the registry to the native `/workspace` VFS, but preserves the upstream list/create/rename/delete/order/archive RPC values and Host frames. Durable Object transactions atomically pair record and registry-order writes.
- Browser features are selected by server capability at assembly time. The graph retains unchanged upstream bundles for the shell, connection, runtime, workspace, conversation, model selection, skills, subagents, tools, and related passive projections. It omits HMR, writable model/plugin settings, Cordis inspection, goals, feedback, and plan clients until their host domains exist. Adding one of those domains restores its upstream client bundle rather than creating an Edge component.
- The edge turn preserves DSH message, stream, tool-call, usage, failure, and attribution semantics. The attribution module now imports its package metadata statically because Workerd bundles do not provide a usable `import.meta.url` to Node's `createRequire`.
- Each workspace instance persists multiple conversations. New and resumed sessions use the upstream `AgentRegistry` and live `SessionStore` lifecycle; the loop factory performs persistence preparation and ordered session/agent publication on cold resume. A retained blank header substitutes only for the process-local owner that upstream loses on host restart, because Durable Object hibernation is transparent to the connected Web client. The first prompt converts that header into the canonical session log. Session rename appends the standard user-owned title event to active or cold sessions and uses that synchronous append as the upstream acceptance point; `PersistenceCoordinator` owns later write-behind or retirement retry. Session fork copies one bounded completed-turn prefix through the canonical seed format and records upstream parent lineage. The registry-global archive set uses the upstream workspace-domain global shape through a serialized Durable Object value, while archived sessions retain their canonical log and workspace slot. Every turn owns one handle until the stream completes, preventing unbounded resident-agent growth without an Edge event or message schema. Canonical `session/end-seed` events mark each cold lifecycle and fork seed. `ReactLoopAgent` derives model history and owns inbox, request, assistant, tool, error, cancellation, and turn/step events. Streamed turn events cross the upstream flush barrier before SSE or WebSocket delivery. The event log is the only conversation source of truth.
- One session accepts one active turn. A synchronous process-local owner claim rejects concurrent turns, an explicit cancel request calls the native agent cancellation path, and a disconnected SSE consumer does not stop event persistence. A later cold resume runs upstream interrupted-turn repair over an open persisted tail.
- Worker Shell is not a Linux process. Commands are limited to just-bash and explicitly registered modules, so future DSH tools must declare unsupported process and native-binary behavior rather than silently emulating it. Every execution receives an explicit timeout. Its cancellation status records whether the adapter requested interruption instead of inferring intent from conventional exit codes, while `timedOut` independently records deadline expiry.
- The entry Worker enforces the single-owner access-key and cookie boundary. Legacy instance selectors are rejected rather than treated as identities.
- `apps/dsh-edge` is a private deployment application, so workspace constraints and npm release discovery exclude that exact manifest from the public DSH release family while still allowing pnpm workspace dependencies and filtering. The exception is path-scoped so another package accidentally marked private remains visible to publish validation. Its composite TypeScript project participates in the repository Host aggregate even though Wrangler remains its deployment entrypoint.
- Text-file, command, and user-message admission measure UTF-8 bytes rather than JavaScript code units, and uploads reject malformed UTF-8. File GET checks VFS metadata and then bounds the actually opened Computer byte stream, covering concurrent growth after the metadata read. Shell execution consumes the raw event stream instead of calling its unbounded `result()` collector, retains at most 64 KiB across stdout and stderr, and requests `SIGINT` on overflow while draining without further accumulation.
- JSON and file-upload bodies are consumed incrementally with route-specific retention bounds before parsing or Durable Object forwarding. Oversized bodies are drained without retaining later chunks and return 413. If the first canonical title flush fails, `abandonUnmaterialized()` discards its retained batch before the upstream `AgentHandle` is disposed, so teardown cannot make a session durable after its create request failed.
- Cold event replay keeps its bounded operation on the concrete Durable Object persistence facade and passes its backend-private loader through `PersistenceCoordinator.readValidatedPage()` for canonical identity, format, legacy-record, and event-type validation. SQL first reads event byte lengths and then materializes only rows within the 1 MiB replay budget; legacy normalization that needs earlier messages rereads one prefix through the same bounded loader and refuses when the required prefix cannot fit. Event count and exact encoded SSE limits still apply before continuation headers are exposed. Upstream `session.history` applies one shared Edge budget before live and cold paths diverge: at most 50 append-origin messages, 8,192 events, and 8 MiB. Cold history discovers its message cut in SQL before decoding payloads and accounts stored bytes; live history locates the cut without first copying the full in-memory window and accounts encoded response bytes. Over-budget history is refused rather than truncated. Only true absence maps to 404, while corrupt events, unsupported formats, and Durable Object SQL failures preserve their server-error semantics. Live SSE has a 1 MiB byte-weighted client queue; exceeding it disconnects that client without cancelling event persistence. Session listing merges retained blank headers with bounded canonical summaries; detail, model-directory, model-selection, and turn-admission existence checks use durable point reads. Only agent resume decodes canonical history. The detail response contains durable metadata only; paginated events are the history API.
- Prompt and queue-edit text share one 64 KiB UTF-8 semantic limit inside the larger RPC carrier. Session creation and fork resolve Workspace ownership before publication when possible; if publication succeeds but attachment fails, the upstream `workspace-attach-failed` error carries the published ids. A browser composition without directory flow hides Delete on its last Workspace, so every visible destructive capability retains a recovery path.
- `@cloudflare/computer` and just-bash remain preview-sensitive dependencies. The default direct backend requires no Worker Loader; the optional isolated backend uses Worker Loaders and Dynamic Workers on Workers Paid. The host Worker keeps only `nodejs_compat`; Cloudflare rejects the `experimental` compatibility flag in deployed Workers. Storage and direct-shell type compatibility casts stay at narrow construction or adapter boundaries and must be rechecked when dependencies change.

## Verification

`@deepseek-ai/dsh-edge` participates in the repository Host TypeScript aggregate and passes native `ReactLoopAgent` and Computer-tool binding tests, deployment timeout validation and pre-read file-bound tests, live-stream success/failure tests, generated-Remote carrier tests, the upstream 12-case `SessionPersistence` contract suite against the Durable Object SQL backend, and local Wrangler session integration. Release-family tests prove only the known Edge manifest is excluded while an ordinary private package remains discoverable. The shared persistence contract covers lazy materialization, round trips, suffix reads, revision changes, cancellation, contiguity and JSON validation, plus interrupted turn/tool recovery. The shared attribution tests confirm that static metadata still matches the LLM package manifest. Wrangler dry-run bundles the Worker and 150 production assets successfully.

The integration run uses an SSE DeepSeek stand-in with the real Wrangler, Durable Object SQLite, Computer runtime, upstream HTTP carrier, hibernatable WebSockets, and static assets. It proves the shell and plugin assets are served, both downlinks open, the upstream host description and session create/list/history/prompt/updateQueue/rename/fork plus workspace list/create/rename/delete/order/archive methods retain their schemas, queue edit/remove/steer crosses the durable inbox path, complete queue snapshots arrive live and after reconnect, workspace mutation frames arrive, and workspace plus archive state survives restart. A focused agent test forces the post-enqueue durability barrier to fail and proves admission still resolves while the pre-step gate prevents a user message or model request. A headless Chrome run boots the actual upstream Web graph, renames the Edge workspace, sends one turn through the UI, executes its branch, session rename, and archive chain, and renders the forked transcript plus archived sidebar without failed HTTP responses or page exceptions; committed ARIA goldens pin both assembled browser states.

The diagnostic integration proves titleless and normalization-empty titles return client errors before an ephemeral session can escape, malformed session-id, replay/list limits and cursors, and overflowing replay sequences return 400, malformed file UTF-8 returns 400, oversized session JSON and a multibyte file upload return 413 through streaming body admission, text-file, command, and user-message limits use UTF-8 bytes, deployment model, reasoning, output, and command-timeout configuration reach their runtime consumers, malformed provider configuration returns JSON before SSE and provider access without leaving a busy owner, command timeout is reported independently, a conventional signal exit code without an adapter interrupt reports failure, multibyte shell output stays within the combined 64 KiB retention bound without a replacement character, and a blank API-key header returns `INVALID_CREDENTIAL` as JSON before SSE opens. A focused stream test covers file growth after the metadata check. The integration also proves a blank identity is durable before its first event, successful prompt barriers persist inbox admission before model visibility, active-turn queue and steering retain their native inbox targets, legacy instance selectors are rejected so every accepted request stays on the fixed owner, and per-turn handle disposal and canonical cold-resume markers preserve history, bounded event and session-summary pagination, metadata-only detail after restart, a two-step `bash` tool call, cancellation, and restart recovery. Focused persistence tests prove retained blank promotion, a failed first materialization is abandoned before disposal can retry it, existence and detail use format-checked point queries, a cold 60-message history requesting two messages loads only those two payload rows, an oversized history request is capped before boundary materialization, a bounded event page refuses unsupported format versions and unknown required event type, and replay stops before loading an event outside its byte budget; the live-stream test proves a slow client disconnect does not stop its producer. The formal keyless snapshots pin the default actual DeepSeek request, full model-visible system prompt and bash schema, live canonical event stream, cold replay from durable storage, and the browser-rendered transcript without unavailable export controls.
