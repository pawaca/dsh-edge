# Agent Note: 验证 Cloudflare Computer 运行时边界

Status: implemented

[English](2026-08-14-cloudflare-computer-runtime-poc.md) | 中文

更广泛的运行时决策仍然有效；其中关于 shell placement 与强制 Paid 的结论由[《将 direct Edge shell 设为免费默认模式》](./2026-08-17-free-direct-edge-shell.md)取代，关于 instance selection 与未认证入口的细节由[《dsh-edge 单 owner 身份认证》](./2026-08-16-single-owner-edge-auth.md)取代。

## 问题

现有 DSH Web 应用假设存在一个长期运行的 Node.js host，可以访问本地文件、启动 子进程并提供 loopback HTTP server。Cloudflare Workers 无法直接提供这些 Node host 能力。在移植完整 agent graph 或镜像 Web UI 之前，该 fork 需要先证明一个 edge 实例能持久保存 workspace 文件、针对这些文件执行实用的 shell 命令，并让一次原生 DSH model/tool 交互跨越该运行时边界。

## 决策

新增 `apps/dsh-edge`，作为独立、私有的 Cloudflare 应用。入口 Worker 选择一个固定的 owner `DshEdgeInstance` Durable Object。Cloudflare Computer 基于 SQLite 的 workspace 拥有该对象的虚拟文件系统，配置的 workspace backend 会针对同一 workspace 执行 just-bash 命令。当前默认为进程内 direct backend；可选 Loader binding 会选择 Worker Shell。

外层 Worker 通过 Cloudflare 直接提供普通 immutable 浏览器资源，而 `/`、`/login` 与 `/api/*` 会先执行 Worker 代码。经过单 owner 边界后，runtime API 会路由到所选 Durable Object 或 Edge workspace adapter；health 与 authentication route 留在入口 Worker。浏览器资源由上游 Web shell 和构建期生成的上游 `dsh.client` 包 graph 组成，该 graph 根据 base 与 Web 组合包配置推导。Assembler 会排除 HMR 及缺少所需 host domain 的客户端插件，不会 fork 浏览器源码。它会生成 Cloudflare asset headers，阻止通过 `/`、`/index.html` 或任意 SPA fallback alias（包括绕过 Worker execution 的 alias）嵌入 shell。Durable Object 通过现有 WHATWG fetch carrier 实现受支持的上游 `ApiProxy` 方法，并用支持休眠的 WebSocket 实现 mux/host downlink。它保留上游 request/response envelope、event frame、projection、correlation id、lazy blank-session 创建和 workspace attachment update。空的 generated-Remote command catalog 可以保留上游 command client，同时不会宣称 Edge preset 提供并不存在的命令。

诊断用的健康状态、UTF-8 文件读写/删除、同步命令执行、持久 REST session、SSE turn 和 replay 路由会与上游浏览器协议并存。Durable Object 内部的 session 生命周期仍由上游 `SessionStore` 和 `SessionPersistence` service 负责。新的 Durable Object SQL backend 使用与上游 SQLite backend 相同的 `SessionHeader`/`SessionEvent` 列映射，实现六个 `PersistenceBackend` 存储原语；lazy materialization、write-behind、revision、resume preparation 和 crash recovery 由 `PersistenceCoordinator` 负责。两个内部 coordinator 扩展会把 Edge 策略留在公共 persistence service 之外：`readValidatedPage()` 校验 backend 私有的有界 replay loader，`abandonUnmaterialized()` 则在 session disposal 能够重试失败的首批数据前将其丢弃。唯一由 Edge 拥有的 session 表 `dsh_edge_blank_sessions` 会在透明的 Durable Object 休眠期间保留仍为空的 live session 的上游 header。首个 canonical event 会在同一个 SQL transaction 中 materialize 标准 header/event rows 并移除该保留 header；冷 prompt 会先把它提升为标准 empty log，再进入上游 resume path。Edge 不定义自有 turn 或 message schema。诊断 REST create 路由要求标题，以便在 HTTP response 前通过 canonical `session/title` event materialize 上游 session；上游 `session.create` 则保留 lazy blank-session 语义。Session turn 会先解析部署 settings，再声明 owner；canonical events 会在通过 WebSocket 广播或 SSE 发送前完成 flush。活动 turn 中的协议 `queue` 和 `steer` 请求会复用 live agent 及其已准备好的 model、shell 和 event observer，分别进入原生 `next-turn` 和 `next-step` inbox。一个 scoped `agent/pre-step` gate 会阻止已 claim 的 prompt 变为 model-visible，直至其 inbox mutation 跨过 durable flush barrier。如果该 barrier 在 enqueue 已唤醒 driver 后失败，RPC 会保持 accepted，不再与 live mutation 矛盾；gate 会阻止模型调用，turn 则通过 host channel 报告持久化失败。每次已提交的 inbox splice 都会发送上游完整 `session/queue` snapshot；mux 重连会在 subscription baseline 后收到 live inbox 当前的待处理状态。Admission gate 只会在初始 runtime binding 就绪后打开，并会在 handle disposal 前同步关闭，因此边界竞态会针对新的 owner 重试，而不会通过 stale agent 写入。Replay endpoint 从指定 `seq` 后恢复；如果 Edge transport failure 逃逸到该边界，response stream 会进入 error 状态，而不是表现为正常 EOF。

Agent endpoint 使用上游 Cordis-composed `ReactLoopAgent`、`AgentRegistry`、`LlmRuntime`、`ToolRuntime` 和 `SystemPrompt`。新 session 通过 registry 创建，冷 session 通过其 persistence-aware factory 恢复。Edge 代码只为一次请求把上游 `DeepSeekAdapter` 绑定到 active session，并注册一个原生 `ToolDefinition`，其 `bash` body 通过配置的 Computer workspace backend 执行。API key 来自 Worker secret 或请求头，在打开 SSE stream 前完成 normalization 和校验，通过 loop 写入的 session id 选择，且绝不会持久化。Base URL、model id、reasoning effort、输出上限和 stream idle timeout 都会在获取 session 前作为部署选择完成校验；默认值仍为官方 endpoint、V4 Flash、reasoning off、8,192 tokens 和 120 秒。Computer 命令还会收到经过校验的部署级默认 timeout 与调用方可选值上限，两者均默认为 120 秒。

这是原生 agent loop 和 Web protocol 的显式 edge composition，不是所有本地 host plugin 的完整移植。受支持的浏览器路径直接使用上游 transport 和 UI 定义；Edge 代码只负责 Worker carrier、运行时实现、能力选择和单 owner 登录外壳。其余工具、可写 settings、generated host remote 和 compaction 仍不属于当前原型。

## 考虑过的替代方案

- **先移植 DSH graph，再验证运行时：** 这会把 Worker 兼容性故障与 agent、 transport 集成故障混在一起，使首次部署难以诊断。
- **在 edge app 中复制 DeepSeek HTTP 协议：** 这会得到一个通用 DeepSeek client， 并使 provider 行为逐渐偏离 DSH。复用上游 adapter 和 content protocol 能让 fork 获得原生集成点。
- **原样复用本地 bash plugin：** 它依赖的 subprocess、sandbox、terminal 和 job 都是 Workerd 无法提供的 host capabilities。在 tool execution seam 上适配，可以 保留 model contract，同时如实说明更小的运行时能力。
- **首先使用 Cloudflare Container 后端：** container 更接近本地 Node 运行时， 但无法验证更低成本、也更能体现该 fork 差异的 Durable Object VFS 与 just-bash 方案。
- **直接修改 `apps/web`：** Web shell 和浏览器 transport 已经把浏览器代码与 host 实现分开。原样构建这些源码并适配服务端，可以保持与上游同步；Edge 专用 UI fork 会重复 presentation 和 protocol 行为。
- **为 blank session 物化一个 synthetic event：** no-op event 可以在不增加表的情况下提供休眠持久性，但会仅为 Edge runtime 改写 canonical history。只保留上游 header 可以维持 empty-log 语义。

## 后果

- Owner 文件系统可跨 Worker 请求和本地 Wrangler 重启保留；由 model 发出的 shell 命令能观察到通过 file API 写入的内容。
- 上游 Web UI 从 Cloudflare 静态资源启动，普通资源请求不会调用 Worker。`/`、`/login` 与 `/api/*` 会先执行 Worker 代码。Asset 层的 `frame-ancestors 'none'` 与 `X-Frame-Options: DENY` headers 会覆盖每个 shell alias，包括直接 `index.html` 和 SPA fallback。浏览器打开标准 HTTP RPC carrier 以及 mux/host WebSocket；Durable Object hibernation attachment 会保留 channel 与已认证 owner session 的过期时间，canonical session 与 workspace 状态则从上游 persistence 重建。Durable Object alarm 会在该时间关闭 downlink，即使对象曾经休眠。Mux client 会收到持久提交后的实时 queue snapshot，并在重连时收到 pending-inbox baseline，与上游 transient-state contract 保持一致。Queue edit/remove/steer 使用 live upstream Agent inbox，并以同步 mutation 作为接纳点；后续 write-behind 与 retirement retry 由 persistence coordinator 负责。
- Edge workspace adapter 会把上游 workspace-domain global value 与 `WorkspaceRecord` value 存在 Durable Object key 下。它只更换物理 backend，并把 registry 限制为原生 `/workspace` VFS，同时保留上游 list/create/rename/delete/order/archive RPC value 和 Host frame。Durable Object transaction 会原子组合 record 与 registry-order 写入。
- 浏览器功能会在组装时按服务端能力选择。Graph 保留 shell、connection、runtime、workspace、conversation、model selection、skills、subagents、tools 及相关 passive projection 的原样上游包；在对应 host domain 存在之前，排除 HMR、可写 model/plugin settings、Cordis inspection、goals、feedback 和 plan client。增加其中一个 domain 时恢复其上游客户端包，而不是创建 Edge component。
- Edge turn 保留 DSH 的 message、stream、tool-call、usage、failure 和 attribution 语义。Attribution 模块现在静态导入自身 package metadata，因为 Workerd bundle 不会为 Node `createRequire` 提供可用的 `import.meta.url`。
- 每个 workspace 实例持久保存多个对话。新建和恢复 session 都使用上游 `AgentRegistry` 和 live `SessionStore` 生命周期；冷恢复时由 loop factory 执行 persistence preparation 以及有序的 session/agent publication。上游在 host restart 时会失去进程内 owner，而 Durable Object 休眠对已连接 Web client 是透明的，因此 retained blank header 只负责替代这一进程内状态。首个 prompt 会把该 header 转换为 canonical session log。Session rename 会向 active 或 cold session 追加标准的用户自有 title event，并把同步 append 作为上游接纳点；后续 write-behind 或 retirement retry 由 `PersistenceCoordinator` 负责。Session fork 会通过 canonical seed format 复制一个有界 completed-turn prefix，并记录上游 parent lineage。Registry-global archive set 会通过一个串行更新的 Durable Object value 使用上游 workspace-domain global shape，archived session 则保留 canonical log 和 workspace slot。每个 turn 持有一个 handle 直到 stream 完成，从而在不引入 Edge event 或 message schema 的前提下避免 resident agent 无界增长。Canonical `session/end-seed` event 会标记每次冷生命周期与 fork seed。`ReactLoopAgent` 生成模型历史，并负责 inbox、request、assistant、tool、error、cancellation 和 turn/step events；streamed turn event 会先跨过上游 flush barrier，再通过 SSE 或 WebSocket 发送。事件日志是唯一的对话真相源。
- 一个 session 同时只接受一个 active turn。同步的进程内 owner claim 会拒绝并发 turn；显式 cancel 请求调用原生 agent cancellation path；SSE consumer 断线不会停止 event 持久化。后续冷恢复会对开放的持久 event tail 运行上游 interrupted-turn repair。
- Worker Shell 不是 Linux 进程。命令能力仅来自 just-bash 和显式注册的 modules， 因此后续 DSH tools 必须明确声明不支持的进程及原生二进制行为，不能静默模拟。每次执行都会收到明确的 timeout；其 cancellation status 记录 adapter 是否实际请求过中断，而不是根据惯例 exit code 推断意图，`timedOut` 则独立记录 deadline expiry。
- 入口 Worker 执行单 owner access-key 与 cookie 边界。旧 instance selector 会被拒绝，不会被当作 identity。
- `apps/dsh-edge` 是私有部署应用，因此 workspace constraints 和 npm release discovery 会把这个精确 manifest 排除在公开 DSH release family 外，同时仍允许 pnpm workspace dependencies 和 filtering。该例外仅作用于指定路径，因此其他误设为 private 的 package 仍会进入 publish validation。它的 composite TypeScript project 会参与仓库 Host aggregate，而 Wrangler 仍是其部署入口。
- 文本文件、命令和用户消息准入按 UTF-8 字节而不是 JavaScript code unit 计数，上传会拒绝非法 UTF-8。File GET 会检查 VFS metadata，再对实际打开的 Computer byte stream 执行边界，从而覆盖 metadata 读取后的并发增长。Shell execution 直接消费原始 event stream，而不调用其无界的 `result()` collector；stdout 与 stderr 合计最多保留 64 KiB，越界时请求 `SIGINT`，随后只排空事件而不再累积输出。
- JSON 和文件上传 body 会在解析或转发给 Durable Object 之前按路由上限增量消费。超限 body 的后续 chunk 只会排空而不继续保留，并返回 413。如果首次 canonical title flush 失败，`abandonUnmaterialized()` 会在 dispose 上游 `AgentHandle` 前丢弃其保留 batch，因此 teardown 无法在创建请求失败后又把 session 持久化。
- 冷 event replay 把有界操作保留在具体的 Durable Object persistence facade，并通过 `PersistenceCoordinator.readValidatedPage()` 把 backend 私有 loader 交给 canonical identity、format、legacy-record 与 event-type 校验。SQL 会先读取 event 字节长度，再只物化 1 MiB replay 预算内的 rows；需要更早 message 的 legacy normalization 会通过同一个受约束 loader 重读一个 prefix，必要 prefix 无法装入时会拒绝。Transport 仍会在暴露 continuation headers 前限制 event 数量与编码后 SSE 的精确字节数。上游 `session.history` 会在 live/cold 分流前应用一份共享 Edge 预算：最多 50 条 append-origin message、8,192 个事件和 8 MiB。Cold history 会先在 SQL 中找到 message cut 再解码 payload，并按存储字节计费；live history 不会先复制完整内存 window，而是先定位 cut，再按编码响应字节计费。超出预算的 history 会被拒绝而不是截断。只有真实缺失才映射为 404；损坏 event、不支持的格式与 Durable Object SQL failure 会保留其服务端错误语义。Live SSE 使用 1 MiB 按字节计费的客户端队列；超限只会断开该客户端，不会取消 event 持久化。Session listing 会合并 retained blank header 与有界 canonical summary；detail、模型目录、模型选择与 turn admission 的存在性检查都使用 durable point read。只有 agent resume 会解码 canonical history。Detail response 只包含持久化 metadata；分页 events 是 history API。
- Prompt 与 queue-edit 文本在更大的 RPC 载体内共用 64 KiB UTF-8 语义上限。Session 创建与 fork 会尽可能在发布前解析 Workspace 归属；如果发布成功但 attachment 失败，上游 `workspace-attach-failed` 错误会携带已发布的 id。没有目录流的浏览器组合会在仅剩最后一个 Workspace 时隐藏 Delete，使每项可见的破坏性能力都保留恢复路径。
- `@cloudflare/computer` 与 just-bash 仍是对 preview 版本敏感的依赖。默认 direct backend 不要求 Worker Loader；可选 isolated backend 会在 Workers Paid 上使用 Worker Loader 与 Dynamic Workers。Host Worker 只保留 `nodejs_compat`，因为 Cloudflare 会拒绝部署启用 `experimental` compatibility flag 的 Worker。Storage 与 direct-shell type compatibility cast 保持在窄范围的 construction 或 adapter boundary；升级依赖时必须重新验证。

## 验证

`@deepseek-ai/dsh-edge` 会参与仓库 Host TypeScript aggregate，并已通过原生 `ReactLoopAgent` 与 Computer-tool binding 测试、部署 timeout 校验与文件预读取边界测试、live-stream 成功/失败测试、generated-Remote carrier 测试、面向 Durable Object SQL backend 的上游 12 项 `SessionPersistence` 契约测试，以及本地 Wrangler session 集成测试。Release-family 测试证明只有已知 Edge manifest 被排除，普通 private package 仍可被发现。共享 persistence contract 覆盖 lazy materialization、round trip、suffix read、revision 变化、取消、连续性与 JSON 校验，以及 interrupted turn/tool recovery。共享 attribution 测试确认静态 metadata 仍与 LLM package manifest 一致。Wrangler dry-run 可以成功打包 Worker 和 150 个生产资源。

集成运行使用 SSE DeepSeek stand-in 以及真实的 Wrangler、Durable Object SQLite、Computer runtime、上游 HTTP carrier、支持休眠的 WebSocket 和静态资源。它证明 shell 与插件资源可访问、两条 downlink 可以打开、上游 host description、session create/list/history/prompt/updateQueue/rename/fork 与 workspace list/create/rename/delete/order/archive 方法保留其 schema、queue edit/remove/steer 经过 durable inbox 路径、完整 queue snapshot 会实时送达并在重连后恢复、workspace mutation frame 可以到达，且 workspace 与 archive 状态可跨重启恢复。一个聚焦的 agent test 会强制入队后的 durability barrier 失败，并证明 admission 仍会 resolve，而 pre-step gate 会阻止 user message 与 model request。Headless Chrome 运行会启动真实的上游 Web graph、rename Edge workspace、通过 UI 发送一个 turn、执行 branch、session rename 与 archive 链路，并在没有 HTTP failure 或页面异常的情况下渲染 fork 后的 transcript 与 archive 后的 sidebar；提交到仓库的 ARIA golden 会固定这两种浏览器状态。

诊断集成证明无标题和 normalization 后为空的标题会在 ephemeral session 逃逸前返回客户端错误、非法 session-id、replay/list limit 与 cursor 以及溢出的 replay sequence 返回 400、非法文件 UTF-8 返回 400、超大 session JSON 和多字节文件上传会通过流式 body 准入返回 413、文本文件、命令和用户消息上限按 UTF-8 字节计算、部署级 model、reasoning、输出和命令 timeout 配置会进入各自的 runtime consumer、非法 provider 配置会在 SSE 与 provider access 前返回 JSON 且不会留下 busy owner、命令 timeout 会单独报告、没有 adapter 中断的惯例 signal exit code 会报告 failure、多字节 shell 输出不含 replacement character 且保持在 stdout/stderr 合计 64 KiB 的保留边界内，并且空白 API-key header 会在 SSE 打开前以 JSON `INVALID_CREDENTIAL` 返回。聚焦的 stream 测试覆盖 metadata 检查后的文件增长。集成还证明 blank identity 会在首个 event 前持久化、成功的 prompt barrier 会在 model visibility 前持久化 inbox admission、活动 turn 的 queue 和 steering 保留各自的原生 inbox target、旧 instance selector 会被拒绝以确保所有已接纳请求都留在固定 owner 上，并证明 per-turn handle disposal 和 canonical cold-resume marker 能在历史、有界 event 与 session-summary pagination、重启后的 metadata-only detail、两步 `bash` tool call、取消及重启恢复中保持正确语义。聚焦的 persistence 测试证明 retained blank promotion、首次物化失败时会在 disposal 能够重试前放弃该 session、existence 与 detail 使用经过 format 校验的 point query、包含 60 条 message 的冷 history 在请求 2 条 message 时只加载这 2 个 payload row、超大 history 请求在物化 boundary 前被封顶、有界 event page 会拒绝不支持的 format version 和未知 required event type，并且 replay 会在加载超出字节预算的 event 前停止；live-stream 测试则证明慢客户端断线不会停止 producer。正式 keyless snapshots 固定了默认的实际 DeepSeek request、模型可见的完整 system prompt 与 bash schema、live canonical event stream、从 durable storage 冷重放的结果，以及不含不可用 export 控件的浏览器对话。缺少 key 的路由在消费 request body 后返回 401。仓库测试不会保存或使用真实 provider key。
