## dsh-edge 0.18.0

将 0.18.0-alpha.1 中的 Linux 容器运行时、按能力引导的安装器和运行设置提升到 npm 的稳定频道 `latest`。在 Workers Paid 上，实例可以加一个 Linux 容器，用于 git、npm、node 和 python3；每条 bash 命令按需要在轻量 shell 或容器中运行。上游 Harness 基线保持 0.1.5-rc.2。

### 自 0.17.0 以来的变更

- **Linux 容器**（#218、#219、#226）：即“+ Work on code projects”能力，需要 Workers Paid。
  - 容器挂在实例的 Durable Object 上，使用 `basic` 实例规格。
  - 自带 git、node 22、npm、python3、jq、make、bzip2、xz、zstd、zip 和 unzip。
  - 每次发版都会发布对应版本的镜像 `docker.io/pawaca/dsh-edge-computer:<version>`。
  - 工作区文件保存在 Durable Object 中并与容器同步，因此停止或替换容器不会丢失文件。
  - 容器可以访问互联网，但不会拿到任何 Edge 凭据。
  - 闲置一段时间后（默认 10 分钟）容器进入休眠，下一条 Linux 命令会唤醒它。容器内同时最多运行 2 条命令。
- **按命令分流**（#221、#223、#224）：文件和文本操作留在轻量 shell；git、npm、python3 等只有 Linux 才有的程序进入容器。
  - 轻量 shell 跑不了的命令，如果没有改动任何文件，就透明地在容器中重跑（`retriedFromLight`）。这包括工具报告不支持的命令，以及访问了 `/workspace` 之外路径的命令，例如 `/etc/os-release`。
  - 如果命令已经改动了文件，则报告为 `lightShellMiss`，由 agent 决定是否重试。重跑共用这条命令的超时时间。
- **运行设置**（#227、#228）：DSH Edge 设置页显示实例能做什么、费用，以及调整能力的命令。
  - 容器部署另有一张 Linux 容器卡片：实时状态、**立即休眠**、命令执行方式（自动、总是轻量、总是 Linux）和闲置多久后休眠（5、10 或 30 分钟）。
  - 修改对下一条命令立即生效，无需重启，重启后仍然保留。
  - 对应接口为 `GET`/`PUT /api/runtime` 和 `POST /api/runtime/container/stop`。
- **安装器**（#229、#231）：改为按能力而不是按套餐提问，每一步都按回车即可装完。
  - 顺序为：账号、Worker 名称、能力，最后确认一次。
  - 能力问题提供“Research and write”（免费，默认）、“+ Analyze data and split big jobs”（Workers Paid；`run_code` 和 `workflow`）以及“+ Work on code projects”（Workers Paid 加容器运行时长）。
  - 临时账号跳过能力问题，Cloudflare 条款并入那一次确认。
  - 新安装把图片存在 Durable Object 中，不再询问 R2；已使用 R2 的实例继续使用 R2。
  - owner 访问密钥自动生成，也可以通过 `DSH_EDGE_ACCESS_KEY` 提供。DeepSeek key 在网页提示时填写，也可以稍后在 Settings → Models 中添加。
  - 部署完成后，安装器会询问是否打开浏览器。
- **同名即更新**（#229）：用已有 Worker 的名称再次运行 `install`，默认选项是“Update it”。
  - 更新会保留实例的能力、对话、文件、访问密钥和 DeepSeek key，不会再次询问。
  - “Update and change what it can do”会标出当前能力；降级时列出将被移除的内容，默认 No。
  - 同名但不是 dsh-edge 的 Worker 永远不会被更新，该名称视为已被占用。
  - `upgrade` 走同一流程，Worker 不存在时直接报错。
- **更新只做公开验证**（#229）：更新保留的 owner 密钥无法读回，因此安装器只确认公开版本已是新版本（“live”）。登录后才会暴露的启动故障，要到 owner 下次登录时才会看到。
- **离开 Container 模式时保留 Container application**（#229、#231）：它是回退目标。安装器会查出它的 id，打印可直接运行的 `npx wrangler containers delete <id>`；登录新版本确认正常后运行该命令，即可停止 Container 计费。
- **`@cloudflare/computer` 0.3.1**（#217），与容器镜像中的 computerd 成对升级。

### 已知限制

- 在 Node 22 上，`pnpm run check` 有两个异步上下文测试失败；Node 24 下全部通过。这只影响测试环境：被测代码运行在 workerd 中，CI 使用 Node 24。该问题自 0.17.0 起就存在。
- 停止 `pnpm --filter dsh-edge dev:container` 后，本地 Docker 容器可能仍在运行；可用 `docker ps` 和 `docker rm -f` 清理。
- 指向 `/workspace` 之外的符号链接不在分流处理范围内。

### 验证与升级

`pnpm run check` 通过 756 个测试。发版时会针对两种发布产物运行集成测试。Container 集成测试（分流、重跑、与强制 Linux 运行逐条比对的差异语料、运行设置和立即休眠）会对接本地 Docker 容器运行，并在 CI 中每日运行。

随后，0.18.0-alpha.1 在真实的 Workers Paid 账号上，用已发布的 npm 包完成了验收，覆盖：
- 0.17.0 实例原地升级，对话、文件、访问密钥和模型设置全部保留；
- 新安装只按 5 次回车，全程约 70 秒；
- 升级到容器档后，git、npm、python3、jq 和 tar/xz 任务按预期分流；
- 设置卡片、立即休眠后自动唤醒、强制分流，以及闲置时长设置的保留；
- 降级后数据和回退应用都保留；
- 同名的非 dsh-edge Worker 没有被改动。

第一条容器命令（含拉取镜像）用时 18.7 秒，之后的命令不到 1 秒，立即休眠后唤醒约 4 秒。相对 alpha.1，0.18.0 只改动了安装器文案和清理命令（#231）。

用 `npx dsh-edge@latest upgrade` 升级，选择“Update it”即可保留一切。alpha 部署应使用 `@latest` 切换到稳定频道。要加上容器，选择“Update and change what it can do”，再选“+ Work on code projects”。本版没有新增存储结构或迁移。
