## dsh-edge 0.18.0

将 Linux 容器运行时、按能力引导的安装器和运行设置从 0.18.0 预发布版提升至 npm `latest` 稳定频道。在 Workers Paid 上，实例现在可以加一个 Linux 容器，用于 git、npm、node 和 python3。工具默认使用普通调用，`run_code` 改为可选的 PTC 模式。上游 Harness 基线保持 0.1.5-rc.2。完整细节见各预发布版说明（[alpha.1](0.18.0-alpha.1.zh.md)、[alpha.2](0.18.0-alpha.2.zh.md)、[alpha.3](0.18.0-alpha.3.zh.md)、[alpha.4](0.18.0-alpha.4.zh.md)）。

### 自 0.17.0 以来的新增

- **Linux 容器**（#217、#218、#219、#226）：即“+ Work on code projects”能力，需要 Workers Paid。
  - 容器挂在实例的 Durable Object 上，自带 git、node 22、npm、python3 以及常用的压缩和构建工具。
  - 每次发版都会发布对应版本的镜像 `docker.io/pawaca/dsh-edge-computer:<version>`。
  - 工作区文件保存在 Durable Object 中并与容器同步，因此停止或替换容器不会丢失文件。
  - 容器可以访问互联网，但不会拿到任何 Edge 凭据。
  - 闲置一段时间后容器进入休眠，约 5 秒即可唤醒。
- **按命令分流**（#221、#223、#224）：有容器时，文件和文本操作留在轻量 shell，只有 Linux 才有的程序进入容器。轻量 shell 跑不了的命令，如果没有改动任何文件，就在容器中重跑。
- **运行设置**（#227、#228）：设置页显示实例能做什么、费用，以及调整能力的命令。容器部署另有实时状态、**立即休眠**、命令执行方式和闲置时长。修改对下一条命令立即生效，无需重启。
- **当前日期**（#236）：模型知道所有者时区下的今天日期。日期以一条简短的上下文消息送达，只在日期变化时出现，不影响缓存的提示词前缀。

### 自 0.17.0 以来的变更

- **默认普通工具调用，PTC 模式改为可选**（#235、#238）：0.17.0 在 Isolated 部署上同时提供 `run_code` 和普通工具，模型因此把大多数步骤都包成一段程序。现在所有部署默认使用普通工具调用，和上游一致。
  - 默认预设是上游的**标准模式**。付费部署的新建会话选择器里还提供上游的 **PTC 模式**，选了它的会话只使用 `run_code`。与上游一致，PTC 模式不提供 `workflow`。
  - 预设在会话第一轮之前选择，之后锁定。0.17.0 的会话以标准模式继续，历史中的 `run_code` 记录照常回放。在 0.18.0 alpha 版中以 PTC 模式开始的会话保持 PTC 模式。
- **新会话的默认预设和模型**（#240）：与上游一致，Settings → Agent presets 选择新会话的起始预设；在任一会话中最近一次选择的模型，就是新会话的起始模型。`DEEPSEEK_MODEL`（默认 `deepseek-v4-flash`）只在所有者第一次选择模型之前生效。
- **安装器**（#229、#231）：改为按能力而不是按套餐提问，每一步都按回车即可装完。
  - 用已有 Worker 的名称再次运行 `install`，默认选项是“Update it”。更新会保留能力、对话、文件、访问密钥和 DeepSeek key。
  - 新安装把图片存在 Durable Object 中，不再询问 R2；已使用 R2 的实例继续使用 R2。
  - DeepSeek key 在 Settings → Models 中再填写。
  - 离开 Container 模式时保留 Container application 作为回退目标，安装器会打印删除它的命令。
- **系统提示词**（#236）：写明工作目录和实例所在档位能做什么，要求模型检查退出码，并写明命令超时上限。plan mode 采用上游规则。

### 自 0.17.0 以来的修复

- **非 UTF-8 命令输出**（#233）：GBK 网页、二进制文件，或 `head -c` 切断多字节字符，都不再让整条命令失败。输出像终端一样解码。

### 已知限制

- 升级后，在所有者发出第一条新消息之前触发的提醒使用 UTC 日期。
- 上游标准模式的说明提到了 workflow，而免费（Direct）部署没有 workflow。
- 与上游一致，空白的“New session”保留打开时的预设。修改默认预设后，请在发出第一条消息前，用该会话的选择器切换预设，或从另一个空白会话开始。
- 在 Node 22 上，`pnpm run check` 有两个异步上下文测试失败；Node 24 下全部通过。这只影响测试环境。
- 停止 `pnpm --filter dsh-edge dev:container` 后，本地 Docker 容器可能仍在运行。
- 指向 `/workspace` 之外的符号链接不在分流处理范围内。

### 验证与升级

`pnpm run check` 通过 778 个测试。集成测试针对两种发布产物运行。Container 集成测试每日在 CI 中运行。Alpha.1 在真实 Cloudflare 账号上通过了验收，覆盖安装、更新、容器和运行设置。对 alpha.1 至 alpha.3 的手动测试发现的问题，已在 alpha.2 至 alpha.4 中修复，alpha.4 也通过了手动检查。

测试实例一天的 Cloudflare 分析数据显示：Worker 和 Durable Object 均无错误，每个请求的 CPU 时间 p99 低于 7 毫秒，每次 Durable Object 调用读取约 25 到 40 行 SQLite，全天没有增长。

用 `npx dsh-edge@latest upgrade` 升级，选择“Update it”。已有的 alpha 部署应使用 `@latest` 切换到稳定频道。要加上容器，选择“Update and change what it can do”，再选“+ Work on code projects”。本版没有存储迁移。
