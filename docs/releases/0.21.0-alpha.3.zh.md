## dsh-edge 0.21.0-alpha.3

减少了 Durable Object 冷启动时工作区文件操作的数据库读取量（#274）。本版发布至 npm 的 `next` 频道，`latest` 仍为 0.20.0。[0.21.0-alpha.2](0.21.0-alpha.2.zh.md) 的全部内容仍然适用。上游 Harness 基线仍为 0.2.0-rc.2，会话格式仍为 V4，所以从 0.20 或 0.21 升级不会迁移任何已存数据。

### 修复

- **实例冷启动时，查找工作区文件读取的数据库行数大幅减少**（#274）。工作区文件系统会在内存里记住最近用过的路径。这份记录为空时（新启动或空闲后被回收的实例），找一个文件要把路径上每一层目录的所有条目都读一遍：在有 50 个文件的目录里找一个文件约读 490 行，目录越大越多。所以搜索 1,000 个文件约读 49 万行，无论用的是 `grep`、`glob` 还是 shell 命令。现在会直接定位到目标条目：同样的搜索约读 4.2 万行，用 `glob` 或 `find` 列出 1,000 个文件约读 2,700 行，而不是 1 万行。结果不变。修复方式是给 Cloudflare 的 `@cloudflare/computer` 0.3.1 打一处查询补丁，记录在 `standalone/patches/audit.json`，等该库自带修复后删除。

### 已知限制

- `glob` 和 `grep` 不应用 `.gitignore` 文件，所以 `grep` 会搜索 ripgrep 本会跳过的被忽略文件。
- 文件写入保护只覆盖 `write` 和 `edit` 工具。在受保护的写入进行期间，由 shell 或容器命令写入的文件改动不会被发现，这与上游一致；在受保护的写入之前已完成的改动会被发现。
- 从 0.18 升级后不支持退回 0.18。
- 0.18 的插件配置卡片（Agent loop、Web search）移到了上游插件管理器中，Edge 没有提供插件管理器。
- Agent 预设页的介绍和模式说明提到了上游的 Creator 模式，Edge 不提供该模式。
- 0.18.0 中关于 Node 22 测试环境、本地 `dev:container` 清理以及指向 `/workspace` 之外的符号链接的限制仍然存在。

### 验证与升级

`pnpm run check` 通过 876 个测试，其中包括一项检查：打补丁后的查询按目录和名字查找目录条目，且已发布的库仍需要这个补丁。集成测试覆盖两个发布产物（Direct 和 Isolated），打包后的安装器通过 `pack:verify`。`upgrade-from-release.probe.mjs` 分别升级由已发布的 0.21.0-alpha.2、0.20.0 和 0.18.0 创建的数据，各通过 11 项检查。上述读取行数是在本地实例上测得的，每次搜索都在冷缓存下进行。

用 `npx dsh-edge@next upgrade` 升级测试实例，选择"Update it"。
