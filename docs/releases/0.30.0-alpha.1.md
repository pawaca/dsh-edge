## dsh-edge 0.30.0-alpha.1

Images can be larger and in more formats when the Cloudflare Images binding is present, `@file` completion searches the whole working directory, and several Edge behaviors now follow upstream exactly: rename and fork, the session storage contract, credential announcements, and the `/` skill menu. Published to npm's `next` channel; `latest` remains on 0.29.0. The upstream baseline stays 0.2.1-rc.2 and the session format stays V4; the session summary gains one column, added on start.

### Added

- **Image optimization** (#348, #381): when the Worker has the Cloudflare Images binding (`IMAGES`, which the installer enables for an owned account), images may be PNG, JPEG, WebP, or GIF (its first frame), up to 8,192 pixels a side and 64 megapixels, 7 MiB each, and 8 per message, with 7 MiB per message in total.
  - A PNG or JPEG of at most 2048 × 2048 pixels and 4 MiB with no EXIF rotation is stored as sent, as upstream does, with no transformation.
  - Anything else is transformed: scaled to upstream's pixel budget, turned upright by its EXIF orientation, and stored as JPEG, or as WebP when it may hold transparency. An output over 4 MiB is encoded again at lower quality (85, then 75, then 60); Cloudflare excludes format and quality when it counts unique transformations, so an image costs one transformation however many qualities it takes.
  - Without the binding the limits are unchanged (PNG or JPEG, 2,000 pixels a side, 3.5 MiB each, 4 per message). Images stored under the larger limits stay readable if the binding is later removed.
- **Recursive `@file` completion** (#353, #380): as upstream's local provider, a bare fragment fuzzy-ranks every file below the working directory, so `@rdm` finds `docs/README.md`. A query with a `/` still lists that directory, and may now be an absolute path inside the working directory. The index skips `.git`, `node_modules`, `dist`, `build`, and other dependency and build-output directories.
- **`run_code` describes its environment** (#352, #376, Isolated only): the tool's description tells the model that each call runs in a fresh isolate without files, network, or imports, and states its limits (200 tool calls, 2 MiB per tool result, 1 MiB of output, 300 seconds, 30 seconds of CPU).

### Changed

- **Credential changes refresh the page** (#351, #375): saving or removing a key announces upstream's `credentials/reference-updated`, so an open Models page, model menu, or web-search card updates without a reload.
- **Rename and fork follow upstream** (#349, #377): a rename made while the first-prompt title is still being generated now wins, where the automatic title used to replace it. A fork with `atSeq` cuts exactly at that event, and one without it takes upstream's latest completed-turn prefix; a missing event is refused.
- **Session storage contract** (#350, #378): the Durable Object store now applies upstream's own checks. An event type the running version does not know (for example after a rollback) is refused rather than replayed, appends must be contiguous and losslessly serializable, and a bounded read reads only its rows. To keep the write-open check from scanning a log, the session summary records the stored event types; a session stored before this release is scanned once at its next write.
- **The `/` skill menu** (#353, #380): upstream's skill catalog is the single answer for `skills/list`. The Edge rechecks the session's skill roots before it lists, so a newly written skill appears, and a session that has already run turns no longer fails with "File operations are only available during an active turn".

### Known limitations

- `@file` completion's first bare query in a working directory reads its index, about 3.5 Durable Object rows per entry and at most 10,000 entries (upstream: 50,000) and 1,000,000 path characters; later queries read about 2 rows. As upstream's, the index is refreshed only after a tool result, so a file uploaded or written through the owner API is found by a bare query only after the next tool call; a query with a `/` always reads the directory. At most 4 working directories' indexes are kept.
- Image transformations count toward the account's Cloudflare Images allowance (5,000 unique transformations a month on the Free plan; then error 9422). When a transformation fails, an image inside the limits without the binding is stored as sent, and a larger one is refused with the reason. EXIF rotation by Images has been confirmed only against Cloudflare's documentation, not yet on a deployed instance; local development does not rotate.
- The Web client sends images inside the 10 MiB prompt body, so an image is limited to 7 MiB where upstream allows 20 MiB.
- A created session keeps two pre-existing differences from upstream's storage contract: its header row is written at creation, and an empty created session is kept as a blank (#379).
- The other limitations listed for 0.29.0 still hold.

### Validation and upgrade

`pnpm run check` passes 1,113 tests. New tests cover the credential announcement (including a browser snapshot of the web-search card), the `run_code` description, rename during a held title and the fork cuts, the storage contract (read validation, contiguity, lossless JSON, the recorded event types and the one-time scan), the `@file` index (ranking, bounds, sharing, staleness, eviction, and one read at a time), and image normalization (header parsing for all four formats, pass-through without a transformation, the transformation and its failures).

Integration runs against both release artifacts (Direct and Isolated). New checks:
- `$events` receives `credentials/reference-updated` after a set and a removal;
- a rename while the title is held keeps the user's title; exact and default fork cuts; a missing `atSeq` refused;
- `skills/list` as the Web client calls it, including a skill written after a listing on a session that has run turns;
- `@ndlref` finding a nested file, and an absolute directory query;
- the `run_code` description (Isolated).

A new snapshot runs the prompt route against a local Worker with Images bound: a 4K PNG is stored as a 2730 × 1536 JPEG.

Measured locally in the Workers runtime:
- `row-cost.probe.mjs` against 0.29.0: plain turns write the same rows (443 SQL rows and 36 KV and alarm writes over nine turns). A cold resume reads 615 rows against 604, the startup check for the new summary column. Over a 200-entry tree, the first bare `@file` query reads 741 rows and later ones 2 (15 on 0.29.0).
- `upgrade-from-release.probe.mjs` upgrades state created by the published 0.29.0, passing 11 checks.

The release artifacts stay within Cloudflare's 64 MiB size limit (Direct 8.3 MB, Isolated 9.7 MB). Not yet validated on a staging instance.

Upgrade a test instance with `npx dsh-edge@next upgrade` and choose "Update it".
