## dsh-edge 0.26.0

Models from other providers, added on the Models page as in upstream DeepSeek Harness. Published to the stable npm `latest` channel, with the same changes as [0.26.0-alpha.1](0.26.0-alpha.1.md) and [0.26.0-alpha.2](0.26.0-alpha.2.md). Version 0.25 is kept for the move to the upstream 0.2.1 baseline, which waits for an upstream release candidate; this release stays on 0.2.0-rc.2. The session format stays V4, so upgrading from 0.24 migrates no stored data. Upgrading from 0.18 still moves sessions to V4 as described in [0.19.0](0.19.0.md).

### Added

- **Other model providers** (#300): Settings → Models can now add providers besides DeepSeek, through upstream's `dsh-llm-pi-ai`.
  - A provider can speak OpenAI chat completions, OpenAI responses, or Anthropic messages, at any HTTP(S) Base URL. That covers OpenRouter, Cloudflare Workers AI or AI Gateway, and a self-hosted OpenAI-compatible gateway, among others.
  - The page can list an endpoint's models before you save, and you can also enter models by hand.
  - A saved provider works at once, with no restart. Its models appear in the model menu, can be the default for new sessions (as in upstream, the model you picked last), and are used by subagents of a session running on them.
  - Each provider's API key is entered on the same page and kept by the credentials service in Durable Object storage, never in the settings.
  - DeepSeek works as before, including `DEEPSEEK_API_KEY` as a Worker secret.

### Fixed

- **DeepSeek settings applied at once** (#300): a retry policy saved for DeepSeek on the Models page now applies to the running instance. Before, it took effect only after the instance restarted.
- **Garbled characters in the Web client** (#302): some text showed broken characters, for example `Deep diving for 14s Â·Â·Â·` while the model was thinking, or `agentâ€™s` on the Agent presets page. The page declared its character encoding too far down for the browser to find it, so the browser read the page and its scripts with the wrong encoding, which could affect any non-English text, Chinese included. The declaration now comes first.
- **Choosing the default agent preset** (#303): making a preset the default for new sessions on Settings → Agent presets failed with `settings namespace "agent-preset-registry" is not registered`. The Edge now stores the choice where upstream's page writes it. A default chosen with an earlier release is kept.

### Known limitations

- To keep credentials out of the settings, which are stored in plain text:
  - each provider must name its own API key, and the name may not be one that belongs to DeepSeek or another Edge feature (`DEEPSEEK_*`, `MCP_TOKEN_*`, `DSH_EDGE_*`);
  - a Base URL may not contain credentials, a query, or a fragment;
  - extra headers are limited to `HTTP-Referer`, `Referer`, `X-Title`, `OpenAI-Organization`, `OpenAI-Project`, and `anthropic-beta`, so a gateway that needs a second credential header (such as an authenticated Cloudflare AI Gateway's `cf-aig-authorization`) cannot be configured yet.
- Providers that sign in through a local login or read local credential files are not offered: GitHub Copilot, OpenAI Codex, and Amazon Bedrock or Google Vertex through local credentials.
- Session titles are still generated with DeepSeek.
- Images sent to a subagent from the subagent panel are not verified on the Edge.
- Up to 8 subagents can stay loaded at once (upstream's default, changeable on the Subagent card). Model requests beyond the Workers limit of six simultaneous connections wait for a free connection.
- Upstream's turn outline (each turn's prompt and response preview) is not offered: it grows with every turn, and the Edge stores a session's cached values as one record, so a long session would outgrow it.
- Upstream's `/feedback` command is not offered: it keeps an anonymous user id in a local file, which Workers cannot store.
- `glob` and `grep` do not apply `.gitignore` files, so `grep` searches ignored files that ripgrep would skip.
- File write protection covers the `write` and `edit` tools. A shell or container command that writes a file during a guarded write is not detected, as in upstream; one that finished before the guarded write is.
- Rolling back to 0.18 after an upgrade from it is not supported.
- The Agent presets page intro and mode guide mention upstream's Creator mode, which the Edge does not offer.
- The 0.18.0 limitations about the Node 22 test environment, local `dev:container` cleanup, and symlinks outside `/workspace` still hold.

### Validation and upgrade

`pnpm run check` passes 912 tests, with new unit tests for:
- saving a provider and using it without a restart, and keeping it after one;
- refusing a Base URL with credentials, a query, or a fragment; a header outside the allowlist; a missing or reserved key name; and a provider id DeepSeek already uses;
- a DeepSeek retry policy applying at once;
- the page's encoding declaration coming first, and a default preset saved by an earlier release being kept.

Integration runs against both release artifacts (Direct and Isolated), with new checks for:
- listing a draft endpoint's models;
- an OpenAI-compatible and an Anthropic-messages provider each running a turn with its own key;
- a subagent running on its parent's provider;
- the last picked model becoming the new-session default;
- the providers and keys still serving a turn after a restart;
- making PTC mode the default the way the Agent presets page does.

The standalone build check rejects a Web page whose encoding declaration is not within its first 1024 bytes. The release artifacts stay within Cloudflare's 64 MiB size limit (Direct 7.3 MB, Isolated 8.6 MB), and their startup takes about 100 to 160 ms locally, against Cloudflare's 1 s limit. The packed installer passes `pack:verify`. `upgrade-from-release.probe.mjs` upgrades state created by the published 0.26.0-alpha.2, 0.24.0, and 0.18.0, passing 11 checks each.

On a staging instance:
- with 0.26.0-alpha.1, a Z.ai provider was added on the Models page: its models were listed from the endpoint and it ran turns;
- with 0.26.0-alpha.2, the Web client showed no garbled characters, and making a preset the default on the Agent presets page succeeded.

Upgrade with `npx dsh-edge@latest upgrade` and choose "Update it", then reload the page. The Web page updates at once, but the instance behind it can keep running the previous version for a few minutes after an upgrade, so a fix in it may show only then.
