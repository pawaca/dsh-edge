# dsh-edge 0.4.0-alpha.1

[English](https://github.com/pawaca/dsh-edge/blob/dsh-edge-v0.4.0-alpha.1/docs/releases/0.4.0-alpha.1.md) | 中文

本预发布版本新增运行时可配置的 Provider 设置和可写凭证，支持从浏览器管理 API Key 和模型配置，无需重新部署。

## 亮点

- **可写凭证**：API Key 现可通过设置 UI 在运行时存储。上游 `CredentialProvider` 接口将值持久化到 Durable Object 存储，Worker 环境密钥作为回退。
- **设置集成**：上游 `dsh-settings` 子系统已安装，使用 Durable Object 存储提供者。Settings → Models 页面展示已注册的 `llm-deepseek` 命名空间。
- **上游 LLM 插件**：`dsh-llm-deepseek` 作为 cordis 插件安装，替代之前 Edge 自有的 `EdgeDeepSeekAdapter`。插件自动注册设置命名空间和可配置 Provider 条目。
- **OpenAI 兼容端点切换**：用户可通过设置修改 DeepSeek 的 `baseURL`，指向 OpenAI、Groq、OpenRouter 或任何 OpenAI 兼容网关。
- **与上游默认值对齐**：`maxTokens` 默认 256,000，`reasoningEffort` 默认 `high`，与上游 `dsh-llm-deepseek` 插件一致。设置部署环境变量时可覆盖。
- **插件故障延迟处理**：格式错误的 `DEEPSEEK_BASE_URL` 不再导致整个 Durable Object 崩溃；工作区、设置和诊断 API 仍可用。

## 限制

- 通过上游 Models UI 的 Provider 配置变更尚未在真实部署中端到端验证。本 alpha 验证基础设施可行性。
- 仅支持 OpenAI 兼容协议。原生 Anthropic API 需要 `dsh-llm-pi-ai`，该包与 Cloudflare Workers 不兼容。
- 本版本不支持多个 Provider 同时使用（例如 DeepSeek + OpenAI 并行）。

## 升级

```sh
npx dsh-edge@next upgrade
```

现有部署完全向下兼容，无需迁移。
