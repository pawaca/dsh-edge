## dsh-edge 0.19.0

Moves the Edge onto the upstream Harness **0.2.0-rc.1** baseline (from 0.1.5-rc.2) and promotes it from the 0.19.0 prereleases to the stable npm `latest` channel. Upstream 0.2.0 changes the session format, the DeepSeek connection, the settings system, reminders, and much of the web client. This release ports the Edge to all of it, keeps existing instances' data, and adds a way to recover a lost access key. **Upgrading moves stored sessions to a new format, and rolling back to 0.18 is not supported.** The prerelease notes ([alpha.1](0.19.0-alpha.1.md), [alpha.2](0.19.0-alpha.2.md)) have the full details.

### Upgrading from 0.18

- **Sessions move to format v4 on first start** (#244). Startup migrates every stored session through the upstream catalog in one transaction and rewrites only the rows the new format changes. A subagent's parent migrates with its children's catalog evidence, as upstream requires.
  - Cost on the published-0.18.0 upgrade state (10 sessions, 609 event rows): 55 rows written, about 2,900 read, 38–40 ms. A second start writes nothing.
  - 0.18 cannot read v4 sessions. The installer tags each deployed Worker version, and updating a Worker whose active version predates 0.19 says that sessions move to a new format and that rolling back is not supported.
- **Reminders carry over** (#244). 0.18's active reminders import once into the new task table, titled from the first line of their prompt, and fire on their original schedule. Upstream itself drops them.
- **Settings, skills, MCP servers, files, and image attachments** keep their storage. Models page edits made on 0.18 keep applying.
- **Endpoint** (#246): the DeepSeek connection now speaks only the Anthropic-compatible Messages API. DeepSeek's OpenAI-compatible root answers that API with 404.
  - `https://api.deepseek.com`, `/v1`, and `/beta` map to `https://api.deepseek.com/anthropic`, in `DEEPSEEK_BASE_URL` and in a saved Models page Base URL (rewritten once on start).
  - Any other endpoint, such as a gateway, is kept. If it answers 404, the turn's error adds a hint: the endpoint may not serve the Messages API, `https://api.deepseek.com/anthropic` does, and the Base URL is set on the Models page or in `DEEPSEEK_BASE_URL`. The hint names no part of the configured endpoint, which may carry a credential. (The 0.19.0-alpha.1 notes said it named the endpoint; it never has.)
- **Models**: new sessions default to DeepSeek-V4.1-Flash (`deepseek-flash`, image input). The catalog is V4.1 Flash and V4 Pro; upstream removed V4 Flash and the vision preview. Existing sessions keep the model they were using, and the API still accepts those ids.

### Added since 0.18.0

- **Reset a lost access key** (#249): when the Worker already exists, the installer offers **Update and reset the access key**.
  - It deploys the release with a new owner key, either generated or taken from `DSH_EDGE_ACCESS_KEY`, and shows the key once.
  - Conversations, files, and the DeepSeek key are kept. The old key stops working, and every signed-in browser must sign in again.
  - The login page says how to recover a lost key, with the command for the deployment's release channel.
- **Upstream parity check** (#243): `pnpm run check` now fails when an upstream plugin or tool is neither used by the Edge nor classified with a reason. Baseline upgrades review upstream's documentation changes, and a stable release requires wiki coverage of every upstream subsystem.
- **Upstream 0.2.0 web client** (#244), including session pinning, the jobs panel, the right sidebar with files, document preview and subagent conversations, and conversation groups.

### Changed since 0.18.0

- **Settings** (#244): the Edge serves upstream's new configuration forms from its own Durable Object settings service, including the web client's theme, language, transcript view, busy-send behavior, preview notice, and developer tools.
- **Reminders** (#244): the upstream schedule tools gain titles, daily, weekly, and cron schedules, `schedule_update`, and deleting inactive reminders. The Edge serves them from Durable Object SQLite, and delivery still goes through the session queue.
- **Upstream behavior now in effect** (#244):
  - Archived sessions do not run until restored.
  - Queued message edits are text-only.
  - Chat links still open in a new browser tab by default; upstream's in-app browser is one setting away.
- **Plan reviews and questions** (#244): `ask_user_question` and `exit_plan_mode` wait for the owner outside the 60-second short-tool deadline.
- **`run_code`** (#244): the runtime behind it is now upstream's PTC runtime. The Edge does not offer the new per-run `timeoutMs`.

### Fixed since 0.18.0

- **Stop during a shell command in Isolated mode** (#245): Stop now ends the turn within 2 seconds and reports the tool call as aborted, instead of waiting for the whole command and reporting `Error: [object Object]`. A command that does not exit may still finish in the background, as it could on 0.18.
- **Installer on macOS** (#247): stopping Wrangler no longer fails with `kill EPERM` under load.

### Known limitations

- Rolling back to 0.18 after the upgrade is not supported.
- The 0.18 plugin configuration cards (Agent loop, Web search) moved into upstream's plugin manager, which the Edge does not ship.
- The Agent presets page intro and mode guide mention upstream's Creator mode, which the Edge does not offer.
- Upstream packages not yet adopted include model request retries, read-before-write file guards, repeated-tool-call reminders, session checkpoints, and the todo list (#234). The [wiki Roadmap](https://github.com/pawaca/dsh-edge/wiki/Roadmap) lists every remaining gap.
- The 0.18.0 limitations about the Node 22 test environment, local `dev:container` cleanup, and symlinks outside `/workspace` still hold.

### Validation and upgrade

`pnpm run check` passes 844 tests. Integration runs against both release artifacts (Direct and Isolated), including the 0.1.3-fixture upgrade path, and the packed installer passes `pack:verify`. `upgrade-from-release.probe.mjs` upgrades state created by the published 0.18.0 and passes all eleven checks.

The upgrade was also run by hand twice:
- **Locally, with a real DeepSeek key.** 10 sessions, including a subagent child, kept their ids, titles, presets, and transcripts. Old sessions continued with their context, tools, PTC, and image input. A reminder set on 0.18 fired on time after the upgrade.
- **On a staging instance** (Isolated with the Linux container) upgraded in place from 0.18.0 to 0.19.0-alpha.2 with the access key reset. The DeepSeek key was kept. All 7 sessions migrated and opened, and an old session recalled its context. A new session defaulted to V4.1 Flash and ran bash in the container. A new reminder fired on time, and the settings pages showed the release and container state.

The [wiki](https://github.com/pawaca/dsh-edge/wiki) covers every upstream 0.2.0 subsystem, and the pages 0.19 changed are updated.

Upgrade with `npx dsh-edge@latest upgrade` and choose "Update it", or "Update and reset the access key" if you no longer have the key. Existing alpha deployments should use `@latest` to switch to the stable channel. Upgrading from 0.18 moves stored sessions to the new format, and rolling back is not supported.
