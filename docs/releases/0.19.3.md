## dsh-edge 0.19.3

Moves the upstream Harness baseline from 0.2.0-rc.1 to **0.2.0-rc.2** (#254) and keeps a generated session title from being lost on restart (#253). Published to the stable npm `latest` channel. This is the first npm release since 0.19.0: 0.19.1 and 0.19.2 were tagged, but their release workflows stopped at the Windows browser-snapshot checks before publishing (#256, #259). Session format stays V4, so upgrading from 0.19.0 migrates no stored data. Upgrading from 0.18 still moves sessions to V4 as described in [0.19.0](0.19.0.md), and rolling back to 0.18 is not supported.

### Changed

- **Reminders are carried out when they fire.** Upstream rc.2 frames a due reminder as a scheduled message from the user. In 0.19.0 the model was told to present the reminder as untrusted content, so a reminder such as "search today's news and summarize it" was only relayed. Now the model does the task. Reminders are created by the owner, or by the agent at the owner's request, through `schedule_create`.
- **Bash path safety.** The `bash` tool now asks the model, as upstream does, to verify the resolved absolute target path before any delete or move, and to guard variables in such paths with `${VAR:?}`, so an unset variable stops the command instead of expanding to an empty path.
- **Web client** from upstream rc.2:
  - the model picker searches long lists;
  - plan reviews keep opening after switching sessions;
  - elapsed time reads "Completed in …";
  - process details and dark-theme styling are refined.

### Fixed

- **A generated title could revert after a restart** (#253). A title that arrives after its turn was shown in the session list right away but stored only after a short write window (about 250 ms), so a Worker restart in that window, such as a deployment, brought back the fallback title. Titles are now stored as soon as they change, at most once per session per window so rapid renames still batch. Only the title was ever affected.

### Known limitations

Everything listed for 0.19.0 still holds.

### Validation and upgrade

`pnpm run check` passes 847 tests. Integration runs against both release artifacts (Direct and Isolated), and the packed installer passes `pack:verify`. `upgrade-from-release.probe.mjs` upgrades state created by the published 0.19.0 and by the published 0.18.0, passing 11 checks each. Started on 0.19.0 state, this release boots in about 0.6 s with no migration. Edge CI now runs the release workflow's Windows integration and browser-snapshot checks on every change (#259), and they passed on this release's commit before tagging.

Upgrade with `npx dsh-edge@latest upgrade` and choose "Update it".
