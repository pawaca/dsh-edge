# dsh-edge 0.2.0-alpha.3

[English](https://github.com/pawaca/dsh-edge/blob/dsh-edge-v0.2.0-alpha.3/docs/releases/0.2.0-alpha.3.md) | 中文

这个预发布版本把完整的 DeepSeek Harness 已发布基线从 `0.1.0-rc.7` 升级到 `0.1.0-rc.8`。它有意保持为兼容性版本：Cloudflare runtime、single-owner 认证模型、公开路由和 Durable Object schema 均不改变。

## 主要变化

- Live turn 被取消时，使用 rc.8 标准的 `assistant/message` interruption marker 保留已经可见的 assistant 文本或 reasoning 前缀；Edge persistence adapter 可以让该 marker 完整经过 Durable Object 冷启动存储往返。
- 采用 rc.8 有界的多 query Web Search 流程和 provider 侧并发，同时保留 dsh-edge request-scoped DeepSeek credential 的处理方式。
- 采用上游 runtime 的 DeepSeek reasoning continuation 修复和统一的默认五次 provider retry。
- 跟进 rc.8 的 client renderer 与基于 slot 的 Harness branding 组合，同时继续由独立、社区所有的 plugin 提供 dsh-edge deployment 和 owner-session 页面。
- 通过新的上游 host-home contract 报告 `/workspace`，并在内部使用上游 DeepSeek request-image bound，但不在 Edge 中宣称支持图片输入。

## 安装或升级预发布版本

需要 Node.js 22.14 或更高版本，以及你自己的 DeepSeek API key。

```sh
npx dsh-edge@next install
```

已有预发布部署可以原地升级：

```sh
npx dsh-edge@next upgrade
```

`next` dist-tag 将指向 alpha.3，`latest` 仍停留在 0.1.3。由于 Cloudflare secret 只写不可读，升级时仍需重新输入现有 owner access key 和 DeepSeek API key。

## 范围与兼容性

每个已发布 Harness package 都精确固定在 `0.1.0-rc.8` 基线。原有 6 个经过审计、绑定版本的 Edge adaptation 已完成 rebase，没有新增上游 patch。组装后的 Web graph 采用必需的 renderer 和官方 Harness brand plugin；新加入的 attachment/image 与 `@file`/`@session` reference plugin 则明确排除，因为 Edge 尚未提供对应的 host capability。

rc.8 Node SQLite schema 17 layout 不是 dsh-edge 使用的存储格式。Durable Object session storage 继续使用 Edge schema v2，因此本版本不执行数据迁移，并保留现有 0.1.3 rollback boundary。Direct Shell 与 Dynamic Worker 两种模式继续保持行为一致。

会话导出、附件与图片、remote MCP、Skills、Workflows、Jobs 和 Subagents 继续暂缓，统一放到 alpha.3 之后的 ROI review。`web_fetch` 在具备明确的网络访问策略前继续保持禁用。

## 发布完整性

npm package 从经过 Review 的 `dsh-edge-v0.2.0-alpha.3` tag 发布到 `next` dist-tag。发布 workflow 会核对精确的 tag 与 package version，重新构建确定性的 rc.8 standalone 装配，验证 Direct 与 Dynamic Worker 两种模式、0.1.3 持久化数据兼容性和 browser/runtime snapshot，并在可信发布前从 workspace 外安装打包产物。配套 GitHub prerelease 会携带完全相同的 tarball asset。
