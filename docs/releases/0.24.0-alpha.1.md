## dsh-edge 0.24.0-alpha.1

Subagents now work as in upstream DeepSeek Harness's standard composition: they run in the background and can be continued, messaged, interrupted, listed, forked, and run on a model the parent chooses. Published to npm's `next` channel; `latest` remains on 0.23.0. The upstream Harness baseline stays 0.2.0-rc.2 and the session format stays V4, so upgrading from 0.23 migrates no stored data. Subagent model selection adds one new session event type, `subagent/model-selection-policy`, written only while that setting is on.

### Changed

- **Background subagents continue** (#295): `subagent` now starts a continuable subagent and, by default, runs it in the background.
  - The call returns the subagent's id at once instead of waiting for its result. When the subagent finishes, its closing message wakes the parent for another turn.
  - The parent can continue the same subagent later instead of starting a new one. A subagent that is not running resumes from storage when messaged, also after a restart.
  - The model can still wait for the result by passing `run_in_background: false`.
  - Before, a background subagent was a one-shot job read with `job_output`.
- As in upstream, Stop on the parent does not stop a subagent that is still running. Use `interrupt_agent`, or the subagent panel in the Web client.

### Added

- **Subagent control tools** (#295): `send_message` continues a subagent (or answers its parent), `interrupt_agent` stops a subagent's current turn and keeps the subagent, and `list_agents` lists the subagents a session started with their status.
- **Forked subagents** (#295): `subagent_fork` starts a subagent that begins from the parent's completed turns, so it knows the conversation so far. It runs on the parent's model.
- **Subagent panel messages** (#295): a message sent to a subagent from the Web client's subagent panel now runs, also when the parent session is not loaded.
  - The Edge loads the parent first, gives a resumed subagent the parent's shell, and runs it in the workspace and working directory it would have in a turn.
  - Before, such a message failed with "File operations are only available during an active turn".
- **Subagent model selection** (#296): Settings → Built-in plugins → Settings → Subagent now shows upstream's **Model selection** section. It is off by default, as in upstream.
  - When it is on, each new session records the models its subagents may use. The parent can list them with `list_subagent_models` and run a `subagent` on one of them, which may differ from its own.
  - Turning it on with no model chosen is refused on save.
  - A session that has already run a turn keeps how it was set up, as upstream applies the setting only to new sessions.
  - `subagent_fork` subagents keep the parent's model.

### Known limitations

- Images sent to a subagent from the subagent panel are not verified on the Edge.
- Up to 8 subagents can stay loaded at once (upstream's default, changeable on the Subagent card). Model requests beyond the Workers limit of six simultaneous connections wait for a free connection.
- Upstream's turn outline (each turn's prompt and response preview) is not offered: it grows with every turn, and the Edge stores a session's cached values as one record, so a long session would outgrow it.
- Upstream's `/feedback` command is not offered: it keeps an anonymous user id in a local file, which Workers cannot store.
- `glob` and `grep` do not apply `.gitignore` files, so `grep` searches ignored files that ripgrep would skip.
- File write protection covers the `write` and `edit` tools. A shell or container command that writes a file during a guarded write is not detected, as in upstream; one that finished before the guarded write is.
- Rolling back to 0.18 after an upgrade from it is not supported.
- The Agent presets page intro and mode guide mention upstream's Creator mode, which the Edge does not offer.
- The 0.18.0 limitations about the Node 22 test environment, local `dev:container` cleanup, and symlinks outside `/workspace` still hold.

### Validation and upgrade

`pnpm run check` passes 902 tests. Integration runs against both release artifacts (Direct and Isolated), with new checks for:
- a background subagent that writes a file after the parent's turn returns, and the parent's wake-up turn that writes one too;
- `list_agents`;
- after a restart, `subagent_fork` seeded from the reloaded parent's history, and `send_message` resuming the subagent;
- after a restart, a panel message to the subagent of a parent that is not loaded, with a relative write in the parent's project directory and a `bash` command;
- Stop on the parent leaving a running subagent working, and `interrupt_agent` ending its turn;
- model selection:
  - off by default;
  - turning it on with no model refused;
  - a new session recording the allowed models once;
  - a subagent run on an allowed model that differs from the parent's;
  - a model outside the list refused;
  - a session started before the setting was turned on kept as it was;
  - the setting surviving a restart.

Browser snapshots pin the Subagent card's Model selection section. The packed installer passes `pack:verify`. `upgrade-from-release.probe.mjs` upgrades state created by the published 0.23.0, 0.22.0, and 0.18.0, passing 11 checks each. Not yet validated on a staging instance.

Upgrade a test instance with `npx dsh-edge@next upgrade` and choose "Update it".
