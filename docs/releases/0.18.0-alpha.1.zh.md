## dsh-edge 0.18.0-alpha.1

Linux 容器运行时、按能力引导的安装器和网页端运行设置的首个预览版。在 Workers Paid 上，实例现在可以加一个 Linux 容器，用于 git、npm、node 和 python3。每条 bash 命令按需要在轻量 shell 或容器中运行。本版发布至 npm 的 `next` 频道，`latest` 仍为 0.17.0。建议先在测试实例上试用，再升级主要部署。上游 Harness 基线保持 0.1.5-rc.2。

### 新增

- **Linux 容器**（#218、#219、#226）：即新的“+ Work on code projects”能力，需要 Workers Paid。
  - 容器挂在实例的 Durable Object 上，使用 `basic` 实例规格。
  - 自带 git、node 22、npm、python3、jq、make、bzip2、xz、zstd、zip 和 unzip。
  - 每次发版都会发布对应版本的镜像 `docker.io/pawaca/dsh-edge-computer:<version>`。
  - 工作区文件保存在 Durable Object 中并与容器同步，因此停止或替换容器不会丢失文件。
  - 容器可以访问互联网，但不会拿到任何 Edge 凭据。
  - 闲置一段时间后容器进入休眠，下一条 Linux 命令会在约 5 秒内唤醒它。部署后的第一条命令可能要等几分钟，等待镜像分发完成。
  - 容器内同时最多运行 2 条命令，其余排队等待。
- **按命令分流**（#221、#223、#224）：有容器时，每条 bash 命令从合适的位置开始运行。
  - 文件和文本操作留在轻量 shell；git、npm、python3 等只有 Linux 才有的程序进入容器。
  - 轻量 shell 跑不了的命令（工具报告不支持，或访问了 `/workspace` 之外的路径，例如 `/etc/os-release`）：如果没有改动任何文件，就透明地在容器中重跑（`retriedFromLight`）；如果已经改动了文件，则报告为 `lightShellMiss`，由 agent 决定是否重试。
  - 重跑共用这条命令的超时时间。
- **运行设置**（#227、#228）：DSH Edge 设置页现在显示实例能做什么、费用，以及调整能力的命令。
  - 容器部署另有一张 Linux 容器卡片：实时状态、**立即休眠**、命令执行方式（自动、总是轻量、总是 Linux）和闲置多久后休眠（5、10 或 30 分钟）。
  - 修改对下一条命令立即生效，无需重启，重启后仍然保留。
  - 对应接口为 `GET`/`PUT /api/runtime` 和 `POST /api/runtime/container/stop`。

### 变更

- **安装器**（#229）：改为按能力而不是按套餐提问，每一步都按回车即可装完。
  - 顺序为：账号、Worker 名称、能力，最后确认一次。
  - 能力问题提供“Research and write”（免费，默认）、“+ Analyze data and split big jobs”（Workers Paid；`run_code` 和 `workflow`）以及“+ Work on code projects”（Workers Paid 加容器运行时长）。
  - 临时账号跳过能力问题，Cloudflare 条款并入那一次确认。
  - 新安装把图片存在 Durable Object 中，不再询问 R2；已使用 R2 的实例继续使用 R2。
  - owner 访问密钥自动生成，也可以通过 `DSH_EDGE_ACCESS_KEY` 提供，不再使用命令行参数传入。DeepSeek key 在 Settings → Models 中再填写。
  - 部署完成后，安装器会询问是否打开浏览器。
- **同名即更新**（#229）：用已有 Worker 的名称再次运行 `install`，默认选项是“Update it”。
  - 更新会保留实例的能力、对话、文件、访问密钥和 DeepSeek key，不会再次询问。
  - “Update and change what it can do”会标出当前能力；降级时列出将被移除的内容，默认 No。
  - 同名但不是 dsh-edge 的 Worker 永远不会被更新，该名称视为已被占用。
  - `upgrade` 走同一流程，Worker 不存在时直接报错。
- **更新只做公开验证**（#229）：更新保留的 owner 密钥无法读回，因此安装器只确认公开版本已是新版本（“live”）。登录后才会暴露的启动故障，要到 owner 下次登录时才会看到。
- **离开 Container 模式时保留 Container application**（#229）：它是回退目标。安装器会打印删除命令；登录新版本确认正常后运行该命令，即可停止 Container 计费。
- **`@cloudflare/computer` 0.3.1**（#217），与容器镜像中的 computerd 成对升级。

### 已知限制

- 本版的安装器和容器运行时已在本地测试（包括本地 Docker 容器），但尚未在真实账号上测试。本 alpha 就是为了这项测试。
- 在 Node 22 上，`pnpm run check` 有两个异步上下文测试失败；Node 24 下全部通过。这只影响测试环境：被测代码运行在 workerd 中，CI 使用 Node 24。该问题自 0.17.0 起就存在。
- 停止 `pnpm --filter dsh-edge dev:container` 后，本地 Docker 容器可能仍在运行；可用 `docker ps` 和 `docker rm -f` 清理。
- 指向 `/workspace` 之外的符号链接不在分流处理范围内。

### 验证与升级

`pnpm run check` 通过 756 个测试。集成测试针对两种发布产物（Direct 和 Isolated）运行。Container 集成测试用正式产物对接本地 Docker 容器，覆盖分流、重跑，以及把自动分流与强制 Linux 运行逐条比对的差异语料；还覆盖了运行设置、立即休眠，以及重启后设置仍然保留。Container 集成测试也在 CI 中每日运行。打包后的安装器会在工作区之外安装，启动 Direct 和 Isolated 两种 Worker，并检查 Container 配置部署的是已发布的镜像。

用 `npx dsh-edge@next upgrade` 升级测试实例，选择“Update it”即可保留一切。要加上容器，选择“Update and change what it can do”，再选“+ Work on code projects”。本版没有新增存储结构或迁移。
