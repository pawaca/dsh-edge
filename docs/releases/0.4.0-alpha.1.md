# dsh-edge 0.4.0-alpha.1

English | [中文](https://github.com/pawaca/dsh-edge/blob/dsh-edge-v0.4.0-alpha.1/docs/releases/0.4.0-alpha.1.zh.md)

This prerelease adds runtime-configurable provider settings and writable credentials, enabling API key management and model configuration from the browser without redeployment.

## Highlights

- **Writable credentials**: API keys can now be stored at runtime through the Settings UI. The upstream `CredentialProvider` seam persists values in Durable Object storage with Worker environment secret fallback.
- **Settings integration**: The upstream `dsh-settings` subsystem is installed with a Durable Object storage provider. The Settings → Models page displays the registered `llm-deepseek` namespace.
- **Upstream LLM plugin**: `dsh-llm-deepseek` is installed as a cordis plugin instead of the previous Edge-owned `EdgeDeepSeekAdapter`. The plugin auto-registers the settings namespace and configurable provider entry.
- **OpenAI-compatible endpoint switching**: Users can change the DeepSeek `baseURL` through Settings to point at OpenAI, Groq, OpenRouter, or any OpenAI-compatible gateway.
- **Edge defaults preserved**: `maxTokens` defaults to 8,192 and `reasoningEffort` defaults to `off` when deployment environment variables are unset, matching documented behavior.
- **Deferred plugin failure**: A malformed `DEEPSEEK_BASE_URL` no longer crashes the entire Durable Object; workspace, settings, and diagnostic APIs remain available.

## Limitations

- Provider configuration changes through the upstream Models UI are not yet verified end-to-end in a real deployment. This alpha validates the infrastructure.
- Only OpenAI-compatible protocols are supported. Native Anthropic API requires `dsh-llm-pi-ai`, which is not compatible with Cloudflare Workers.
- Multiple simultaneous providers (e.g., DeepSeek + OpenAI side by side) are not supported in this release.

## Upgrade

```sh
npx dsh-edge@next upgrade
```

Existing deployments are fully backward compatible. No migration is required.
