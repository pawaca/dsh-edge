# dsh-edge 0.3.0-alpha.2

[English](https://github.com/pawaca/dsh-edge/blob/dsh-edge-v0.3.0-alpha.2/docs/releases/0.3.0-alpha.2.md) | 中文

这个修正预发布版本保留 alpha.1 引入的模型与图片能力，同时移除已有 Workers Free 部署不必要的 R2 启用门槛。

## 亮点

- 识别在图片能力出现前创建的 Worker，并询问一次新图片的存储位置：无需启用 R2 的有界 Durable Object storage，或私有 R2 bucket。
- 旧版升级默认选择 Durable Object storage，并明确显示每个实例 64 MiB 的限制。
- 在收集 Worker secret 前检查 R2。Cloudflare 返回 `10042` 时，现在会显示当前账户的启用 URL，并允许安全的旧版升级在同一次安装流程中重试、切换 DO 或取消。
- 保留所有已有 attachment marker 或权威 R2 binding；任何可能持有图片引用的部署都不会在 backend 之间静默切换。
- 新的永久安装继续使用私有 R2，并说明 R2 Standard 有月度免费额度，但必须先启用其独立的按量 subscription。
- 更新只读 `agent.cordis.yml` projection，区分部署默认模型与 per-session 选择，并列出 runtime 实际读取的上游 DeepSeek catalog。
- 从简洁安装错误中移除 Wrangler 已知的 Node `punycode` 弃用警告；完整诊断仍保留在 `--verbose` 输出与 Wrangler 日志中。

## 安装或升级

需要 Node.js 22.14 或更高版本，以及自己的 DeepSeek API key。

```sh
npx dsh-edge@next install
```

原地升级已有 Worker：

```sh
npx dsh-edge@next upgrade
```

已经标记为 `temporary-do` 或 `private-r2` 的 Worker 会直接保留该 backend，不再询问。只有既没有 attachment marker、也没有 R2 binding 的 pre-0.3 Worker 才会收到一次性选择。该版本无法保存图片引用，因此任选一个初始 backend 都是安全的。若尚未启用 R2，同一次引导流程可以把这个仍未固定的 Worker 切换到 DO；新的部署或已固定为 R2 的部署必须启用 R2 后重试，或取消。部署后会固定选择，自动迁移仍不在当前范围内。

## 限制与兼容性

Durable Object 图片存储对每个 owner instance 限制为 64 MiB。R2-backed 部署需要已启用 R2 subscription，超过 Standard 月度免费额度后仍遵循 Cloudflare 按量计费。两个 backend 都只接受 PNG 与 JPEG：每条消息最多 4 张、每张 3.5 MiB、每条消息合计 7 MiB、最多 4,000 万像素，且单边不超过 2,000 像素。

Vision Exp 仍是实验模型，可能并非对每个 DeepSeek 账户开放。部署继续采用 single-owner 模式；alpha.1 列出的其他暂缓 Edge 能力没有变化。

## 发布完整性

npm package 从经过 Review 的 `dsh-edge-v0.3.0-alpha.2` tag 发布到 `next` dist-tag。发布自动化会在可信发布前验证 tag、package identity、双语说明、两种 attachment 选择、model catalog projection、browser snapshot、持久化兼容性，以及从 workspace 外安装打包产物。配套 GitHub prerelease 会携带同一个 tarball asset。
