## dsh-edge 0.18.0-alpha.4

修复手动测试 0.18.0-alpha.3 时发现的两个问题：所有者现在可以选择新会话的起始预设和起始模型。本版发布至 npm 的 `next` 频道，`latest` 仍为 0.17.0。上游 Harness 基线保持 0.1.5-rc.2。[0.18.0-alpha.3](0.18.0-alpha.3.zh.md)、[0.18.0-alpha.2](0.18.0-alpha.2.zh.md) 和 [0.18.0-alpha.1](0.18.0-alpha.1.zh.md) 的内容仍然适用。

### 修复

- **默认预设**（#240）：在 Settings → Agent presets 里选择预设，会显示 `settings namespace "agent-presets" is not registered`，新会话也总是从标准模式开始。
  - 现在和上游一样：新会话从选中的预设开始，“In use”标签也跟着移动。
  - 只能选择部署提供的预设。如果部署之后不再提供 PTC 模式，已保存的 PTC 默认值会按标准模式处理。
- **默认模型**（#240）：不管所有者之前选过什么，新会话总是从 DeepSeek-V4-Flash 开始。
  - 与上游一致，在任一会话中最近一次选择的模型，就是新会话的起始模型。
  - `DEEPSEEK_MODEL`（默认 `deepseek-v4-flash`）只在所有者第一次选择模型之前生效。
  - 如果保存选择失败，保留之前的默认值。

### 已知限制

- 部署默认模型仍是 DeepSeek-V4-Flash。上游说明 DeepSeek-V41-Flash（`deepseek-flash`）在 DeepSeek API 开放之前可能调用失败，因此是否切换交给所有者决定。
- 0.18.0-alpha.3 列出的限制仍然存在。

### 验证与升级

`pnpm run check` 通过 778 个测试。集成测试针对两种发布产物运行：
- 在一个会话中选择模型后，新会话报告的就是该模型。
- 在 isolated 构建中，把 PTC 模式设为默认后，“In use”标记随之移动，新会话从 PTC 模式开始。

用 `npx dsh-edge@next upgrade` 升级测试实例，选择"Update it"。本版没有存储迁移；默认预设保存在已有的设置文档中。
