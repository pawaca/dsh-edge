## dsh-edge 0.29.0

Bash commands keep running past the output cap, `grep` applies ignore files, and four upstream surfaces join the Edge: the ralph tool, the session history tools, MCP resources, and the Shell settings card. Published to the stable npm `latest` channel, with the same code as [0.29.0-alpha.1](0.29.0-alpha.1.md); the staging run found that a burst of output stops a Linux Container (below). The upstream baseline stays 0.2.1-rc.2 and the session format stays V4, so upgrading from 0.28 migrates no stored data.

### Added

- **Session history tools** (#362, #367): upstream's `session_search`, `session_event_search`, `session_trace`, `session_event_trace`, and `session_event_read` let the model find and read earlier sessions. They are off by default; turn them on under Settings → DSH Edge → Optional tools. A change applies from the next model request, a mount that fails is reverted, and a failed mount after a restart is retried before the next turn.
  - Reads of stored sessions stay bounded: search covers the 32 newest sessions; a read takes the event and its neighbors in pages of at most 4 MiB, checking each row's size before loading it; titles come from the session summary.
- **MCP resources** (#364, #368): a server that declares the resources capability gets upstream's `list_mcp_resources`, `list_mcp_resource_templates`, and `read_mcp_resource`. Each response is limited to 1 MiB and fails while it streams in past that. Resource calls follow the connector's tool permission, and a server with resources but no tools can be added.
- **ralph tool** (#363, #365, Isolated only): upstream's fresh-agent loop, which runs one new subagent per round toward one objective until a round reports completion or a blocker. It runs on the workflow engine, so a run is limited to 100 rounds (upstream allows 256). As upstream, its prompt reserves it for an explicit request, and the PTC mode preset does not offer it.
- **Shell settings card** (#345, #370): Settings → Built-in plugins → Settings shows upstream's Shell card. Its command timeout defaults to `DSH_EDGE_DEFAULT_COMMAND_TIMEOUT_MS` and may not exceed `DSH_EDGE_MAX_COMMAND_TIMEOUT_MS`; its output cap per stream (64,000 bytes by default, 1 KiB to 1 MiB) is the inline tail before output spills. Both apply to the next command.

### Changed

- **Long command output** (#345, #369): a command no longer stops when its output passes 64 KiB. As upstream, each stream keeps its last 64,000 bytes inline and saves the whole stream to `/workspace/.spill/bash-<execution>.<stream>.txt`, which the result names, so `npm install` or a noisy test run finishes in the lightweight shell. In a Linux Container, a large burst of output can instead stop the container (see Known limitations). A stream saves at most 16 MiB; output under the cap writes nothing. The result shows upstream's layout: stdout, a `[stderr]` section, a notice per truncated stream, `[timed out after Nms]`, and `[exit code: N]` last. A `timeoutMs` above the ceiling is lowered to it instead of refused, and the terminal card shows the working directory.
- **`grep` and ignore files** (#346, #366): as ripgrep's defaults that upstream's `grep` keeps, `grep` skips what `.rgignore`, `.ignore`, and (inside a git repository) `.gitignore` files exclude, without entering an ignored directory. A large ignored `node_modules` therefore no longer exhausts the 20,000-entry walk. An `include` glob still selects a file an ignore file excludes, as ripgrep's `--glob` does. `glob` keeps upstream's behavior and lists ignored files.

### Known limitations

- **A burst of output stops a Linux Container** (#373). computerd 0.3.1, the daemon inside the container, ends a command when its process exits, while output can still be waiting in the pipes. When the Durable Object reads the output more slowly than the command writes it, the output that arrives after the exit makes computerd throw and exit. On the staging instance, `seq 1 60000` (about 350 KB) failed this way on almost every run: the call failed with an internal error, the rest of the command did not run, and the container restarted in 4 to 6 seconds. The upstream fix (cloudflare/computer#260) is not released yet; computerd and the Computer package must be upgraded together, so the Edge picks it up with that upgrade. Until then, redirect large output to a file in the container, such as `npm install > /tmp/install.log 2>&1; tail -n 50 /tmp/install.log`. Commands in the lightweight shell are not affected.
- The lightweight shell returns a command's output whole rather than streaming it, so it still stops a command whose output passes 8 MiB (previously 64 KiB), reported as `[stopped: …]`.
- A spill uses workspace storage that is never freed (#358), which is why a stream saves at most 16 MiB. A spill whose write fails midway leaves its stored chunks unreachable.
- `glob` at a repository root with a large `node_modules` can still pass its 20,000-entry limit, as upstream's `glob` lists ignored files.
- `grep` differs from ripgrep in rare cases: `?` and character classes match by character rather than by byte; one search compiles at most 5,000 ignore patterns and tests them at most 5,000,000 times; an ignore file over 256 KiB is not applied; global gitignore and `.git/info/exclude` are not read.
- Every session of an instance can read every other through the session history tools, because their access check compares working directories and every Edge session starts in `/workspace`. `session_event_trace` refuses a stored session over 10,000 events or 8 Mi stored characters, and `session_trace` refuses an instance with more than 2,000 stored sessions. Turning the tools off while a request is in flight makes a call to them in that response fail as an unknown tool.
- Reading a session stored in an earlier format migrates its whole log in memory first (#371).
- An MCP server configured before this release offers resources only after it is probed again.
- The other limitations listed for 0.28.0 still hold.

### Validation and upgrade

`pnpm run check` passes 1,081 tests. New tests cover the output capture (20 MiB at a flat footprint, the tail, partial and pending spills, cancellation and deadline bounds), the ignore rules and their precedence and budgets, the bounded session reads, the tool switch, MCP resource requests and approvals, and the Shell card settings.

Integration runs against both release artifacts (Direct and Isolated). New checks:
- a two-round ralph loop through structured reports (Isolated);
- the session history tools enabled and disabled through the settings API, with `session_search` finding an earlier session;
- a probed MCP server's text resource and a 2 MiB resource refused at the cap;
- `grep` skipping a directory an `.ignore` excludes while `glob` lists it;
- a Shell card cap of 2,048 bytes applied to the next command.

The Container integration ran locally against Docker: `seq 1 1000000` (about 6.9 MB) completed with its later side effect, the tail ended with the last lines within 64,000 bytes, and the spill's SHA-256 matched the output. Locally the container stops only when the Durable Object's reader is slowed artificially, which is how #373 was reproduced.

Measured locally in the Workers runtime:
- `row-cost.probe.mjs` against 0.28.0: plain turns write the same rows (443 SQL rows and 36 KV and alarm writes over nine turns).
- `upgrade-from-release.probe.mjs` upgrades state created by the published 0.28.0, passing 11 checks.

The release artifacts stay within Cloudflare's 64 MiB size limit (Direct 8.3 MB, Isolated 9.7 MB), and their startup takes about 110 to 125 ms locally, against Cloudflare's 1 s limit.

On a staging instance upgraded from 0.28.0 to 0.29.0-alpha.1 (Isolated, with the Linux container):
- in the lightweight shell, `seq 1 20000` kept its last 64,000 bytes inline and saved the whole output to its spill file;
- in the container, `seq 1 200000` once ran to the end, its spill file's MD5 matched the output, and the command after it ran; repeated bursts of 350 KB and more then stopped the container (#373), while `seq 1 300000 > /tmp/big.log 2>&1; tail -n 2 /tmp/big.log` passed five runs out of five;
- with a `.ignore` excluding `skipped/`, `grep` found matches only outside it while `glob` listed `skipped/e.txt`;
- with the session history tools on, the model found an earlier session's note with `session_search` and read the matching event; with them off, `tools.session_search` was undefined;
- a Shell card timeout of 3 seconds and output cap of 2,048 bytes applied to the next command;
- turns were stored and read back normally, and the Worker logs showed no errors other than the container stops.

MCP resources were not exercised on staging, because the instance's only MCP server needed its OAuth sign-in renewed; the integration covers them. ralph was not run on staging.

Upgrade with `npx dsh-edge@latest upgrade` and choose "Update it", then reload the page. The Web page updates at once, but the instance behind it can keep running the previous version for a few minutes after an upgrade.
