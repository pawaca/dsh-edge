# dsh-edge 0.3.0

[English](https://github.com/pawaca/dsh-edge/blob/dsh-edge-v0.3.0/docs/releases/0.3.0.md) | 中文

dsh-edge 0.3 把上游 DeepSeek Harness 的模型与图片体验带到个人 Cloudflare 部署中，同时继续以上游 UI、agent loop、协议和 schema 为权威实现。

## 亮点

- 把精确锁定的 Harness 发布基线升级到 `0.1.1-rc.1`。
- 通过上游选择器提供 DeepSeek V4 Flash、V4 Pro 和实验性 V4 Flash Vision Exp 模型。
- 原样复用上游图片 composer、gallery、lightbox、attachment 协议、准入规则和 provider serializer。
- 新的永久部署把图片存入私有 R2；临时部署使用有界的 64 MiB Durable Object backend。
- 两种 runtime 都支持 DeepSeek Web Search、持久对话、`/workspace` 和原生 DSH `bash` tool。
- 保留一条命令安装、single-owner 登录、原地升级和部署诊断，不要求源码仓库或 Cloudflare Builds。

## 安装或升级

需要 Node.js 22.14 或更高版本，以及你自己的 DeepSeek API key。

```sh
npx dsh-edge install
```

原地升级现有 Worker：

```sh
npx dsh-edge upgrade
```

如果当前安装版本包含 `-alpha` 或 `-rc`，请执行一次 `npx dsh-edge@latest upgrade` 切换到稳定渠道。

Workers Free 选择 **Free — Direct Shell**，Workers Paid 可选择 **Isolated — Dynamic Worker**。两种模式使用相同 UI、协议、对话、Workspace、模型选择器、图片流程和 Web Search tool。

## Attachment storage 与升级

新的永久部署使用私有 R2 bucket。Cloudflare 为 R2 Standard 提供月度免费额度，但账户必须先启用独立的按量 R2 subscription。临时部署使用有界 Durable Object storage，必须在 60 分钟内认领才能保留 Worker 与数据。

Attachment backend 会在每个部署中固定。图片功能之前创建的 Worker 没有 attachment marker 或图片引用，因此首次升级到 0.3 时会在无需额外设置的 DO storage 与私有 R2 之间选择一次。已有 marker 与 R2 binding 始终保留；自动迁移刻意不在当前范围内。

## 限制与兼容性

图片必须是 PNG 或 JPEG。每条消息最多 4 张、每张 3.5 MiB、合计 7 MiB、最多 4,000 万像素，且单边不超过 2,000 像素。Vision Exp 仍是实验模型，可能并非对所有 DeepSeek 账户开放。

部署仍刻意采用 single-owner 模式。非图片附件、会话导出、`@file`、`@session`、remote MCP、Skills、Workflows、Jobs 和 Subagents 尚未适配 Edge。Runtime 在拥有明确的 SSRF、私网地址和重定向策略前，`web_fetch` 保持禁用。

## 发布完整性

npm package 从经过 Review 的 `dsh-edge-v0.3.0` tag 发布到 `latest` dist-tag。发布自动化会在可信发布前验证 package identity、双语说明、Direct/Isolated artifact、两种 attachment backend、模型选择、browser snapshot、持久化兼容性，以及从 workspace 外安装打包产物。配套 GitHub Release 会携带同一个 tarball asset。
