## dsh-edge 0.32.0-alpha.1

The Web client's changed-files card now appears under a turn that edited files with `write` or `edit`, listing each file's added and deleted lines and opening its comparison in the sidebar. The system prompt also gains upstream's guidance on linking files and on when to use `present`. Published to npm's `next` channel; `latest` remains on 0.31.0. The upstream baseline stays 0.2.1-rc.2 and the session format stays V4.

### Added

- **Changed-files card** (#391): the Edge now serves upstream's `workspaceChanges` (`dsh-workspace-changes`) in its documented no-git mode.
  - **What is listed:** every top-level turn's `write` and `edit` calls. Each edited file is copied before its first edit in the turn and again at turn end, compared line by line as upstream compares, and announced with a `workspace/changes` event.
  - **Not listed:** Workers run no git, so files changed only through `bash` or in the Linux container are not listed, and subagent sessions are not recorded.
  - **Bounds:**
    - as upstream, a file over 2 MiB is listed without counts or comparison;
    - unlike upstream, so is a file with more than 20,000 lines on either side, because a comparison allocates per line;
    - a file holding a NUL byte is listed as binary;
    - a rewrite with unchanged content is not listed;
    - a summary carries at most 500 files.
  - **Where copies live:** in the workspace VFS under `/.dsh/workspace-changes`, named by their SHA-1, so a turn holds at most two file contents in memory. They are removed with their session, and those of a previous Durable Object activation before the next capture.
  - **Lifetime:** as upstream's, summaries live with their resident session; after a restart, earlier turns have no card.

### Changed

- **Deliverables host half** (#391): upstream's `dsh-client-ui-deliverables` host half is now mounted as is. It serves the cards' `/api/present.*` and `/api/changes.*` routes, which replace the Edge's own present handlers and answer the same way without a desktop. It also adds upstream's `ui:deliverable-file-references` section to the system prompt: link every mention of an existing file to its path, show primary results inline, and use `present` when a file card helps. The Edge had not sent this section before, so model replies may link files more often.

### Known limitations

- The changed-files card lists file-tool edits only; shell and Linux container edits need a turn-start view of the workspace, which is not built yet.
- A turn that edits files writes more Durable Object rows for the copies: a turn whose one `write` creates a file wrote 31 more rows than on 0.31.0. Turns that edit no file are unchanged.
- The other limitations listed for 0.31.0 still hold.

### Validation

`pnpm run check` passes 1,129 tests. New tests cover the comparison (line counts, a missing final newline, the timeout's whole-file fallback) and the recorder:
- edits, new and deleted files, an unchanged rewrite, paths outside the working directory and under `/tmp`;
- oversized files by bytes and by lines, and binary files;
- no event for a quiet turn or a subagent;
- one copy per content;
- removal of a disposed session's copies and of a previous activation's.

Integration runs against both release artifacts (Direct and Isolated). A scripted turn reads a file, edits it, writes a new file, rewrites a third with the same content, and changes a fourth through bash.
- `/api/changes.summary` lists exactly the edited and the new file with their counts.
- `/api/changes.diff` returns their hunks.
- The deliverables routes answer from upstream's handlers.

A new browser check, in both modes, sends that turn and finds the "Edited 2 files" card, then opens a file's comparison.

Measured locally in the Workers runtime:
- `row-cost.probe.mjs` against 0.31.0: plain, bash, and schedule turns write the same rows (443 SQL rows and 36 KV and alarm writes over nine plain turns). The step whose woken parent writes one file writes 31 more rows (243 against 212), and a cold resume reads 628 rows against 616.
- `upgrade-from-release.probe.mjs` upgrades state created by the published 0.31.0, passing 11 checks.

The release artifacts stay within Cloudflare's 64 MiB size limit (Direct 8.4 MB, Isolated 9.7 MB). Not yet validated on a staging instance.

Upgrade a test instance with `npx dsh-edge@next upgrade` and choose "Update it".
