# dsh-edge 0.3.0-alpha.1

[English](https://github.com/pawaca/dsh-edge/blob/dsh-edge-v0.3.0-alpha.1/docs/releases/0.3.0-alpha.1.md) | 中文

这个预发布版本把 DeepSeek Harness `0.1.1-rc.1` 已发布的模型与图片体验带到 Cloudflare。它开放上游三款 DeepSeek 模型，保留上游 composer、gallery、wire protocol、admission rule 与 provider conversion，仅在这些能力下方选择 Cloudflare 原生的图片 backend。

## 亮点

- 把完整固定的 Harness 依赖闭包升级到 `0.1.1-rc.1`，并通过上游模型选择器开放 V4 Flash、V4 Pro 与实验性的 V4 Flash Vision Exp。
- 在不改变上游 session protocol 的前提下，让每个 session 的上游模型选择跨 Durable Object 休眠与重启恢复。
- 启用上游 PNG/JPEG 粘贴、拖入、预览、历史 gallery 与 lightbox 体验。
- 永久账户安装会把不可变图片字节存入私有 R2 bucket，session event 仍只保留上游 content-addressed reference。
- 匿名临时账户安装通过有界的 64 MiB、按 512 KiB 分块的 Durable Object backend，获得相同的浏览器图片流程。
- 每个部署固定所选 attachment backend，确保认领、休眠、重启与升级不会让已有图片 reference 失联。
- 以产品结果、真实运行截图、一条命令安装以及清晰的临时/永久选择，重写仓库首页。

## 安装或升级预发布版本

需要 Node.js 22.14 或更高版本，以及自己的 DeepSeek API key。

```sh
npx dsh-edge@next install
```

已有预发布部署可以原地升级：

```sh
npx dsh-edge@next upgrade
```

npm `next` dist-tag 会移动到 `0.3.0-alpha.1`，`latest` 继续停留在 `0.2.0`。Durable Object 中的对话、工作区与 VFS 数据保持兼容。Cloudflare secret 只能写入、不能读回，因此升级仍会询问已有 owner access key 和 DeepSeek API key。

新的永久部署会创建或复用私有 R2 bucket，所选账户必须已经启用 R2。临时部署使用 Durable Object 图片存储，并且必须在 60 分钟内认领才能保留 Worker 与数据。认领会保留该 backend；本版本不会自动把临时图片迁移到 R2。

## 限制与兼容性

图片仅接受 PNG 和 JPEG：每条消息最多 4 张、每张 3.5 MiB、每条消息合计 7 MiB、最多 4,000 万像素，且单边不超过 2,000 像素。Vision Exp 仍是实验模型，可能并非对所有 DeepSeek 账户开放。

部署继续有意采用 single-owner 模式。非图片文件附件、会话导出、`@file` 与 `@session` 引用、remote MCP、Skills、Workflows、Jobs 和 Subagents 继续暂缓。`web_fetch` 在具备明确的 SSRF、私网地址与重定向策略前保持关闭。Direct Shell 仍是 just-bash 环境而非 Linux 容器；Dynamic Worker 模式仍要求符合条件的 Workers Paid 套餐。

Edge release 没有增加独立的模型、附件或浏览器协议。它使用已发布的上游 package，并在 R2 或 Durable Object storage 上实现现有 `AttachmentStore` seam。这个版本保留 5 个绑定精确版本的上游 patch；当 storage seam 使上游图片输入可以直接组合后，阶段 3 已删除原有 conversation capability patch。

## 发布完整性

npm package 从经过 Review 的 `dsh-edge-v0.3.0-alpha.1` tag 发布到 `next` dist-tag。发布自动化会验证 tag、版本号与这份已审阅的说明，重新构建精确的 standalone 装配，验证 Direct/Temporary DO 与 Dynamic/R2 集成、持久化兼容性和 browser snapshot，并在可信发布前从 workspace 外安装打包产物。配套 GitHub prerelease 会携带完全相同的 tarball asset。
