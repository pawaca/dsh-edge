# dsh-edge 0.3.0

English | [中文](https://github.com/pawaca/dsh-edge/blob/dsh-edge-v0.3.0/docs/releases/0.3.0.zh.md)

dsh-edge 0.3 brings the upstream DeepSeek Harness model and image experience to a personal Cloudflare deployment while keeping the upstream UI, agent loop, protocols, and schemas authoritative.

## Highlights

- Upgrades the exact published Harness baseline to `0.1.1-rc.1`.
- Exposes the upstream selector for DeepSeek V4 Flash, V4 Pro, and the experimental V4 Flash Vision Exp model.
- Reuses the upstream image composer, gallery, lightbox, attachment protocol, admission rules, and provider serializer.
- Stores images in private R2 for new permanent deployments or in a bounded 64 MiB Durable Object backend for temporary deployments.
- Keeps DeepSeek Web Search, persistent conversations, `/workspace`, and the native DSH `bash` tool available in both runtime modes.
- Preserves the one-command installer, single-owner login, in-place upgrades, and deployment diagnostics without requiring a source repository or Cloudflare Builds.

## Install or upgrade

Requires Node.js 22.14 or newer and your own DeepSeek API key.

```sh
npx dsh-edge install
```

Upgrade an existing Worker in place:

```sh
npx dsh-edge upgrade
```

If the installed version contains `-alpha` or `-rc`, switch it to the stable channel once with `npx dsh-edge@latest upgrade`.

Choose **Free — Direct Shell** for Workers Free or **Isolated — Dynamic Worker** for Workers Paid. Both modes use the same UI, protocol, conversations, Workspace, model selector, image flow, and Web Search tool.

## Attachment storage and upgrades

New permanent deployments use a private R2 bucket. Cloudflare includes an R2 Standard monthly free tier, but the account must first enable its separate usage-based R2 subscription. Temporary deployments use bounded Durable Object storage and must be claimed within 60 minutes to keep the Worker and its data.

The attachment backend is pinned per deployment. A Worker created before image support has no attachment marker or image references, so its first 0.3 upgrade asks once between no-setup DO storage and private R2. Existing markers and R2 bindings are always preserved; automatic migration is intentionally out of scope.

## Limits and compatibility

Images must be PNG or JPEG. One message accepts at most 4 images, 3.5 MiB each, 7 MiB total, 40 million pixels, and 2,000 pixels per side. Vision Exp remains experimental and may not be enabled for every DeepSeek account.

The deployment remains deliberately single-owner. Non-image file attachments, session export, `@file`, `@session`, remote MCP, Skills, Workflows, Jobs, and Subagents are not yet adapted to Edge. `web_fetch` remains disabled in 0.3.0; later releases may enable it only with explicit per-hop private-target blocking and Cloudflare's strictly-public global fetch routing.

## Release integrity

The npm package is published under the `latest` dist-tag from the reviewed `dsh-edge-v0.3.0` tag. Release automation verifies package identity, bilingual notes, Direct/Isolated artifacts, both attachment backends, model selection, browser snapshots, durable compatibility, and installation of the packed artifact outside the workspace before trusted publication. The matching GitHub Release carries the same tarball as an asset.
