## dsh-edge 0.14.1

为流式输出和后台 Agent 工作负载修复 Durable Session 写入批处理。上游基线仍为 0.1.2-rc.1。

### 修复

- **Durable Object 写放大**（#170）：不再为每个流式 Session 事件强制执行一次持久化 flush。事件现在共享上游 200ms 写回窗口，使连续的 Assistant chunk 能打包到一个物理事件行中，避免每个 token chunk 消耗多次 Durable Object 行写入。
- **先持久化、后可见的事件投递**（#170）：仅在批次持久化后发布 WebSocket 事件，并在空闲 mutation、重命名、活跃 turn、后台子代理及 detached Session 生命周期之间保持 seq 顺序。
- **Mux 回放/实时边界**（#170）：注册多路复用事件 Socket 前，等待所有待投递队列达到稳定状态，其中包括已经 detach 的冷 Session 队列。新订阅者不会再收到 seq 小于或等于已公告 `lastSeq` 基线的延迟事件。
- **投递失败隔离**（#170）：失败的 Session 级投递屏障保持为终止状态，防止后续批次或替换后的 Session 生命周期越过缺失的持久化事件，继续发布更高 seq 的事件。

### 验证

- 新增队列行为、SQLite 物理打包测试，以及 Direct 与 Dynamic Loader 发布产物集成测试。包含 100 个 chunk 的流式响应会持久化为一个打包后的 `text-chunks` 行，同时保持 WebSocket 与历史记录表面的完整顺序和内容。
