## dsh-edge 0.15.0-alpha.1

Upstream baseline upgrade to 0.1.5-rc.2. Published to npm's `next` channel for testing; the stable `latest` channel is unchanged.

### Changed

- **Upstream baseline 0.1.5-rc.2** (#169): all `@deepseek-ai/dsh-*` dependencies upgraded from 0.1.2-rc.1 to 0.1.5-rc.2. This brings Session Format V3, the SessionHandle-based persistence API, dynamic system prompt support, and the DeepSeek-V41-Flash model.
- **SessionPersistence rewrite** (#169): `DurableObjectSessionPersistence` reimplemented around the new `SessionHandle` API. The old `PersistenceCoordinator`/`PersistenceBackend` delegation is replaced with per-session handles that own append, flush, and close. Write ownership tracking prevents concurrent writers. Live session events route through handle buffering. The DO SQL storage layer (table schema, event encoding, summary materialization) is unchanged.
- **Session Format V0→V3 lazy migration** (#171): sessions stored at format V0 (the 0.1.2-rc.1 era format) are transparently migrated to V3 on first open, using the upstream `dsh-session-format-catalog` migration chain. Migration runs inside a DO SQL transaction.
- **Persona config** (#169): `persona:` renamed to `personaPrefix:` in the `SystemPrompt` plugin config.

### Added

- **DeepSeek-V41-Flash** (upstream): new default model with text + image input and in-history system prompt updates.

### Patches

- **Dropped**: `dsh-session-persistence` (coordinator deleted upstream), `dsh-message-feedback` (upstream uses event-sourcing).
- **Rebased**: `dsh-api-gateway`, `dsh-llm`, `dsh-tool-web`, `dsh-web-search-deepseek` (trivial), `dsh-api-session-controller`, `dsh-web-fetch-http`, `dsh-workspace` (reworked for upstream changes).

### Try the alpha

Upgrade with `npx dsh-edge@0.15.0-alpha.1 upgrade`, or install fresh with `npx dsh-edge@0.15.0-alpha.1 install`.

Suggested checks: verify existing sessions open and continue normally after the V0→V3 migration; verify new sessions use the correct format; test background subagents across turns.
