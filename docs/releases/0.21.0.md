## dsh-edge 0.21.0

Gives the agent three upstream Harness capabilities (#234): a task list, `AGENTS.md` instructions, and the `glob` and `grep` search tools. It also cuts the database reads of workspace file operations when an instance starts cold (#274). Published to the stable npm `latest` channel, with the same changes as [0.21.0-alpha.2](0.21.0-alpha.2.md) and [0.21.0-alpha.3](0.21.0-alpha.3.md). The upstream Harness baseline stays 0.2.0-rc.2 and the session format stays V4, so upgrading from 0.20 migrates no stored data. Upgrading from 0.18 still moves sessions to V4 as described in [0.19.0](0.19.0.md).

### Added

- **Task list** (#268): the agent keeps a session task list with upstream's `todo_write` tool, and the Web client shows it in the todo dock. Each update replaces the whole list; several tasks may be in progress at once, since subagents, background commands, and workflows run work in parallel.
- **`AGENTS.md` instructions** (#269): before the first request, the agent receives the `AGENTS.md` and `CLAUDE.md` files (and their `.local.md` overlays) from the project root down to the session's working directory, read from the workspace. The project root is the nearest directory containing `.git`, otherwise the working directory. When a `read`, `write`, or `edit` reaches a deeper directory, that directory's instructions join the next request. The user-global file is `/.dsh/AGENTS.md`, because Workers have no home directory.
- **`glob` and `grep`** (#270): the agent searches the workspace with upstream's `glob` (file paths, oldest first) and `grep` (matching lines grouped by file) instead of shell `find` and `grep`. Results over 100 paths or 250 matches are saved to a file the agent can read. Workers cannot run the ripgrep program upstream uses, so Edge runs the same tools over the workspace:
  - `grep` patterns use RE2 syntax, matched in linear time, so a pathological pattern cannot stall the instance. RE2 has no lookaround or backreferences, like ripgrep's default engine.
  - Both skip version-control directories such as `.git`; `grep` also skips hidden, binary, and over-4 MiB files.
  - Paths in results are relative to the session's working directory, also when that directory was given as `/workspace/./project` or with a trailing `/` (#272).
  - A search walks at most 20,000 entries and `grep` keeps at most 20,000 matching lines or 20 MB of their text; past a cap the search fails and asks for a narrower path or pattern. A search stops at the 30-second tool timeout.

### Fixed

- **Workspace file lookups read far fewer database rows when the instance starts cold** (#274). The workspace filesystem keeps recently used paths in memory. When that memory is empty (a new or idle-evicted instance), finding a file read every entry of each directory on its path, about 490 rows for a file in a 50-file directory, and more in wider directories. Searching the contents of 1,000 files therefore read about 490,000 rows, whether through the `grep` tool or `grep -r` in the shell. Lookups now go straight to the named entry: the same content search reads about 42,000 rows, and listing 1,000 files with `glob` or `find` reads about 2,700 instead of 10,000. Results are unchanged. The fix is a one-query patch to Cloudflare's `@cloudflare/computer` 0.3.1, recorded in `standalone/patches/audit.json`, and is removed once the library ships its own fix.

### Known limitations

- `glob` and `grep` do not apply `.gitignore` files, so `grep` searches ignored files that ripgrep would skip.
- File write protection covers the `write` and `edit` tools. A shell or container command that writes a file during a guarded write is not detected, as in upstream; one that finished before the guarded write is.
- Rolling back to 0.18 after an upgrade from it is not supported.
- The 0.18 plugin configuration cards (Agent loop, Web search) moved into upstream's plugin manager, which the Edge does not ship.
- The Agent presets page intro and mode guide mention upstream's Creator mode, which the Edge does not offer.
- The 0.18.0 limitations about the Node 22 test environment, local `dev:container` cleanup, and symlinks outside `/workspace` still hold.

### Validation and upgrade

`pnpm run check` passes 876 tests. Integration runs against both release artifacts (Direct and Isolated), the packed installer passes `pack:verify`, and `upgrade-from-release.probe.mjs` upgrades state created by the published 0.21.0-alpha.3, 0.20.0, and 0.18.0, passing 11 checks each. On a staging instance upgraded to 0.21.0-alpha.3:
- the agent kept a task list that the todo dock showed;
- a nested `AGENTS.md` reached the agent after it read a file in that directory, and the agent followed it;
- `glob` and `grep` returned the expected files and matches and left out `.md` and hidden files;
- `read`, `edit` after `read`, `write`, and `bash` produced the expected files;
- files written before the upgrade read back unchanged.

Upgrade with `npx dsh-edge@latest upgrade` and choose "Update it".
