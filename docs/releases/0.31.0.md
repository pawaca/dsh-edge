## dsh-edge 0.31.0

The Linux Container no longer stops when a command's output arrives after the command has exited. Deleted workspace files now give their storage back, and an old session too large to migrate no longer stops the instance from starting. Published to the stable npm `latest` channel, with the same code as [0.31.0-alpha.1](0.31.0-alpha.1.md), which passed a staging run (below). The upstream baseline stays 0.2.1-rc.2 and the session format stays V4. The workspace storage format moves forward on first start and cannot be read by 0.30 (see Upgrade).

### Fixed

- **Container output after a command exits** (#373, #384): the Container image now carries computerd 0.7.0, and the Worker `@cloudflare/computer` 0.7.0; the two are one wire-protocol pair and move together. computerd 0.3.1 stopped, taking the container and every command in it down, when output reached it after its command had exited. That happens when a background job started with `&` keeps the pipes, or when the Durable Object reads more slowly than the command prints.
  - A command now finishes once both output pipes close. If a background job still holds them, it finishes 250 ms after its shell exits; output the job writes afterwards is dropped, and the container keeps running.
  - 0.29.0's workaround, redirecting large output to a file, is no longer needed.
- **Old sessions too large to migrate** (#371, #387): a session stored in a format older than V4 is converted on the first start after an upgrade. Upstream's converter takes the whole log at once, about four times its stored size in memory (measured under a 128 MiB heap: 22 MiB converted, 26 MiB ran out).
  - A session with more than 8 MiB of stored events is now left as stored, with a warning in the Worker log; before, it failed every start of the instance.
  - The Edge treats such a session as absent: it is not listed, and reads by id answer that it does not exist. Its stored events are kept.
  - This only concerns instances upgrading from a release before 0.19.0 (which moved sessions to V4) that still hold such a session.

### Changed

- **Deleted files free their storage** (#358, #386): the workspace stores file contents as shared chunks, and deleting or overwriting a file never removed them, so stored size only grew. The daily cleanup now also deletes chunks no file uses, at most 200 per run and only if unused for at least a day.
  - It skips a run while the Linux Container is up, because the container may be syncing content it has not yet linked to a file.
  - It runs only on the workspace storage version it was written against, and stops with a warning on any other.
  - This covers expired spill files, replaced uploads, and files the model deleted or overwrote.

### Known limitations

- The Linux Container still uses Computer's platform-scheduled backend (`LegacyContainerBackend`). Computer's newer Durable Object-scheduled backend would need a new Durable Object class, leaving each instance's stored data behind, so it waits until Cloudflare can convert an existing application (#385).
- A deleted file's storage is freed a day or more after its last use, in batches of 200 chunks per daily run (hourly while a pass is unfinished), and not while the container is running.
- The other limitations listed for 0.30.0 still hold.

### Validation

`pnpm run check` passes 1,123 tests. New tests cover:
- The chunk cleanup, against the installed Computer's own table definitions: which chunks it deletes, the one-day margin, resuming across runs, and other storage versions. Further tests pin what the cleanup assumes about Computer, so a later upgrade that changes it fails CI.
- The 8 MiB migration limit: the instance starts, the other sessions migrate, the large session is not listed and keeps its rows, and no table rebuild drops them.

Integration runs against both release artifacts (Direct and Isolated). The Container integration adds a background job that writes 200,000 lines after its shell exits: the same container serves the next command. This check fails on 0.30.0.

Measured locally in the Workers runtime:
- `row-cost.probe.mjs` against 0.30.0: plain turns write the same rows (443 SQL rows and 36 KV and alarm writes over nine turns). The first turn reads 225 rows against 153; the extra 72 are the chunk cleanup's daily scan, which reads at most about 2,000.
- `vfs-reclaim.probe.mjs`, in both modes: after a 939 KB file is deleted and its chunks are aged past the margin, the next cleanup frees exactly its 938,890 bytes, and a kept file reads back whole.
- `upgrade-from-release.probe.mjs` upgrades state created by the published 0.30.0, passing 11 checks, including workspace files read back after the storage-format change.

The release artifacts stay within Cloudflare's 64 MiB size limit (Direct 8.4 MB, Isolated 9.7 MB).

On a staging instance upgraded from 0.30.0 to 0.31.0-alpha.1 (Isolated, with the Linux Container):
- the 52 sessions from before the upgrade were still listed;
- `seq 1 60000` (about 350 KB) in the container returned with exit code 0 and the rest of its command ran; on 0.29.0 the same command failed on almost every run and restarted the container;
- a background job writing 200,000 lines after its shell exited returned at once, and a file kept on the container's own disk was still there five seconds later, so the container had not restarted;
- a 300,000-line command still saved its full output to `/workspace/.spill`, and Computer kept no second copy in `/.computer/output`.

Freeing deleted files' storage was not observed on staging, since content must sit unused for a day first; it was measured locally (above).

### Upgrade

Upgrade with `npx dsh-edge@latest upgrade` and choose "Update it", then reload the page. The Web page updates at once, but the instance behind it can keep running the previous version for a few minutes after an upgrade.

**This upgrade is one-way for workspace storage.** On first start, Computer 0.7.0 moves the workspace storage format from version 8 to 10, and 0.30.0 refuses version 10. An instance rolled back to 0.30.0 after running this release cannot read its workspace files.
