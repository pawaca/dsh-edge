## dsh-edge 0.23.0-alpha.2

修复 0.23.0-alpha.1 staging 验收中发现的问题：两个 turn 之间写入的工作区 skill 现在会出现在 `/` 菜单中。发布到 npm 的 `next` 渠道；`latest` 仍为 0.22.0。上游 Harness 基线仍为 0.2.0-rc.2，会话格式仍为 V4，所以从 0.22 或 0.23.0-alpha.1 升级不会迁移任何已存数据。0.23.0-alpha.1 新增的内容（工作区 skill、图片卸载和子 agent 设置卡片）没有变化，详见其说明。

### 修复

- **skill 变更后的 `/` 菜单**（#292）：`/` 菜单的 skill 列表取自上次检查时缓存的目录，而 skill 目录只在 turn 开始前重新检查。因此两个 turn 之间写入的 `SKILL.md`，在之后打开的会话的 `/` 菜单里看不到，直到跑过一个 turn。现在列出前会像 turn 一样先检查文件大小和修改时间，只重读有变化的目录。
  - 与上游一致，已打开的页面会保留每个会话打开时的 `/` 列表，刷新后才更新。写入 skill 时已经打开的会话，刷新页面后即可看到。

### 已知限制

- 子 agent 卡片只显示"限制"部分：选择子 agent 可用的模型将在后续版本提供。
- 不提供上游的 turn 大纲（每个 turn 的提问与回答预览）：它随每个 turn 增长，而 Edge 把一个会话的缓存值存为一条记录，长会话会超出上限。
- 不提供上游的 `/feedback` 命令：它把匿名用户 id 保存在本地文件中，Workers 无法保存。
- 子 agent 运行期间暂时无法发消息、中断或列出（上游的 `send_message`、`interrupt_agent` 和 `list_agents`）。
- `glob` 和 `grep` 不应用 `.gitignore` 文件，所以 `grep` 会搜索 ripgrep 本会跳过的被忽略文件。
- 文件写入保护只覆盖 `write` 和 `edit` 工具。在受保护的写入进行期间，由 shell 或容器命令写入的文件改动不会被发现，这与上游一致；在受保护的写入之前已完成的改动会被发现。
- 从 0.18 升级后不支持退回 0.18。
- Agent 预设页的介绍和模式说明提到了上游的 Creator 模式，Edge 不提供该模式。
- 0.18.0 中关于 Node 22 测试环境、本地 `dev:container` 清理以及指向 `/workspace` 之外的符号链接的限制仍然存在。

### 验证与升级

0.23.0-alpha.1 已在 staging 实例上验收：已有会话保留、子 agent 卡片、真实模型加载工作区 skill、按项目区分的 `/` 列表，以及图片卸载。上面的修复正是这次验收中发现的。

`pnpm run check` 通过 902 个测试。集成测试覆盖两个发布产物（Direct 和 Isolated），新增一项检查：在 `/` 列表之后写入的 skill，不经过任何 turn 就出现在下一次列表中；去掉修复时该检查会失败。打包后的安装器通过 `pack:verify`。`upgrade-from-release.probe.mjs` 分别升级由已发布的 0.23.0-alpha.1、0.22.0 和 0.18.0 创建的数据，各通过 11 项检查。

用 `npx dsh-edge@next upgrade` 升级测试实例，选择"Update it"。
