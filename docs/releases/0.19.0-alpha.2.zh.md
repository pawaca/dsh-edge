## dsh-edge 0.19.0-alpha.2

新增找回丢失的 owner 访问密钥的方法。本版发布至 npm 的 `next` 频道，`latest` 仍为 0.18.0。上游 Harness 基线保持 0.2.0-rc.1。[0.19.0-alpha.1](0.19.0-alpha.1.zh.md) 的内容仍然适用，包括从 0.18 升级时不可回退的会话格式迁移。

### 新增

- **重置丢失的访问密钥**（#249）：Cloudflare 无法再次显示 Worker 的 secret；此前更新会保留密钥，但没有任何办法更换它。
  - Worker 已存在时，安装器提供 **Update and reset the access key**。它以相同能力部署该版本，并使用新的 owner key（自动生成，或取自 `DSH_EDGE_ACCESS_KEY`），只显示一次。
  - 对话、文件和 DeepSeek key 都保留，因为安装器只替换访问密钥。旧密钥随即失效，所有已登录的浏览器都需要重新登录。
  - 拿到新密钥后，安装器在部署完成后会登录并检查实例是否就绪，和新装时一样。普通更新仍然只验证公开发布版本。
  - 登录页会说明如何找回丢失的密钥，并给出与部署所在发布渠道一致的命令：预发布版为 `npx dsh-edge@next upgrade`，稳定版为 `npx dsh-edge@latest upgrade`。
  - `dsh-edge --help` 和 README 都说明了重置方法。

### 已知限制

0.19.0-alpha.1 列出的内容仍然适用。

### 验证与升级

`pnpm run check` 通过 844 个测试。集成测试覆盖两个发布产物（Direct 和 Isolated）。打包后的安装器通过 `pack:verify`，包括其 `--help` 文本。新增测试覆盖了用自动生成密钥和用自行提供密钥两种重置：只有访问密钥作为 secret 发送，能力不变，激活检查使用新密钥登录。其他测试覆盖了菜单、确认和完成提示，以及登录页按发布渠道给出的命令。重置尚未在真实 Cloudflare 账号上运行过；其他 secret 会被保留这一点，依据的是 Wrangler 4.129 文档中 `--secrets-file` 的行为。

用 `npx dsh-edge@next upgrade` 升级测试实例，选择"Update it"；如果已经没有密钥，选择"Update and reset the access key"。从 0.18 升级会把已存的会话迁移到新格式，不支持回退。
