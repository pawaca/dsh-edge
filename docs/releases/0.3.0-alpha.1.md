# dsh-edge 0.3.0-alpha.1

English | [中文](https://github.com/pawaca/dsh-edge/blob/dsh-edge-v0.3.0-alpha.1/docs/releases/0.3.0-alpha.1.zh.md)

This prerelease brings the published DeepSeek Harness `0.1.1-rc.1` model and image experience to Cloudflare. It exposes all three upstream DeepSeek models and keeps the upstream composer, gallery, wire protocol, admission rules, and provider conversion while selecting a Cloudflare-native image backend underneath them.

## Highlights

- Upgrades the complete pinned Harness closure to `0.1.1-rc.1` and exposes V4 Flash, V4 Pro, and experimental V4 Flash Vision Exp through the upstream model selector.
- Persists each session's upstream model selection across Durable Object hibernation and restart without changing the upstream session protocol.
- Enables the upstream PNG/JPEG paste, drop, preview, history-gallery, and lightbox experience.
- Stores immutable image bytes in a private R2 bucket for permanent-account installations while retaining only upstream content-addressed references in session events.
- Gives anonymous temporary-account installations the same browser image flow through a bounded 64 MiB, 512 KiB-chunked Durable Object backend.
- Pins the selected attachment backend per deployment so claim, sleep, restart, and upgrade cannot strand existing image references.
- Rewrites the repository landing page around the product outcome, a real runtime screenshot, the one-command installer, and a clear temporary-versus-permanent choice.

## Install or upgrade the prerelease

Requires Node.js 22.14 or newer and your own DeepSeek API key.

```sh
npx dsh-edge@next install
```

Existing prerelease deployments can upgrade in place:

```sh
npx dsh-edge@next upgrade
```

The `next` dist-tag moves to `0.3.0-alpha.1`; `latest` remains on `0.2.0`. Durable Object conversations, workspaces, and VFS data remain compatible. Cloudflare secrets are write-only, so an upgrade still asks for the existing owner access key and DeepSeek API key.

New permanent deployments create or reuse a private R2 bucket and require R2 to be enabled for the selected account. Temporary deployments use Durable Object image storage and must be claimed within 60 minutes to retain their Worker and data. Claiming preserves that backend; this release does not automatically migrate temporary images to R2.

## Limits and compatibility

Image admission accepts PNG and JPEG only, at most 4 images per message, 3.5 MiB per image, 7 MiB per message, 40 million pixels, and 2,000 pixels per side. Vision Exp remains experimental and may not be enabled for every DeepSeek account.

The deployment remains intentionally single-owner. Non-image file attachments, session export, `@file` and `@session` references, remote MCP, Skills, Workflows, Jobs, and Subagents remain deferred. `web_fetch` stays disabled pending an explicit SSRF, private-address, and redirect policy. Direct Shell remains a just-bash environment rather than a Linux container; Dynamic Worker mode still requires an eligible Workers Paid plan.

The Edge release adds no independent model, attachment, or browser protocol. It consumes the published upstream packages and implements the existing `AttachmentStore` seam over R2 or Durable Object storage. The release retains five exact-version upstream patches; Stage 3 removed the former conversation capability patch once the storage seam made upstream image intake directly composable.

## Release integrity

The npm package is published under the `next` dist-tag from the reviewed `dsh-edge-v0.3.0-alpha.1` tag. Release automation verifies that tag, version, and these reviewed notes, rebuilds the exact standalone assembly, exercises Direct/Temporary DO and Dynamic/R2 integrations, checks durable compatibility and browser snapshots, and installs the packed artifact outside the workspace before trusted publication. The matching GitHub prerelease carries the same tarball as an asset.
