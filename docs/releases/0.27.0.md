## dsh-edge 0.27.0

The upstream DeepSeek Harness 0.2.1-rc.2 baseline, with upstream's Automation tasks page, session log download, turn outline, and `/feedback`. Published to the stable npm `latest` channel, with the same changes as [0.27.0-alpha.1](0.27.0-alpha.1.md). The session format stays V4, so upgrading from 0.26 migrates no stored data.

### Added

- **Upstream baseline 0.2.1-rc.2** (#324): all upstream packages move from 0.2.0-rc.2 to 0.2.1-rc.2.
  - The model gets upstream's `working_directory` tool, which reads and changes the session's working directory, and each prompt tells it the current one.
  - Upstream's time context tells the model the current time in your browser's time zone, at most once every 10 minutes. When no browser is involved (a delivered reminder, the HTTP turn API), it says the time zone is unknown.
  - Every subagent can be continued; the `subagent` tool no longer takes `run_in_background` and gains `cwd`.
  - The Web app masks key-shaped text such as `sk-…` in messages (#326). Masking is display only: the stored message and the request the model receives keep the original text.
  - The DeepSeek V4.1 Flash model shows upstream's `1017` label.
- **Automation tasks page** (#329): upstream's page in the sidebar lists every reminder with its session and status, edits a reminder's name, instruction, and timing, deletes it, and shows each delivery it made. The list refreshes by itself when a reminder is created, changed, deleted, or delivered.
  - Each reminder keeps its newest 200 deliveries within 30 days, as upstream does, and they are deleted with the reminder. Reminders created before this release show their earlier deliveries as unavailable.
- **Session log download** (#318, #328): the session header's "Download session log" item and the `/export` command download upstream's session archive, with its subagent sessions. The Edge reads the log a page at a time while it compresses, so a long session no longer needs to fit in memory, and there is no size limit.
- **DeepSeek Search and Fetch APIs** (#327): the web search card can switch web search and fetch to DeepSeek's own APIs, using the DeepSeek key from the Models page. DeepSeek then fetches the page, so the Worker no longer reads third-party pages itself. The switch is off by default, because these APIs may be billed separately from model tokens.
- **Turn outline** (#312): the chat view's turn list, from upstream's turn outline.
- **`/feedback`** (#310): upstream's command and the session feedback dialog record feedback in the session.
- **Harness shell variables** (#311): bash commands see `DSH_SHELL=1`, `DSH_SESSION_ID`, and `DSH_HOME=/.dsh`. No Worker secret or binding reaches a command.

### Fixed

- **Cached session details on a cold list** (#315): the session list now shows cached details (stats, goal, todos, model) for sessions not loaded since a restart. Before, they appeared only after the session was opened.
- **Smaller stored session cache** (#316): the cached values that grow with a conversation are rebuilt from the session log instead of being stored. For a 600-turn session the stored cache drops from 90 KB to 2 KB, which also cuts what each Durable Object start loads.

### Known limitations

- Rolling back to 0.26 is not supported: 0.26 cannot read a session in which 0.27 recorded a working-directory change.
- A new instance lists no models until its DeepSeek key is set (upstream change).
- The DeepSeek Search and Fetch APIs were tested against a stand-in, not yet against `api.deepseek.com`.
- The Automation tasks page lets you edit a subagent session's reminder, which upstream refuses. The model's tools already refuse to create reminders for subagents, so none exist in practice.
- Upstream's session search tools (`dsh-tool-session-query`) are not offered yet.
- To keep credentials out of the settings, which are stored in plain text, a provider's API key name may not belong to DeepSeek or another Edge feature (`DEEPSEEK_*`, `MCP_TOKEN_*`, `DSH_EDGE_*`); a Base URL may not contain credentials, a query, or a fragment; and extra headers are limited to an allowlist, so a gateway that needs a second credential header cannot be configured yet.
- Providers that sign in through a local login or read local credential files are not offered.
- Session titles are still generated with DeepSeek.
- `glob` and `grep` do not apply `.gitignore` files.
- Rolling back to 0.18 after an upgrade from it is not supported.
- The Agent presets page intro and mode guide mention upstream's Creator mode, which the Edge does not offer.
- The 0.18.0 limitations about the Node 22 test environment, local `dev:container` cleanup, and symlinks outside `/workspace` still hold.

### Validation and upgrade

`pnpm run check` passes 979 tests, with new unit tests for the session log exporter (its archive matches upstream's entry for entry, and a log rewritten during an export fails instead of mixing turns), the reminder delivery records and their limits, the Automation tasks service, the DeepSeek Search and Fetch providers, and the turn outline's size.

Integration runs against both release artifacts (Direct and Isolated), with new checks for a 4.4 MiB session log download, the Automation tasks service over the gateway after a real reminder, `/feedback`, the shell variables, and cached details on a cold list. Browser snapshots in real Chromium cover the Automation tasks page after a delivered reminder and the masking of a key-shaped message.

Measured locally in the Workers runtime:
- `upgrade-from-release.probe.mjs` upgrades state created by the published 0.26.1 and 0.18.0, passing 11 checks each.
- `row-cost.probe.mjs` against 0.26.1: plain turns write the same rows (443 SQL rows and 36 KV and alarm writes over nine turns); the first turn writes 2 more rows, for the time context. Each delivered reminder writes 1 more row, for its delivery record.
- Downloading a 408-event session log reads about 1.06 rows per event and writes none.

The release artifacts stay within Cloudflare's 64 MiB size limit (Direct 8.1 MB, Isolated 9.5 MB), and their startup takes about 95 to 120 ms locally, against Cloudflare's 1 s limit.

On a staging instance upgraded from 0.26.1 to 0.27.0-alpha.1 (Isolated, with the Linux container):
- the 36 existing sessions stayed listed, and each downloaded as a session log archive;
- a reminder from 0.19 showed on the Automation tasks page as inactive, with its earlier deliveries unavailable;
- a reminder created by the model was delivered after one minute and answered in its session. While it was pending, the session showed it in the sidebar; when it was delivered, the page marked it inactive without a reload and listed the delivery under Records;
- bash commands saw the `DSH_*` variables, `working_directory` reported `/workspace`, the reminder time used the browser's time zone, `/feedback` recorded feedback, the turn outline showed each turn, a key-shaped string in a sent message was masked, and the model menu showed the `1017` label;
- Cloudflare's analytics for the instance's Durable Object showed only successful alarm runs, no CPU, memory, or internal errors, and fewer rows read per idle hour than on 0.26.

Upgrade with `npx dsh-edge@latest upgrade` and choose "Update it", then reload the page. The Web page updates at once, but the instance behind it can keep running the previous version for a few minutes after an upgrade.
