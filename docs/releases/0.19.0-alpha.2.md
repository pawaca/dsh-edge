## dsh-edge 0.19.0-alpha.2

Adds a way to recover a lost owner access key. Published to npm's `next` channel; `latest` remains on 0.18.0. The upstream Harness baseline remains 0.2.0-rc.1. Everything in [0.19.0-alpha.1](0.19.0-alpha.1.md) still applies, including the one-way session format upgrade from 0.18.

### Added

- **Reset a lost access key** (#249): Cloudflare cannot show a Worker secret again, and until now an update kept the key with no way to replace it.
  - When the Worker already exists, the installer offers **Update and reset the access key**. It deploys the release with the same capabilities and a new owner key, either generated or taken from `DSH_EDGE_ACCESS_KEY`, and shows the key once.
  - Conversations, files, and the DeepSeek key are kept, because the installer replaces only the access key. The old key stops working, and every signed-in browser must sign in again.
  - With the new key, the installer signs in after deployment and checks that the instance is ready, as for a new install. An ordinary update still verifies only the public release.
  - The login page says how to recover a lost key, with the command for the deployment's own release channel: `npx dsh-edge@next upgrade` on a prerelease, `npx dsh-edge@latest upgrade` on a stable release.
  - `dsh-edge --help` and the README describe the reset.

### Known limitations

Everything listed for 0.19.0-alpha.1 still holds.

### Validation and upgrade

`pnpm run check` passes 844 tests. Integration runs against both release artifacts (Direct and Isolated). The packed installer passes `pack:verify`, including its `--help` text. New tests cover a reset with a generated key and with a supplied key: only the access key is sent as a secret, the capabilities are unchanged, and activation signs in with the new key. Other tests cover the menu, confirmation, and finish notes, and the login page's channel-aware command. The reset has not yet been run against a real Cloudflare account; that Wrangler keeps the other secrets comes from Wrangler 4.129's documented `--secrets-file` behavior.

Upgrade a test instance with `npx dsh-edge@next upgrade` and choose "Update it", or "Update and reset the access key" if you no longer have the key. Upgrading from 0.18 moves stored sessions to the new format, and rolling back is not supported.
