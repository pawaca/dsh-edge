## dsh-edge 0.18.0-alpha.1

First preview of the Linux container runtime, a capability-first installer, and runtime settings in the web UI. On Workers Paid, an instance can now add a Linux container for git, npm, node, and python3. Each bash command runs in the lightweight shell or the container, whichever it needs. Published to npm's `next` channel; `latest` remains on 0.17.0. Use this alpha on a test instance before upgrading a primary deployment. The upstream Harness baseline remains 0.1.5-rc.2.

### Added

- **Linux container** (#218, #219, #226): the new "+ Work on code projects" capability, which requires Workers Paid.
  - The container is attached to the instance's Durable Object and runs the `basic` instance type.
  - It ships git, node 22, npm, python3, jq, make, bzip2, xz, zstd, zip, and unzip.
  - Every release publishes the matching image, `docker.io/pawaca/dsh-edge-computer:<version>`.
  - Workspace files stay in the Durable Object and sync with the container, so stopping or replacing the container loses no files.
  - The container has internet access but receives no Edge credentials.
  - It sleeps after an idle window, and the next Linux command wakes it in about 5 seconds. The first command after a deployment can take a few minutes while the image rolls out.
  - At most 2 commands run in it at once, and later ones wait for a slot.
- **Per-command routing** (#221, #223, #224): with a container, each bash command starts where it belongs.
  - File and text work stays in the lightweight shell. Programs only Linux has, such as git, npm, and python3, go to the container.
  - A command the lightweight shell cannot run, either because a tool reports it is unsupported or because it reaches outside `/workspace` (for example `/etc/os-release`), reruns in the container transparently (`retriedFromLight`) when it changed no files. If it already changed files, it is reported as `lightShellMiss` so the agent decides whether to retry.
  - A rerun shares the command's timeout.
- **Runtime settings** (#227, #228): the DSH Edge settings page now shows what the instance can do, what it costs, and the command that changes it.
  - Container deployments add a Linux container card: live status, **Sleep now**, where commands run (Automatic, Always lightweight, or Always Linux), and the idle window before sleep (5, 10, or 30 minutes).
  - A change applies to the next command without a restart and is kept across restarts.
  - The API is `GET`/`PUT /api/runtime` and `POST /api/runtime/container/stop`.

### Changed

- **Installer** (#229): the installer asks about capabilities instead of plans, and pressing Enter at every prompt completes an install.
  - The order is account, Worker name, capability, then one confirmation.
  - The capability question offers "Research and write" (Free, the default), "+ Analyze data and split big jobs" (Workers Paid; `run_code` and `workflow`), and "+ Work on code projects" (Workers Paid plus container time).
  - A temporary account skips the capability question, and its Cloudflare terms are part of the single confirmation.
  - New installs store images in the Durable Object and never ask for R2. Existing R2 instances keep R2.
  - The owner access key is generated, or read from `DSH_EDGE_ACCESS_KEY`; no flag carries it. The DeepSeek key is added later in Settings → Models.
  - After deployment the installer offers to open the browser.
- **Same name means update** (#229): rerunning `install` with an existing Worker's name offers "Update it" by default.
  - An update keeps the instance's capabilities, conversations, files, access key, and DeepSeek key, and it never asks for them again.
  - "Update and change what it can do" marks the current capability. A downgrade names what is removed and defaults to No.
  - A same-named Worker that is not dsh-edge is never updated; the name counts as taken.
  - `upgrade` follows the same flow and fails if the Worker does not exist.
- **Update verification is public-only** (#229): an update cannot read back the owner key it keeps, so the installer confirms only that the public release reports the new version ("live"). A startup failure behind login shows when the owner next signs in.
- **Leaving Container mode keeps the Container application** (#229): it is the rollback target. The installer prints the command that removes it; run it after signing in to the new version to stop Container billing.
- **`@cloudflare/computer` 0.3.1** (#217), paired with the container image's computerd.

### Known limitations

- The installer and the container runtime have been tested locally (including a local Docker container) but not yet against a real account for this version. This alpha is that test.
- `pnpm run check` fails two async-context tests on Node 22; Node 24 passes. They are test-environment only: the code under test runs in workerd, and CI uses Node 24. This dates from 0.17.0.
- Stopping `pnpm --filter dsh-edge dev:container` can leave its local Docker containers running; remove them with `docker ps` and `docker rm -f`.
- Symlinks that point outside `/workspace` are out of scope for routing.

### Validation and upgrade

`pnpm run check` passes 756 tests. Integration runs against both release artifacts (Direct and Isolated). The Container integration runs the promoted artifact against a local Docker container. It covers routing, reruns, and a differential corpus that compares automatic routing with a forced Linux run. It also covers the runtime settings, sleep now, and settings kept across a restart. The Container integration also runs daily in CI. The packed installer is installed outside the workspace; it starts the Direct and Isolated Workers and checks that the Container configuration deploys the published image.

Upgrade a test instance with `npx dsh-edge@next upgrade` and choose "Update it" to keep everything. To add the container, choose "Update and change what it can do", then "+ Work on code projects". This release adds no storage schema or migration.
