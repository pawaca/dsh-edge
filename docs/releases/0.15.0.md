## dsh-edge 0.15.0

Promotes the runtime from 0.15.0-alpha.2 to the stable npm `latest` channel. There are no runtime changes from alpha.2. The upstream Harness baseline is 0.1.5-rc.2.

### Changed since 0.14.1

- **Harness integration** (#173): adopt the upstream `SessionHandle` persistence contract and V3 session format, which stores compact assistant streams inside canonical message events.
- **File previews** (#177): support the right-sidebar file preview through the Edge VFS, with bounded reads and metadata subscriptions. Owner-authenticated downloads remain available.

### Fixed

- **Session delivery and recovery** (#177): persist initialization events before model selection so prompts reach cold sessions; repair safe interrupted physical tails and atomically rebuild reminder state and summaries. Unsafe tails are refused to avoid losing prompts or duplicating delivery.
- **Legacy upgrades** (#179): normalize known historical cancellation records before V0 migration, validate all outdated logs before migration writes, and commit events, session headers and summaries atomically.
- **Migration write volume** (#179): choose per-session replacement or a compact event-table rebuild based on estimated row cost, with bounded event reads and no per-session strategy query. A local workerd fixture measured 1,934 writes versus 155,493 before optimization, with identical resulting event content; this is not a guarantee for every database or total account usage.
- **Installation verification** (#179): require initialized session services and the DeepSeek adapter, and verify the exact uploaded Cloudflare Worker version before reporting success. Retry transient deployment authentication failures and validate owner keys by UTF-8 byte length.
- **Recovery access and cancellation** (#179): keep session and recovery routes available if model-adapter initialization fails; readiness reports the failure. Browser coverage verifies that stopping a reply restores the send control without displaying `[object Object]`.

### Validation and upgrade

Alpha.2 passed Linux and Windows CI, both Worker-mode integration tests, six browser tests, and installation checks outside the workspace. This stable release retains that runtime and changes only release identity and notes.

Upgrade with `npx dsh-edge@latest upgrade`. Existing alpha deployments should explicitly use `@latest` to switch to the stable channel. Check remaining Durable Objects quota before a large migration: rollback and database restoration do not refund consumed quota.
