## dsh-edge 0.15.0-alpha.2

修复 alpha.1 的旧会话升级问题，并降低迁移写入量。上游 Harness 基线保持 0.1.5-rc.2。发布至 npm 的 `next` 通道；`latest` 保持 0.14.1。

### 修复

- **旧会话兼容性**（#179）：在上游 V0 迁移前规范化已知的历史取消记录，使已有会话和工作区能够在升级后初始化。写入迁移结果前先验证全部旧版本会话日志，再原子提交事件数据、会话头和摘要。
- **迁移写入量**（#179）：根据预估行成本，选择逐会话替换或重建紧凑事件表。策略查询限制事件读取量，避免每个会话执行一次 SQL 查询。大型历史数据仍需足够的账户配额；事务回滚和数据库还原不会退回已消耗的配额。
- **安装结果验证**（#179）：等待会话服务和 DeepSeek 适配器完成初始化，并核对本次上传的 Cloudflare Worker 版本后才报告成功。部署传播期间重试临时认证失败，并按 UTF-8 字节数验证所有者密钥长度。
- **恢复访问**（#179）：模型适配器初始化失败时，普通会话和恢复路由仍可访问，同时就绪端点报告该失败。

### 验证

- 本地单元检查通过 432 项测试，保留两项既有跳过。两种 Worker 模式均通过集成和打包检查；全部六项浏览器测试通过，针对取消操作的覆盖还确认停止回复不会显示 `[object Object]`。
- 本地 workerd 迁移基准在同一旧历史数据样本上，将实测写入量从 155,493 降至 1,934，迁移后的事件内容一致。这是样本测量结果，不代表任意数据库的保证值，也不代表账户总计费使用量。
- 已合并修复的 Linux 和 Windows CI 均通过。

本版本仍为 alpha。升级主要部署前，请先在测试实例评估，并在大型迁移前检查账户剩余的 Durable Objects 配额。
