## dsh-edge 0.17.0

将 Dynamic Worker 工具从 0.17.0-alpha.1 提升至 npm `latest` 稳定频道。上游 Harness 基线保持 0.1.5-rc.2。

### 自 0.16.0 以来的变更

- **运行时 provider**（#209）：Direct Shell 与 Dynamic Worker 被建模为带有能力与套餐要求的运行时 provider，Worker 与安装器从同一份目录推导运行时信息。只有部分 provider 提供的能力，在对应 provider 不可用时直接缺席，而不是以损坏的状态出现。
- **`workflow` 工具**（#210，仅 Isolated）：即上游的编排工具。模型编写一个脚本，用 `agent()`、`parallel()`、`pipeline()`、`phase()`、`log()` 把工作分发给多个子 agent。每次运行都在独立的 Dynamic Worker 中执行，没有出站网络，并受 Worker Loader `cpuMs` 上限约束。Durable Object 负责执行各项上限：同时最多 4 个子 agent，单次运行最多 100 个；请求、回复、进度和结果的大小也都有上限。取消当前轮次时，会销毁隔离环境并取消所有子 agent。
- **`run_code` 工具**（#211，仅 Isolated）：即上游 `dsh-tools` 的 PTC 模式，以 `both` 方式启用，与原生工具并存。模型编写 TypeScript 程序，用 `await tools.name(args)` 调用工具。程序先用 sucrase 去除类型，再在独立的 Dynamic Worker 中运行。嵌套调用就是普通的工具派发，审批和 spill 照常生效。单次运行的上限：嵌套调用最多 200 次，每次调用的参数最多 256 KiB，单次结果最多 2 MiB，总输出最多 1 MiB。每轮 prompt 都会附带一段生成的工具 SDK 说明。
- **隔离环境回调的轮次上下文**（#212）：workflow 或代码隔离环境回调 Durable Object 时，会在发起它的那次工具调用的上下文中执行，因此 `run_code` 和 workflow 子 agent 中的文件工具可以正常使用。
- **安装器**：Isolated 运行时选项的提示中注明它额外提供 `workflow` 与 `run_code`。

### 验证与升级

Alpha.1 通过了 534 项测试和两种发布产物上的集成测试，并在本地用真实模型和 Web UI 做了测试。测试覆盖：3 个和 6 个子 agent 的 workflow（包括结构化输出和中途取消）；`run_code` 调用 bash、文件工具和 `web_fetch`，以及审批流程；历史回放。测试中，一次 6 个子 agent 的 workflow 以批量写入的方式写了约 135 行 session 事件。稳定版保持该运行时不变。

使用 `npx dsh-edge@latest upgrade` 升级。已有的 alpha 部署应使用 `@latest` 切换到稳定频道。新工具只出现在 Isolated 部署中，Direct 部署不受影响。本版没有新增存储结构或迁移。
