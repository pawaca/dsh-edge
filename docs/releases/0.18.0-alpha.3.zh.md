## dsh-edge 0.18.0-alpha.3

手动测试 0.18.0-alpha.2 后的跟进：默认预设改为上游的**标准模式**。本版发布至 npm 的 `next` 频道，`latest` 仍为 0.17.0。上游 Harness 基线保持 0.1.5-rc.2。[0.18.0-alpha.2](0.18.0-alpha.2.zh.md) 和 [0.18.0-alpha.1](0.18.0-alpha.1.zh.md) 的内容仍然适用。

### 变更

- **标准模式**（#238）：alpha.2 的新建会话预设选择器在 **PTC 模式**旁边列出了 **DSH Edge**（"DeepSeek Harness running in a Cloudflare Durable Object"）。这一项写的是产品名和部署细节，而且只有 PTC 那一项有中文。
  - 默认预设现在使用上游的 `standard` id。Web 客户端直接显示上游自带的中英文名称“Standard mode” / “标准模式”，和 PTC 模式的做法一致。
  - 以前记录为 `dsh-edge` 的会话，在预设选择器、会话列表和打开的会话里都显示为标准模式。已存储的数据不做任何改动。
  - 不提供上游的极简模式和创造模式。极简模式相比标准模式增加的东西很少；创造模式依赖运行时插件，Workers 无法承载。

### 已知限制

- 上游标准模式的说明提到了 workflow，而免费（Direct）部署没有 workflow。这类部署只提供这一个预设。
- 0.18.0-alpha.2 列出的限制仍然存在。

### 验证与升级

`pnpm run check` 通过 776 个测试。集成测试针对两种发布产物运行：离线把一个会话头改回旧的 `dsh-edge` id，重启 Worker 后，检查会话列表和打开的会话都报告 `standard`。浏览器快照中预设查看器的标题为“View · Standard mode”。

用 `npx dsh-edge@next upgrade` 升级测试实例，选择"Update it"。本版没有存储迁移。
