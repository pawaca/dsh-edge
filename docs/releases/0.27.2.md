## dsh-edge 0.27.2

Adds the Web app's way to download a session log, missing from 0.27.0. Published to the stable npm `latest` channel. The upstream Harness baseline stays 0.2.1-rc.2 and the session format stays V4, so upgrading from 0.27.0 or 0.26 migrates no stored data.

There is no published 0.27.1: its tag was cut with the same fix, but its release checks failed on the Windows runner before npm publication, and a release that fails there ships as a new version.

### Fixed

- **Session log download in the Web app** (#332): 0.27.0 served session log downloads, but its Web app left out the part of upstream's `dsh-session-log-export` that runs in the browser. The session header had no More actions button with "Download session log", and `/export` started no download, so the download was reachable only through `/api/session.export`. Both now download the session's ZIP.

### Release checks

- **Windows test runs** (#334): the release's Windows checks failed three times on waits that ran out while the runner was slow, in a different test each time; the same code passed elsewhere. The snapshot tests now allow for a slow runner, a failed snapshot runs once more on CI, and a failed browser test keeps each page's screenshot and console for diagnosis. No product code changed.

### Validation and upgrade

`pnpm run check` passes 979 tests. A browser test in real Chromium, run against both release artifacts (Direct and Isolated), downloads a session's log from the header menu and with `/export` and reads the session's prompt out of each ZIP. `upgrade-from-release.probe.mjs` upgrades state created by the published 0.27.0, passing 11 checks.

Upgrade with `npx dsh-edge@latest upgrade` and choose "Update it", then reload the page. The Web page updates at once, but the instance behind it can keep running the previous version for a few minutes after an upgrade.
