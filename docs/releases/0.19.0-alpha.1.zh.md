## dsh-edge 0.19.0-alpha.1

首个基于上游 Harness **0.2.0-rc.1** 基线的预览版（原基线为 0.1.5-rc.2）。上游 0.2.0 改了会话格式、DeepSeek 连接方式、设置系统、定时提醒，以及大部分网页客户端；本版把 Edge 全部适配过来，并保留已有实例的数据。本版发布至 npm 的 `next` 频道，`latest` 仍为 0.18.0。**升级会把已存的会话迁移到新格式，之后不支持退回 0.18**，请先在测试实例上试用。

### 从 0.18 升级

- **会话在首次启动时迁移到 v4 格式**（#244）。启动时通过上游的格式目录迁移所有已存会话，在一个事务内完成，只改写新格式有变化的行。按上游要求，子代理的父会话迁移时会带上子会话的目录信息。
  - 在已发布 0.18.0 的升级测试数据上（10 个会话、609 行事件）：写入 55 行，读取约 2,900 行，耗时 38–40 ms。再次启动不再写入。
  - 0.18 读不了 v4 会话。安装器现在会给每个部署的 Worker 版本打标签；更新一个当前版本早于 0.19 的 Worker 时，会提示会话将迁移到新格式、不支持回退。
- **定时提醒会保留**（#244）。0.18 中仍有效的提醒会一次性导入新的任务表，标题取提醒内容的第一行，并按原定时间触发。上游自身不迁移这些提醒。
- **设置、技能、MCP 服务器、文件和图片附件**存储不变。0.18 上在 Models 页面做的修改继续生效。
- **连接地址**（#246）：DeepSeek 连接现在只走 Anthropic 兼容的 Messages API，DeepSeek 的 OpenAI 兼容根地址对它返回 404。
  - `https://api.deepseek.com`、`/v1`、`/beta` 会映射到 `https://api.deepseek.com/anthropic`，`DEEPSEEK_BASE_URL` 和 Models 页面保存的 Base URL 都适用（后者在启动时改写一次）。
  - 其他地址（例如网关）保持不变。如果它返回 404，这一轮会失败，并提示当前地址、需要的 Messages 根地址，以及在哪里修改。
- **模型**：新会话默认使用 DeepSeek-V4.1-Flash（`deepseek-flash`，支持图片）。模型列表为 V4.1 Flash 和 V4 Pro；上游去掉了 V4 Flash 和视觉预览版。已有会话继续使用原来的模型，这些模型 id 目前 API 仍然接受。

### 变更

- **设置**（#244）：上游新的配置表单由 Edge 自己的 Durable Object 设置服务提供，包括网页客户端的主题、语言、对话视图、忙碌时发送行为、预览提示和开发者工具。设置页不再提供"打开本地配置文件"。
- **定时提醒**（#244）：上游的提醒工具新增标题，每天、每周和 cron 计划，`schedule_update`，以及删除已失效的提醒。Edge 用 Durable Object SQLite 提供这些功能，送达仍走会话队列，所以提醒和你的消息共用准入、顺序和取消。
- **网页客户端**（#244）：跟随上游 0.2.0，包括会话置顶和后台任务面板。Edge 没有提供服务端的客户端功能不包含在内：产品统计、PTY 终端、DeepSeek 账号登录、插件管理器及其设置页、权限预设选择器、会话日志上传偏好。
- **随上游生效的行为**（#244）：
  - 已归档的会话恢复之前不能运行。
  - 排队消息只能编辑文字。
  - Edge 在准入前暂存的排队消息，只在发送它的标签页显示；其他标签页在准入后看到。
  - 对话中的链接仍默认在浏览器新标签页打开；改一个设置就能用上游的内置浏览器。
- **计划审阅和提问**（#244）：`ask_user_question` 和 `exit_plan_mode` 等待所有者时不受 60 秒短工具时限约束。在 0.18 上，计划审阅放一分钟不处理就会失败。
- **`run_code`**（#244）：背后的运行时改为上游的 PTC 运行时。Edge 不提供新增的单次 `timeoutMs`，每次运行仍使用部署的上限。

### 修复

- **Isolated 模式下 shell 命令运行中点停止**（#245）：以前这一轮要等整条命令跑完，然后报 `Error: [object Object]`。现在点停止后 2 秒内结束这一轮，工具调用显示为已中止。不退出的命令会标为 `detached`，可能仍在后台跑完，和 0.18 一样。
- **macOS 上的安装器**（#247）：负载高时停止 Wrangler 可能报 `kill EPERM` 失败。

### 已知限制

- 升级后不支持退回 0.18（见上文）。
- 0.18 的插件配置卡片（Agent loop、Web search）移到了上游插件管理器中，Edge 没有提供插件管理器。已记为 P2 缺口。
- Agent 预设页的介绍和模式说明提到了上游的 Creator 模式，Edge 不提供该模式。
- 尚未接入的上游包（P1）：模型请求重试、文件先读后写保护、重复工具调用提醒、会话检查点。上游对等检查列出了所有缺口。
- wiki 还没有覆盖上游 0.2.0 的 25 个子系统。预发布版只报告此项；正式版需要补齐。

### 验证与升级

`pnpm run check` 通过 841 个测试。集成测试覆盖两个发布产物（Direct 和 Isolated），包括 0.1.3 样本数据的升级路径。打包后的安装器通过 `pack:verify`。定时提醒和运行队列探针在 Direct 和 Isolated 下均通过。

`upgrade-from-release.probe.mjs` 先启动已发布的 0.18.0，创建长会话、工具会话、子代理会话、PTC 会话、图片会话、分叉会话、已归档会话，以及提醒、文件、设置、MCP 服务器和技能，再用本版在同一份数据上启动；全部 11 项检查通过。同样的升级也用真实 DeepSeek key 手动跑过一遍：10 个会话（含一个子代理子会话）的 id、标题、预设和对话记录都保留；旧会话能带着上下文继续对话，工具、PTC 和图片输入正常；提醒能列出并带有自动生成的标题；在 0.18 上设的一次性提醒升级后按时触发。

用 `npx dsh-edge@next upgrade` 升级测试实例，选择"Update it"。
