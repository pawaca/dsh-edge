## dsh-edge 0.26.1

按源码复审 Edge 与上游对照判断时发现的两个问题的修复。本版发布至稳定的 npm `latest` 频道。上游 Harness 基线仍为 0.2.0-rc.2，会话格式仍为 V4，所以从 0.26.0 或 0.24 升级不会迁移任何已存数据。从 0.18 升级仍会按 [0.19.0](0.19.0.zh.md) 所述把会话迁移到 V4。

没有 0.25 版本：版本号按发布顺序递增，这个编号当初被误留给升级到上游 0.2.1 基线。0.26.0 的发布说明已同步更正。

### 修复

- **失败的命令显示为成功**（#306）：在带 Linux 容器的部署中，在容器里失败的命令，会在聊天的终端卡片上显示为成功。轻量 shell 跑不完而失败的命令，以及已取消但还没停下的命令，也会这样显示。原因是 Edge 把"命令在哪里运行"的说明写在了退出码后面，而 Web 客户端只从最后一行读退出码。现在退出码放在最后，与上游一致。
- **过时的 agent 指引**（#307）：Edge 给模型的指引没有跟上 0.24 和 0.26 的变化。
  - 现在与上游预设一样写明会话所用的模型，其他服务商的模型也能知道自己是哪个模型。切换会话模型后，从下一步起指引随之更新。
  - 不再让模型用 job 工具跟踪子 agent；从 0.24 起子 agent 由 `list_agents`、`send_message` 和 `interrupt_agent` 管理。
  - 子 agent 现在会收到上游的说明：它是被委派的，需要审批的操作会被自动拒绝，所以它会说明限制而不是反复重试。子 agent 也会收到当前日期，每个会话都会收到上游对其审批策略的说明。

### 已知限制

- 设置以明文存储，为了不让凭据进入设置：
  - 每个服务商必须指定自己的 API key 名，且不能使用属于 DeepSeek 或其他 Edge 功能的名字（`DEEPSEEK_*`、`MCP_TOKEN_*`、`DSH_EDGE_*`）；
  - Base URL 不能包含账号密码、查询参数或片段；
  - 附加请求头只能是 `HTTP-Referer`、`Referer`、`X-Title`、`OpenAI-Organization`、`OpenAI-Project` 和 `anthropic-beta`，所以需要第二个认证头的网关（例如开启认证的 Cloudflare AI Gateway 所需的 `cf-aig-authorization`）暂时无法配置。
- 不提供通过本地登录或读取本地凭据文件认证的服务商：GitHub Copilot、OpenAI Codex，以及通过本地凭据使用的 Amazon Bedrock 或 Google Vertex。
- 会话标题仍由 DeepSeek 生成。
- 从子 agent 面板发给子 agent 的图片尚未在 Edge 上验证。
- 最多同时保持加载 8 个子 agent（上游默认值，可在子 agent 卡片中修改）。超出 Workers 六个并发连接上限的模型请求会等待空闲连接。
- 不提供上游的 turn 大纲（每个 turn 的提问与回答预览）：它随每个 turn 增长，而 Edge 把一个会话的缓存值存为一条记录，长会话会超出上限。
- 不提供上游的 `/feedback` 命令：它把匿名用户 id 保存在本地文件中，Workers 无法保存。
- `glob` 和 `grep` 不应用 `.gitignore` 文件，所以 `grep` 会搜索 ripgrep 会跳过的被忽略文件。
- 文件写入保护只覆盖 `write` 和 `edit` 工具。在受保护的写入进行期间由 shell 或容器命令写入的文件不会被发现，与上游一致；在受保护的写入之前已经完成的则会被发现。
- 从 0.18 升级后不支持退回 0.18。
- Agent 预设页的介绍和模式说明提到了上游的 Creator 模式，Edge 不提供该模式。
- 0.18.0 中关于 Node 22 测试环境、本地 `dev:container` 清理以及指向 `/workspace` 之外的符号链接的限制仍然存在。


### 验证与升级

`pnpm run check` 通过 912 个测试，其中一个单元测试按 Web 客户端的方式解析 bash 结果。集成测试针对两个发布产物（Direct 和 Isolated）运行，并新增检查：后台子 agent 的首个请求带有委派说明、审批说明和日期，父 agent 和子 agent 的指引都写明了模型。打包后的安装器通过 `pack:verify`。`upgrade-from-release.probe.mjs` 分别升级由已发布的 0.26.0、0.24.0 和 0.18.0 创建的状态，各通过 11 项检查。

用 `npx dsh-edge@latest upgrade` 升级，选择"Update it"，然后刷新页面。Web 页面会立即更新，但升级后背后的实例可能还会运行旧版本几分钟，所以实例里的修复可能要稍后才生效。
