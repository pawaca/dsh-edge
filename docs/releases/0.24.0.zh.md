## dsh-edge 0.24.0

子 agent 现在与上游 DeepSeek Harness 标准组合中的行为一致：在后台运行，可以续接、发消息、中断、列出、分叉，并能运行在父 agent 选择的模型上。本版发布至稳定的 npm `latest` 频道，变更与 [0.24.0-alpha.1](0.24.0-alpha.1.zh.md) 相同。上游 Harness 基线仍为 0.2.0-rc.2，会话格式仍为 V4，所以从 0.23 升级不会迁移任何已存数据。从 0.18 升级仍会按 [0.19.0](0.19.0.zh.md) 所述把会话迁移到 V4。子 agent 模型选择新增一种会话事件类型 `subagent/model-selection-policy`，只在该设置开启时写入。

### 变更

- **后台子 agent 可续接**（#295）：`subagent` 现在启动一个可续接的子 agent，并默认在后台运行。
  - 调用立即返回子 agent 的 id，而不是等待结果。子 agent 完成后，它的结束消息会唤醒父 agent 再跑一个 turn。
  - 父 agent 之后可以继续同一个子 agent，而不必新开一个。未在运行的子 agent 收到消息时会从存储恢复，重启后也一样。
  - 模型仍可传入 `run_in_background: false` 等待结果。
  - 以前，后台子 agent 是一次性 job，用 `job_output` 读取结果。
- 与上游一致，停止父 agent 不会停止仍在运行的子 agent。请使用 `interrupt_agent`，或 Web 客户端的子 agent 面板。

### 新增

- **子 agent 控制工具**（#295）：`send_message` 继续一个子 agent（或回复它的父 agent），`interrupt_agent` 停止子 agent 当前的 turn 并保留该子 agent，`list_agents` 列出会话启动的子 agent 及其状态。
- **分叉子 agent**（#295）：`subagent_fork` 启动一个从父 agent 已完成的 turn 开始的子 agent，所以它了解此前的对话。它使用父 agent 的模型。
- **子 agent 面板消息**（#295）：从 Web 客户端子 agent 面板发给子 agent 的消息现在可以运行，父会话未加载时也一样。
  - Edge 会先加载父 agent，为恢复的子 agent 提供父 agent 的 shell，并在它在 turn 中会使用的工作区和工作目录里运行。
  - 以前，这类消息会报错"File operations are only available during an active turn"。
- **子 agent 模型选择**（#296）："设置 → 内置插件 → 设置 → 子 agent"现在显示上游的**模型选择**部分。与上游一样默认关闭。
  - 开启后，每个新会话会记录其子 agent 可用的模型。父 agent 可以用 `list_subagent_models` 列出它们，并让 `subagent` 使用其中某个模型运行，可以与自己的模型不同。
  - 开启但未选任何模型时，保存会被拒绝。
  - 已经运行过 turn 的会话保持原有设置，因为上游只对新会话应用该设置。
  - `subagent_fork` 的子 agent 沿用父 agent 的模型。

### 已知限制

- 从子 agent 面板发给子 agent 的图片尚未在 Edge 上验证。
- 最多同时保持加载 8 个子 agent（上游默认值，可在子 agent 卡片中修改）。超出 Workers 六个并发连接上限的模型请求会等待空闲连接。
- 不提供上游的 turn 大纲（每个 turn 的提问与回答预览）：它随每个 turn 增长，而 Edge 把一个会话的缓存值存为一条记录，长会话会超出上限。
- 不提供上游的 `/feedback` 命令：它把匿名用户 id 保存在本地文件中，Workers 无法保存。
- `glob` 和 `grep` 不应用 `.gitignore` 文件，所以 `grep` 会搜索 ripgrep 会跳过的被忽略文件。
- 文件写入保护只覆盖 `write` 和 `edit` 工具。在受保护的写入进行期间由 shell 或容器命令写入的文件不会被发现，与上游一致；在受保护的写入之前已经完成的则会被发现。
- 从 0.18 升级后不支持退回 0.18。
- Agent 预设页的介绍和模式说明提到了上游的 Creator 模式，Edge 不提供该模式。
- 0.18.0 中关于 Node 22 测试环境、本地 `dev:container` 清理以及指向 `/workspace` 之外的符号链接的限制仍然存在。

### 验证与升级

`pnpm run check` 通过 902 个测试。集成测试覆盖两个发布产物（Direct 和 Isolated），新增的检查包括：
- 后台子 agent 在父 agent 的 turn 返回后写入文件，父 agent 被唤醒的 turn 也写入文件；
- `list_agents`；
- 重启后，`subagent_fork` 以重新加载的父 agent 的历史为种子，`send_message` 恢复子 agent；
- 重启后，向未加载的父 agent 的子 agent 发送面板消息，在父 agent 的项目目录中以相对路径写入，并运行一条 `bash` 命令；
- 停止父 agent 不影响正在运行的子 agent，`interrupt_agent` 结束其 turn；
- 模型选择：
  - 默认关闭；
  - 开启但未选模型时被拒绝；
  - 新会话只记录一次允许的模型；
  - 子 agent 运行在与父 agent 不同的允许模型上；
  - 不在列表中的模型被拒绝；
  - 开启前已开始的会话保持原样；
  - 设置在重启后仍然有效。

浏览器快照固定了子 agent 卡片的模型选择部分。打包后的安装器通过 `pack:verify`。`upgrade-from-release.probe.mjs` 分别升级由已发布的 0.24.0-alpha.1、0.23.0 和 0.18.0 创建的数据，各通过 11 项检查。

在本地用存储和 alarm 计数器测量过：子 agent 自身不安排 alarm。turn 会设置 alarm，并在结束时清除；子 agent 流程结束后没有遗留待触发的 alarm。已加载但空闲的子 agent 在后台不读也不写。存储写入量随实际运行的 turn（子 agent 的 turn 和父 agent 被唤醒的 turn）增长，没有放大。

在升级到 0.24.0-alpha.1 的 staging 实例上，使用真实的 DeepSeek 模型：
- 后台子 agent 写出了文件，它的结束唤醒父 agent 又跑了一个 turn；
- `list_agents` 列出了它，`send_message` 续接同一个子 agent 写出了第二个文件；
- `subagent_fork` 的子 agent 复述了父 agent 的第一条消息；
- 子 agent 运行 `sleep 90` 时，`interrupt_agent` 结束了它的 turn，命令没有跑完；
- 开启模型选择且只允许 `deepseek-flash` 时，使用 `deepseek-v4-pro` 的父 agent 调用了 `list_subagent_models`，并让子 agent 运行在 `deepseek-flash` 上；开启但未选模型时被拒绝。

用 `npx dsh-edge@latest upgrade` 升级，选择"Update it"。
