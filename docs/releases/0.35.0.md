## dsh-edge 0.35.0

Stable Edge release for the DeepSeek Harness 0.2.2-rc.1 baseline upgrade, from Edge 0.34.0 / Harness 0.2.1-rc.4. It promotes the runtime validated in 0.35.0-alpha.1; the exactly pinned upstream baseline remains a prerelease.

### Changed

- Pin the published Harness dependency closure to 0.2.2-rc.1, refresh upstream parity, and assemble the new browser plugins and declared assets.
- Adapt the Host Schedule API, including RRULE, revisions, pause/resume, manual run and delivery history, while keeping the original Session target, SQL task storage and DO alarms. Automatic new-Session targets remain unavailable. Create tasks through the conversation; the unsupported manual creation form is disabled. Editing a paused task does not resume it.
- Add bounded Copy as Markdown: 2,048 events and 4 MiB input/output budgets. Oversized copies return HTTP 413 and direct users to streaming Download session logs. One copy per DO remains admitted through body completion; excess requests return 429 with Retry-After, and stalled bodies expire after 30 seconds.
- Retain Trajectory with bounded live raw JSON: 256 KiB per result, 1 MiB per Session and 4 MiB globally. Oversized, evicted or cold results are explicitly unavailable.
- Add filesystem patch/delete/move provider methods and deletion tracking. The apply_patch tool remains disabled, and the Edge keeps its read-before-write observation policy.
- Adapt model/preset services, native/PTC tool executors, staged image uploads and file streaming to the new public interfaces. List summaries now use upstream summary keys; complete projections, including statistics and todos, remain available through the dedicated Session API. Subagent model discovery can show the inherited route even when choosing a different child model is disabled.
- Correct startup profiling to inspect each promoted Worker artifact rather than allowing Wrangler to fall back to source configuration.
- Bound alarm batches and reuse recovery deadlines; paginate before resolving task execution state and use the existing due index to avoid repeated full task scans.
- Release request timeout timers when RPC, command admission, MCP and OAuth operations settle, allowing an otherwise idle Durable Object to hibernate. The idle/reconnect browser regression now runs by default.
- Refresh discovered model listings on stale access, retaining TTL and shared in-flight loads, without an idle background timer.

### Compatibility and limits

Existing Session and workspace state is preserved. This is not a promise of binary-only downgrade: new RRULE tasks and inherited delivery acknowledgments in ordinary forks may be unreadable by the old baseline. Preserve pre-upgrade state for recovery.

Web Fetch retains Workers fetch, per-hop URL validation and the existing strictly-public platform flag. URL checks alone do not pin DNS. Public fetching passed bounded staging acceptance; private-resolving DNS boundaries remain unverified. Account budget and a usable recovery process must be checked for each production deployment.

See the [baseline adaptation record](../upgrades/0.2.2-rc.1.md) for all package dispositions, limits, validation and remaining gates.

### Acceptance and known capacity limit

- Released-state upgrade from 0.34.0 passed all 11 local checks. Published alpha artifacts passed Direct, Dynamic and Container validation.
- In the local nine-turn comparison, SQL rows written were 441 versus 443 on 0.34.0; KV/alarm writes were 36 versus 36. Within the candidate, batching reduced 128 task executions from 128 to 4 alarm callbacks and from 385 to 9 setAlarm calls; that optimization comparison is not against 0.34.0.
- Bounded staging acceptance covered real-model conversations, files and attachments, Container commands, Markdown, Trajectory and task lifecycle, including native browser controls. Passive observation confirmed an alarm-triggered DO reconstruction with one delivery and a completed reply, approximately 0.77 seconds after the scheduled time.
- Long-history capacity remains a known risk: local combined-workload heap samples reached 170.1 MiB, while the old release reached 172.9 MiB in its comparison. GC timing prevents a precise relative-memory conclusion; neither result demonstrates safety below the Workers memory limit. Bounded staging samples peaked at approximately 83.7 MiB with no recorded CPU/memory-exceeded or fatal-internal errors, but they do not establish worst-case capacity. This release does not claim to resolve resident-history pressure or provide a validated safe history/session-count threshold.

The long-history capacity risk is tracked separately from the baseline promotion. New recovery tooling and production deployment are outside this release change.
