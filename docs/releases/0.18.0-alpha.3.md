## dsh-edge 0.18.0-alpha.3

A follow-up from testing 0.18.0-alpha.2 by hand: the default preset is now upstream's **Standard mode**. Published to npm's `next` channel; `latest` remains on 0.17.0. The upstream Harness baseline remains 0.1.5-rc.2. Everything in [0.18.0-alpha.2](0.18.0-alpha.2.md) and [0.18.0-alpha.1](0.18.0-alpha.1.md) still applies.

### Changed

- **Standard mode** (#238): in alpha.2, the new-session preset picker listed **DSH Edge** ("DeepSeek Harness running in a Cloudflare Durable Object") beside **PTC mode**. That row carried a product name and a deployment detail, and only the PTC row was translated.
  - The default preset now uses upstream's `standard` id. The Web client shows upstream's own copy for it, "Standard mode" / "标准模式", in both languages, as it already did for PTC mode.
  - Sessions recorded under the earlier `dsh-edge` id read as Standard mode everywhere: the picker, the session list, and the open session. No stored data changes.
  - Upstream's Minimal and Creator mode presets are not offered. Minimal adds little over Standard mode, and Creator mode relies on runtime plugins that Workers cannot host.

### Known limitations

- Upstream's Standard mode description mentions workflows, which Free (Direct) deployments do not have. Those deployments offer only this one preset.
- Everything listed for 0.18.0-alpha.2 still holds.

### Validation and upgrade

`pnpm run check` passes 776 tests. Integration runs against both release artifacts. It rewrites a session header to the old `dsh-edge` id offline, restarts the Worker, and checks that both the session list and the open session report `standard`. The browser snapshot shows the preset viewer titled "View · Standard mode".

Upgrade a test instance with `npx dsh-edge@next upgrade` and choose "Update it". This release adds no storage migration.
