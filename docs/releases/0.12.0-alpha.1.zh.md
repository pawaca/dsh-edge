## dsh-edge 0.12.0-alpha.1

定时提醒与有界运行时调度的 Alpha 预览版。发布到 npm 的 `next` 通道供测试，稳定版 `latest` 通道保持不变。上游基线仍为 0.1.2-rc.1。

### 新增

- **原会话中的定时提醒**（#151）：通过 Agent 调用上游 Schedule 工具创建、列出或删除提醒。支持延迟、带明确偏移或时区的绝对时间，以及最短 300 秒的重复间隔。即使所有浏览器 tab 都已关闭，Durable Object alarm 也会唤醒会话。提醒在运行中的任务后排队，不取消或 steer 当前任务，也不创建新 session 或独立 cron 执行槽。本版不包含日历 cron 表达式和外部通知。
- **持久化提醒投递**：提醒 dispatch 与入队一起提交。错过多个重复周期时只呈现最新一次。每个 owner 最多 128 条活跃提醒，每条 prompt 的 JSON 编码预算为 4 KiB。准备或准入失败后按会话退避 30 秒，重试时间跨重启保存，并允许健康会话继续执行。删除最后一条提醒会清理对应重试状态。

### 调整

- **共享单执行槽与有界短工具池**（#148）：多个浏览器输入进入持久主会话队列，每个 owner 最多保留 128 条未完成输入和 2 MiB 序列化输入数据。实际工具共享两个执行许可，最多等待 32 项，排队期限为 30 秒，合作式执行期限为 60 秒。alarm 恢复复用现有执行槽；本版不增加 subagent 或后台长时间工具。

### 修复

- **队列恢复**（#149）：短暂的模型失败不再暂停后续排队输入。驻留中断仍会暂停待处理输入，直到用户发送新消息明确恢复；不会自动重放结果未知的外部副作用。执行开始前的失败会记录并呈现。
- **休眠后的浏览器连接**（#150）：唤醒时恢复 Remote 流处理，避免 Durable Object 休眠后，从已打开的 tab 发消息却没有响应。
- **提醒失败隔离**（#151）：损坏的提醒会话不会阻塞健康的排队输入或其他会话的到期提醒。损坏尾部修复会原子重建提醒投影；投递状态不明确的提醒要求人工恢复，避免重复投递。

### 试用 Alpha

使用 `npx dsh-edge@0.12.0-alpha.1 upgrade` 升级已有安装，或使用 `npx dsh-edge@0.12.0-alpha.1 install` 新建安装。升级时选择相同名称的 Worker 和运行模式，以保留 Durable Object 数据。由于 Cloudflare secrets 只写不可读，升级会再次要求输入 owner access key。

建议测试：创建一分钟后的提醒并关闭所有 tab，再打开原会话查看回复；任务忙碌时从两个 tab 发送消息；在到期前列出并删除提醒。提醒要求模型呈现内容，不会把内容当作新的用户命令执行；不会发送邮件或推送。崩溃后已暂停的会话仍需用户明确恢复。
