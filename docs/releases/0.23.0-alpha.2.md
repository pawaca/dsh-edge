## dsh-edge 0.23.0-alpha.2

A fix found in the 0.23.0-alpha.1 staging acceptance: the `/` menu now lists a workspace skill written between turns. Published to npm's `next` channel; `latest` remains on 0.22.0. The upstream Harness baseline stays 0.2.0-rc.2 and the session format stays V4, so upgrading from 0.22 or 0.23.0-alpha.1 migrates no stored data. 0.23.0-alpha.1's additions (workspace skills, image offload, and the Subagent settings card) are unchanged; see its notes.

### Fixed

- **`/` menu after a skill change** (#292): the `/` menu's skill list came from the catalog cached at the last check, and the skill folders were rechecked only before a turn. A `SKILL.md` written between turns was therefore missing from the `/` menu of a session opened afterwards until a turn ran. The list now checks file sizes and modification times first, as a turn does, and rereads only folders that changed.
  - As in upstream, an open page keeps each session's `/` list from when the session opened until the page reloads. A session already open when a skill is written shows it after a reload.

### Known limitations

- The Subagent card shows only its Limits section: choosing which models subagents may use comes in a later release.
- Upstream's turn outline (each turn's prompt and response preview) is not offered: it grows with every turn, and the Edge stores a session's cached values as one record, so a long session would outgrow it.
- Upstream's `/feedback` command is not offered: it keeps an anonymous user id in a local file, which Workers cannot store.
- Subagents cannot yet be messaged, interrupted, or listed while they run (upstream's `send_message`, `interrupt_agent`, and `list_agents`).
- `glob` and `grep` do not apply `.gitignore` files, so `grep` searches ignored files that ripgrep would skip.
- File write protection covers the `write` and `edit` tools. A shell or container command that writes a file during a guarded write is not detected, as in upstream; one that finished before the guarded write is.
- Rolling back to 0.18 after an upgrade from it is not supported.
- The Agent presets page intro and mode guide mention upstream's Creator mode, which the Edge does not offer.
- The 0.18.0 limitations about the Node 22 test environment, local `dev:container` cleanup, and symlinks outside `/workspace` still hold.

### Validation and upgrade

0.23.0-alpha.1 was accepted on a staging instance: existing sessions kept, the Subagent card, a workspace skill loaded by the real model, per-project `/` lists, and image offload. That acceptance found the fix above.

`pnpm run check` passes 902 tests. Integration runs against both release artifacts (Direct and Isolated), with a new check that a skill written after a `/` listing appears in the next listing with no turn in between; without the fix that check fails. The packed installer passes `pack:verify`. `upgrade-from-release.probe.mjs` upgrades state created by the published 0.23.0-alpha.1, 0.22.0, and 0.18.0, passing 11 checks each.

Upgrade a test instance with `npx dsh-edge@next upgrade` and choose "Update it".
