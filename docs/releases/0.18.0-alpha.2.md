## dsh-edge 0.18.0-alpha.2

Fixes found while testing 0.18.0-alpha.1 by hand: container commands no longer fail on output that is not UTF-8, tools are native by default with `run_code` moved into an opt-in preset, and the system prompt now tells the model the current date, its working directory, and what its tier can do. Published to npm's `next` channel; `latest` remains on 0.17.0. The upstream Harness baseline remains 0.1.5-rc.2. Everything in [0.18.0-alpha.1](0.18.0-alpha.1.md) still applies.

### Fixed

- **Non-UTF-8 command output** (#233): container programs emit raw bytes. Before this fix, any of these failed the whole command with "shell output was not valid UTF-8":
  - a GBK web page;
  - a binary file;
  - `head -c` cutting a Chinese character in the middle of the output.

  Output is now decoded as a terminal would: invalid bytes become `�`, and the command reports its real result.
- **Container cleanup command** (#231): after leaving Container mode, the installer looks up the kept Container application's id and prints a runnable `npx wrangler containers delete <id>`.

### Changed

- **Native tools by default; PTC mode is opt-in** (#235): since 0.17.0, Paid deployments offered both the native tools and `run_code`. The model then wrapped most steps, even a single bash command, in a program. Every deployment now uses native tool calls by default, as upstream does.
  - On Paid deployments the new-session preset picker adds upstream's **PTC mode** (`ptc`, programmatic tool calling). Its sessions use only `run_code`, and their programs call the other tools, which suits batch work.
  - As upstream does, PTC mode does not offer `workflow`; the default preset keeps it.
  - The preset is chosen before the session's first turn and is locked afterwards.
  - Existing sessions keep the default preset and continue with native tools; their `run_code` history replays unchanged.
- **System prompt** (#236):
  - It states the working directory.
  - The Free tiers state what the lightweight shell covers and point the user to "Work on code projects" when a task needs git, node, python, or the network.
  - The bash guidance asks the model to check exit codes and states the timeout ceiling. The model exceeded the undisclosed ceiling twice in alpha.1 testing.
  - Container deployments are told to read web pages with `web_fetch` rather than `curl`.
  - Plan mode follows the upstream rules.
  - The generic "powered by DeepSeek Harness" opener is gone.
- **Current date** (#236): the model now knows today's date in the owner's time zone. The zone comes from the browser with each prompt and is stored once per instance, when it changes. The date arrives as a short context message only when it changes, at most once a day per session, so the cached prompt prefix is unaffected. Session search ignores these messages.
- **Installer copy** (#231): the installer says to add the DeepSeek key when the web app asks, and that the container's 10-minute idle window can be changed in Settings.

### Known limitations

- After an upgrade, a reminder that fires before the owner's first new prompt uses a UTC date. Near midnight it can be a day off, and the next prompt corrects it for good.
- Everything listed for 0.18.0-alpha.1 still holds: Node 22 test failures, leftover local `dev:container` containers, and symlinks out of routing scope.

### Validation and upgrade

`pnpm run check` passes 774 tests. Integration runs against both release artifacts. In the isolated run, a default session offers no `run_code`, and a PTC session offers only `run_code`, runs a program, and then locks its preset. The Container integration runs in CI, including real GBK and `head -c` output. The schedule probe confirms that a reminder after a Worker restart keeps the owner's time zone.

Upgrade a test instance with `npx dsh-edge@next upgrade` and choose "Update it". This release adds no storage migration. Two keys are new: a session's preset selection is recorded in its header, and the owner time zone in one Durable Object key.
