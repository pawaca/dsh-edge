## dsh-edge 0.26.0-alpha.2

修复在 staging 实例上测试 0.26.0-alpha.1 时发现的两个问题。发布到 npm 的 `next` 渠道；`latest` 仍为 0.24.0。上游 Harness 基线仍为 0.2.0-rc.2，会话格式仍为 V4，所以从 0.24 或 0.26.0-alpha.1 升级不会迁移任何已存数据。0.26.0-alpha.1 新增的内容（在 Models 页面添加其他模型服务商）没有变化，详见其说明。

### 修复

- **Web 客户端中的乱码**（#302）：部分文字显示为乱码，例如模型思考时的 `Deep diving for 14s Â·Â·Â·`，或 Agent presets 页面上的 `agentâ€™s`。页面的字符编码声明位置太靠后，浏览器找不到它，于是用错误的编码读取页面及其脚本，任何非英文文字（包括中文）都可能受影响。现在编码声明排在最前面。
- **设置默认 agent 预设**（#303）：在"设置 → Agent presets"中把某个预设设为新会话默认时，会报错 `settings namespace "agent-preset-registry" is not registered`。Edge 现在把这个选择保存在上游页面写入的位置。用早期版本选定的默认值会保留。

### 已知限制

- 设置以明文存储，为了不让凭据进入设置：
  - 每个服务商必须指定自己的 API key 名，且不能使用属于 DeepSeek 或其他 Edge 功能的名字（`DEEPSEEK_*`、`MCP_TOKEN_*`、`DSH_EDGE_*`）；
  - Base URL 不能包含账号密码、查询参数或片段；
  - 附加请求头只能是 `HTTP-Referer`、`Referer`、`X-Title`、`OpenAI-Organization`、`OpenAI-Project` 和 `anthropic-beta`，所以需要第二个认证头的网关（例如开启认证的 Cloudflare AI Gateway 所需的 `cf-aig-authorization`）暂时无法配置。
- 不提供通过本地登录或读取本地凭据文件认证的服务商：GitHub Copilot、OpenAI Codex，以及通过本地凭据使用的 Amazon Bedrock 或 Google Vertex。
- 会话标题仍由 DeepSeek 生成。
- 从子 agent 面板发给子 agent 的图片尚未在 Edge 上验证。
- 最多同时保持加载 8 个子 agent（上游默认值，可在子 agent 卡片中修改）。超出 Workers 六个并发连接上限的模型请求会等待空闲连接。
- 不提供上游的 turn 大纲（每个 turn 的提问与回答预览）：它随每个 turn 增长，而 Edge 把一个会话的缓存值存为一条记录，长会话会超出上限。
- 不提供上游的 `/feedback` 命令：它把匿名用户 id 保存在本地文件中，Workers 无法保存。
- `glob` 和 `grep` 不应用 `.gitignore` 文件，所以 `grep` 会搜索 ripgrep 会跳过的被忽略文件。
- 文件写入保护只覆盖 `write` 和 `edit` 工具。在受保护的写入进行期间由 shell 或容器命令写入的文件不会被发现，与上游一致；在受保护的写入之前已经完成的则会被发现。
- 从 0.18 升级后不支持退回 0.18。
- Agent 预设页的介绍和模式说明提到了上游的 Creator 模式，Edge 不提供该模式。
- 0.18.0 中关于 Node 22 测试环境、本地 `dev:container` 清理以及指向 `/workspace` 之外的符号链接的限制仍然存在。

### 验证与升级

`pnpm run check` 通过 912 个测试，新增的单元测试检查页面的编码声明排在最前面，以及早期版本保存的默认预设会被保留。独立构建检查现在会拒绝编码声明不在前 1024 字节内的页面；在本地实例的浏览器中，页面现在按 UTF-8 读取。集成测试覆盖两个发布产物（Direct 和 Isolated），现在按 Agent presets 页面的方式把 PTC 模式设为默认。打包后的安装器通过 `pack:verify`。`upgrade-from-release.probe.mjs` 分别升级由已发布的 0.26.0-alpha.1、0.24.0 和 0.18.0 创建的数据，各通过 11 项检查。

用 `npx dsh-edge@next upgrade` 升级测试实例，选择"Update it"，然后刷新页面。
