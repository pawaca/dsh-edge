## dsh-edge 0.18.0

Promotes the Linux container runtime, the capability-first installer, and runtime settings from the 0.18.0 prereleases to the stable npm `latest` channel. On Workers Paid, an instance can now add a Linux container for git, npm, node, and python3. Tools are native by default, and `run_code` moves into an opt-in PTC mode. The upstream Harness baseline remains 0.1.5-rc.2. The prerelease notes ([alpha.1](0.18.0-alpha.1.md), [alpha.2](0.18.0-alpha.2.md), [alpha.3](0.18.0-alpha.3.md), [alpha.4](0.18.0-alpha.4.md)) have the full details.

### Added since 0.17.0

- **Linux container** (#217, #218, #219, #226): the "+ Work on code projects" capability, which requires Workers Paid.
  - The container is attached to the instance's Durable Object and ships git, node 22, npm, python3, and common archive and build tools.
  - Every release publishes the matching image, `docker.io/pawaca/dsh-edge-computer:<version>`.
  - Workspace files stay in the Durable Object and sync with the container, so stopping or replacing the container loses no files.
  - The container has internet access but receives no Edge credentials.
  - It sleeps after an idle window and wakes in about 5 seconds.
- **Per-command routing** (#221, #223, #224): with a container, file and text work stays in the lightweight shell, and programs only Linux has run in the container. A command the lightweight shell cannot run reruns in the container when it changed no files.
- **Runtime settings** (#227, #228): the settings page shows what the instance can do, what it costs, and the command that changes it. Container deployments add live status, **Sleep now**, where commands run, and the idle window. A change applies to the next command without a restart.
- **Current date** (#236): the model knows today's date in the owner's time zone. The date arrives as a short context message only when it changes, so the cached prompt prefix is unaffected.

### Changed since 0.17.0

- **Native tools by default; PTC mode is opt-in** (#235, #238): 0.17.0 offered `run_code` beside the native tools on Isolated deployments, and the model then wrapped most steps in a program. Every deployment now uses native tool calls by default, as upstream does.
  - The default preset is upstream's **Standard mode**. On Paid deployments the new-session picker also offers upstream's **PTC mode**, whose sessions use only `run_code`. As upstream does, PTC mode does not offer `workflow`.
  - The preset is chosen before a session's first turn and locked afterwards. Sessions from 0.17.0 continue in Standard mode, and their `run_code` history replays unchanged. A session started in PTC mode on a 0.18.0 alpha stays in PTC mode.
- **Default preset and model for new sessions** (#240): as upstream, Settings → Agent presets chooses the preset new sessions start on, and the latest model chosen in any session is where new sessions start. `DEEPSEEK_MODEL` (default `deepseek-v4-flash`) applies until the owner first chooses a model.
- **Installer** (#229, #231): the installer asks about capabilities instead of plans, and pressing Enter at every prompt completes an install.
  - Rerunning `install` with an existing Worker's name offers "Update it" by default. An update keeps capabilities, conversations, files, the access key, and the DeepSeek key.
  - New installs store images in the Durable Object and never ask for R2. Existing R2 instances keep R2.
  - The DeepSeek key is added later in Settings → Models.
  - Leaving Container mode keeps the Container application as the rollback target, and the installer prints the command that removes it.
- **System prompt** (#236): it states the working directory and what the instance's tier can do. It tells the model to check exit codes and states the command timeout. Plan mode follows the upstream rules.

### Fixed since 0.17.0

- **Non-UTF-8 command output** (#233): a GBK page, a binary file, or `head -c` cutting a multibyte character no longer fails the whole command. Output is decoded as a terminal would.

### Known limitations

- After an upgrade, a reminder that fires before the owner's first new prompt uses a UTC date.
- Upstream's Standard mode description mentions workflows, which Free (Direct) deployments do not have.
- As upstream, a blank "New session" keeps the preset it was opened with. After changing the default preset, switch that session in its picker before the first message, or start from a different blank session.
- `pnpm run check` fails two async-context tests on Node 22; Node 24 passes. This affects only the test environment.
- Stopping `pnpm --filter dsh-edge dev:container` can leave local Docker containers running.
- Symlinks that point outside `/workspace` are out of scope for routing.

### Validation and upgrade

`pnpm run check` passes 778 tests. Integration runs against both release artifacts. The Container integration runs daily in CI. Alpha.1 passed acceptance on a real Cloudflare account, covering install, update, the container, and the runtime settings. Manual testing of alpha.1 through alpha.3 found the issues fixed in alpha.2 through alpha.4, and alpha.4 passed its manual checks.

A day of Cloudflare analytics for the test instance showed no Worker or Durable Object errors, a CPU time p99 under 7 ms per request, and about 25 to 40 SQLite rows read per Durable Object invocation, with no growth over the day.

Upgrade with `npx dsh-edge@latest upgrade` and choose "Update it". Existing alpha deployments should use `@latest` to switch to the stable channel. To add the container, choose "Update and change what it can do", then "+ Work on code projects". This release adds no storage migration.
