## dsh-edge 0.18.0

Promotes the Linux container runtime, the capability-first installer, and runtime settings from 0.18.0-alpha.1 to the stable npm `latest` channel. On Workers Paid, an instance can add a Linux container for git, npm, node, and python3, and each bash command runs in the lightweight shell or the container, whichever it needs. The upstream Harness baseline remains 0.1.5-rc.2.

### Changed since 0.17.0

- **Linux container** (#218, #219, #226): the "+ Work on code projects" capability, which requires Workers Paid.
  - The container is attached to the instance's Durable Object and runs the `basic` instance type.
  - It ships git, node 22, npm, python3, jq, make, bzip2, xz, zstd, zip, and unzip.
  - Every release publishes the matching image, `docker.io/pawaca/dsh-edge-computer:<version>`.
  - Workspace files stay in the Durable Object and sync with the container, so stopping or replacing the container loses no files.
  - The container has internet access but receives no Edge credentials.
  - It sleeps after an idle window (10 minutes by default), and the next Linux command wakes it. At most 2 commands run in it at once.
- **Per-command routing** (#221, #223, #224): file and text work stays in the lightweight shell. Programs only Linux has, such as git, npm, and python3, go to the container.
  - A command the lightweight shell cannot run reruns in the container transparently (`retriedFromLight`) when it changed no files. This covers a tool reporting it is unsupported and a command reaching outside `/workspace`, for example `/etc/os-release`.
  - If the command already changed files, it is reported as `lightShellMiss` so the agent decides whether to retry. A rerun shares the command's timeout.
- **Runtime settings** (#227, #228): the DSH Edge settings page shows what the instance can do, what it costs, and the command that changes it.
  - Container deployments add a Linux container card: live status, **Sleep now**, where commands run (Automatic, Always lightweight, or Always Linux), and the idle window before sleep (5, 10, or 30 minutes).
  - A change applies to the next command without a restart and is kept across restarts.
  - The API is `GET`/`PUT /api/runtime` and `POST /api/runtime/container/stop`.
- **Installer** (#229, #231): the installer asks about capabilities instead of plans, and pressing Enter at every prompt completes an install.
  - The order is account, Worker name, capability, then one confirmation.
  - The capability question offers "Research and write" (Free, the default), "+ Analyze data and split big jobs" (Workers Paid; `run_code` and `workflow`), and "+ Work on code projects" (Workers Paid plus container time).
  - A temporary account skips the capability question, and its Cloudflare terms are part of the single confirmation.
  - New installs store images in the Durable Object and never ask for R2. Existing R2 instances keep R2.
  - The owner access key is generated, or read from `DSH_EDGE_ACCESS_KEY`. The DeepSeek key is added when the web app asks, or later in Settings → Models.
  - After deployment the installer offers to open the browser.
- **Same name means update** (#229): rerunning `install` with an existing Worker's name offers "Update it" by default.
  - An update keeps the instance's capabilities, conversations, files, access key, and DeepSeek key, and never asks for them again.
  - "Update and change what it can do" marks the current capability. A downgrade names what is removed and defaults to No.
  - A same-named Worker that is not dsh-edge is never updated; the name counts as taken.
  - `upgrade` follows the same flow and fails if the Worker does not exist.
- **Update verification is public-only** (#229): an update cannot read back the owner key it keeps, so the installer confirms only that the public release reports the new version ("live"). A startup failure behind login shows when the owner next signs in.
- **Leaving Container mode keeps the Container application** (#229, #231): it is the rollback target. The installer looks up its id and prints a runnable `npx wrangler containers delete <id>`. Run it after signing in to the new version to stop Container billing.
- **`@cloudflare/computer` 0.3.1** (#217), paired with the container image's computerd.

### Known limitations

- `pnpm run check` fails two async-context tests on Node 22; Node 24 passes. They are test-environment only: the code under test runs in workerd, and CI uses Node 24. This dates from 0.17.0.
- Stopping `pnpm --filter dsh-edge dev:container` can leave its local Docker containers running; remove them with `docker ps` and `docker rm -f`.
- Symlinks that point outside `/workspace` are out of scope for routing.

### Validation and upgrade

`pnpm run check` passes 756 tests. The release runs the integration against both release artifacts. The Container integration (routing, reruns, a differential corpus against forced Linux runs, runtime settings, and sleep now) runs against a local Docker container and daily in CI.

0.18.0-alpha.1 was then accepted on a real Workers Paid account from the published npm package. The run covered:
- a 0.17.0 instance upgraded in place, with its conversations, files, access key, and model settings kept;
- a new install in five presses of Enter, about 70 seconds end to end;
- a move to the container tier with git, npm, python3, jq, and tar/xz tasks routed as expected;
- the settings card, Sleep now with automatic wake, forced routing, and a kept idle window;
- a downgrade that keeps data and the rollback application;
- a same-named non-dsh-edge Worker left untouched.

The first container command, including the image pull, took 18.7 seconds. Later commands took under a second, and a wake after Sleep now took about 4 seconds. 0.18.0 changes only installer copy and the cleanup command from alpha.1 (#231).

Upgrade with `npx dsh-edge@latest upgrade` and choose "Update it" to keep everything. Alpha deployments should use `@latest` to switch to the stable channel. To add the container, choose "Update and change what it can do", then "+ Work on code projects". This release adds no storage schema or migration.
