## dsh-edge 0.23.0-alpha.1

Workspace skills, image offload, and the Subagent settings card, three more pieces of upstream DeepSeek Harness. Published to npm's `next` channel; `latest` remains on 0.22.0. The upstream Harness baseline stays 0.2.0-rc.2 and the session format stays V4, so upgrading from 0.22 migrates no stored data. Image offload adds one new session event type, `image/offload`, written only when a request's images exceed the model route's budget.

### Added

- **Workspace skills** (#289): skills can be files in the workspace, as in upstream. A skill is `<name>/SKILL.md` or `<name>.md` with YAML frontmatter: `name` and `description` are required; `whenToUse`, `metadata`, `disable-model-invocation`, and `user-invocable` are optional.
  - The Edge looks in the session's project, `.dsh/skills` and `.agents/skills`, and in `/.dsh/skills` and `/.agents/skills` for skills shared by every project. Workers have no home directory, so those sit at the workspace's root. The project is the nearest folder above the session's working directory that contains `.git`, otherwise the working directory itself.
  - A project skill outranks a shared one with the same name, and both outrank skills stored through `/api/skills`, which keep working.
  - You or the agent can now create, edit, and delete skills as files. An added, edited, or removed skill applies from the next turn.
  - The `/` menu lists the skills of the session's own project. An open page keeps its `/` list until it reloads, as upstream's desktop app does.
  - Each skill folder is read up to 100 entries, and a skill file over 64 KiB is skipped. A turn checks only file sizes and modification times, so unchanged skills are not reread.
- **Image offload** (#287): when a request's images exceed the model route's budget (by default 600 images per request), the oldest images are marked offloaded and the request is retried, instead of the turn ending in an error. The model sees a placeholder for each offloaded image.
- **Subagent settings card** (#288): Settings → Built-in plugins → Settings now also shows upstream's Subagent card with the maximum recursion depth (default 1) and the parallelism limit for resident subagents (default 8). A saved value applies to the running instance without a restart.

### Known limitations

- The Subagent card shows only its Limits section: choosing which models subagents may use comes in a later release.
- Upstream's turn outline (each turn's prompt and response preview) is not offered: it grows with every turn, and the Edge stores a session's cached values as one record, so a long session would outgrow it.
- Upstream's `/feedback` command is not offered: it keeps an anonymous user id in a local file, which Workers cannot store.
- Subagents cannot yet be messaged, interrupted, or listed while they run (upstream's `send_message`, `interrupt_agent`, and `list_agents`).
- `glob` and `grep` do not apply `.gitignore` files, so `grep` searches ignored files that ripgrep would skip.
- File write protection covers the `write` and `edit` tools. A shell or container command that writes a file during a guarded write is not detected, as in upstream; one that finished before the guarded write is.
- Rolling back to 0.18 after an upgrade from it is not supported.
- The Agent presets page intro and mode guide mention upstream's Creator mode, which the Edge does not offer.
- The 0.18.0 limitations about the Node 22 test environment, local `dev:container` cleanup, and symlinks outside `/workspace` still hold.

### Validation and upgrade

`pnpm run check` passes 902 tests. Integration runs against both release artifacts (Direct and Isolated), with new checks for:
- a workspace `SKILL.md` outranking a same-name `/api/skills` skill;
- a same-size rewrite of a flat skill refreshing the catalog on the next turn;
- the `/` list resolving each session's own project skills;
- image offload with a one-image budget, read back after a restart;
- the `subagent` settings namespace.

Browser snapshots pin the Settings tab with three cards. The packed installer passes `pack:verify`. `upgrade-from-release.probe.mjs` upgrades state created by the published 0.22.0 and by the published 0.18.0, passing 11 checks each. Not yet validated on a staging instance.

Upgrade a test instance with `npx dsh-edge@next upgrade` and choose "Update it".
