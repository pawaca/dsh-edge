## dsh-edge 0.19.0-alpha.1

First preview on the upstream Harness **0.2.0-rc.1** baseline (from 0.1.5-rc.2). Upstream 0.2.0 changes the session format, the DeepSeek connection, the settings system, reminders, and much of the web client; this release ports the Edge to all of it and keeps existing instances' data. Published to npm's `next` channel; `latest` remains on 0.18.0. **Upgrading moves stored sessions to a new format, and rolling back to 0.18 is not supported**, so try it on a test instance first.

### Upgrading from 0.18

- **Sessions move to format v4 on first start** (#244). Startup migrates every stored session through the upstream catalog, in one transaction, and rewrites only the rows the new format changes. A subagent's parent migrates with its children's catalog evidence, as upstream requires.
  - Cost on the published-0.18.0 upgrade state (10 sessions, 609 event rows): 55 rows written, about 2,900 read, 38–40 ms. A second start writes nothing.
  - 0.18 cannot read v4 sessions. The installer now tags each deployed Worker version, and updating a Worker whose active version predates 0.19 says that sessions move to a new format and that rolling back is not supported.
- **Reminders carry over** (#244). 0.18's active reminders import once into the new task table, with a title taken from the first line of their prompt, and fire on their original schedule. Upstream itself drops them.
- **Settings, skills, MCP servers, files, and image attachments** keep their storage. Models page edits made on 0.18 keep applying.
- **Endpoint** (#246): the DeepSeek connection now speaks only the Anthropic-compatible Messages API, and DeepSeek's OpenAI-compatible root answers it with 404.
  - `https://api.deepseek.com`, `/v1`, and `/beta` map to `https://api.deepseek.com/anthropic`, both in `DEEPSEEK_BASE_URL` and in a saved Models page Base URL (rewritten once on start).
  - Any other endpoint, such as a gateway, is kept. If it answers 404, the turn fails with a message naming the endpoint, the required Messages root, and where to change it.
- **Models**: new sessions default to DeepSeek-V4.1-Flash (`deepseek-flash`, image input). The catalog is V4.1 Flash and V4 Pro; upstream removed V4 Flash and the vision preview. Existing sessions keep the model they were using, and those ids are still accepted by the API.

### Changed

- **Settings** (#244): the Edge serves upstream's new configuration forms from its own Durable Object settings service, including the web client's theme, language, transcript view, busy-send behavior, preview notice, and developer tools. The settings page no longer offers to open a local configuration file.
- **Reminders** (#244): the upstream schedule tools gain titles, daily, weekly, and cron schedules, `schedule_update`, and deleting inactive reminders. The Edge serves them from Durable Object SQLite, and delivery still goes through the session queue, so a reminder shares admission, ordering, and cancellation with your messages.
- **Web client** (#244): it follows upstream 0.2.0, including session pinning and the jobs panel. Clients whose host side the Edge does not provide are left out: product analytics, the PTY terminal, DeepSeek account sign-in, the plugin manager and its settings pages, the permission-preset picker, and the session-log upload preference.
- **Upstream behavior now in effect** (#244):
  - Archived sessions do not run until restored.
  - Queued message edits are text-only.
  - Queued inputs the Edge holds before admission show in the tab that sent them; other tabs see them once admitted.
  - Chat links still open in a new browser tab by default; upstream's in-app browser is one setting away.
- **Plan reviews and questions** (#244): `ask_user_question` and `exit_plan_mode` wait for the owner outside the 60-second short-tool deadline. On 0.18, a plan review left open for a minute failed.
- **`run_code`** (#244): the runtime behind it is now upstream's PTC runtime. The Edge does not offer the new per-run `timeoutMs`; each run keeps the deployment's ceiling.

### Fixed

- **Stop during a shell command in Isolated mode** (#245): the turn used to wait for the whole command and then report `Error: [object Object]`. Stop now ends the turn within 2 seconds and reports the tool call as aborted. A command that does not exit is marked `detached` and may still finish in the background, as it could on 0.18.
- **Installer on macOS** (#247): stopping Wrangler could fail with `kill EPERM` under load.

### Known limitations

- Rolling back to 0.18 after the upgrade is not supported (see above).
- The 0.18 plugin configuration cards (Agent loop, Web search) moved into upstream's plugin manager, which the Edge does not ship. Tracked as P2 gaps.
- The Agent presets page intro and mode guide mention upstream's Creator mode, which the Edge does not offer.
- Upstream packages not yet adopted (P1): model request retries, read-before-write file guards, repeated-tool-call reminders, and session checkpoints. The upstream parity check lists every gap.
- The wiki does not yet cover 25 upstream 0.2.0 subsystems. A prerelease only reports this; the stable release needs it.

### Validation and upgrade

`pnpm run check` passes 841 tests. Integration runs against both release artifacts (Direct and Isolated), including the 0.1.3-fixture upgrade path. The packed installer passes `pack:verify`. The schedule and runtime-queue probes pass in Direct and Isolated.

`upgrade-from-release.probe.mjs` starts the published 0.18.0, creates long, tool, subagent, PTC, image, forked, and archived sessions, reminders, files, settings, MCP servers, and skills, and then starts this build on the same state; all eleven checks pass. The same upgrade was run by hand with a real DeepSeek key: 10 sessions (including a subagent child) kept their ids, titles, presets, and transcripts; old sessions continued with their context, tools, PTC, and image input; reminders were listed with generated titles; and a one-shot reminder set on 0.18 fired on time after the upgrade.

Upgrade a test instance with `npx dsh-edge@next upgrade` and choose "Update it".
