## dsh-edge 0.29.0

bash 命令的输出超过上限后会继续运行，`grep` 会应用 ignore 文件，另有四项上游功能加入 Edge：ralph 工具、会话历史工具、MCP 资源和 Shell 设置卡片。发布到稳定的 npm `latest` 渠道，代码与 [0.29.0-alpha.1](0.29.0-alpha.1.zh.md) 相同；staging 测试发现一次性大量输出会让 Linux 容器停止（见下文）。上游基线仍为 0.2.1-rc.2，会话格式仍为 V4，所以从 0.28 升级不会迁移任何已存数据。

### 新增

- **会话历史工具**（#362，#367）：上游的 `session_search`、`session_event_search`、`session_trace`、`session_event_trace` 和 `session_event_read` 让模型查找和读取以前的会话。默认关闭，可在 Settings → DSH Edge → 可选工具中打开。修改从下一次模型请求起生效；挂载失败的修改会被撤回；重启后挂载失败的，会在下一个回合前重试。
  - 对已存会话的读取保持有界：检索只覆盖最新的 32 个会话；读取事件及其相邻事件时按每页最多 4 MiB 分页，并在加载每一行前先检查大小；标题取自会话摘要。
- **MCP 资源**（#364，#368）：声明了 resources 能力的服务器会获得上游的 `list_mcp_resources`、`list_mcp_resource_templates` 和 `read_mcp_resource`。每个响应限制为 1 MiB，传输中一旦超过就失败。资源调用遵循该连接器的工具权限；只有资源、没有工具的服务器也可以添加。
- **ralph 工具**（#363，#365，仅 Isolated）：上游的全新子 agent 循环，每一轮启动一个新的子 agent 朝同一个目标推进，直到某一轮报告完成或遇到阻碍。它运行在 workflow 引擎上，因此一次最多 100 轮（上游允许 256 轮）。与上游一样，它的提示词要求只在用户明确要求时使用，PTC 模式预设不提供它。
- **Shell 设置卡片**（#345，#370）：Settings → 内置插件 → 设置中会显示上游的 Shell 卡片。命令超时默认取 `DSH_EDGE_DEFAULT_COMMAND_TIMEOUT_MS`，不能超过 `DSH_EDGE_MAX_COMMAND_TIMEOUT_MS`；单流输出上限（默认 64,000 字节，范围 1 KiB 到 1 MiB）是输出转存前内联保留的尾部。两者都从下一条命令起生效。

### 变更

- **较长的命令输出**（#345，#369）：命令的输出超过 64 KiB 后不再停止。与上游一样，每个流内联保留最后 64,000 字节，并把整个流保存到 `/workspace/.spill/bash-<execution>.<stream>.txt`，结果中会给出这个路径，所以 `npm install` 或输出很多的测试能够在轻量 shell 中跑完。在 Linux 容器中，一次性大量输出反而可能让容器停止（见已知限制）。每个流最多保存 16 MiB；未超过上限的输出不写任何文件。结果按上游格式呈现：stdout、`[stderr]` 段、每个被截断的流的提示、`[timed out after Nms]`，最后是 `[exit code: N]`。超过上限的 `timeoutMs` 会被降到上限而不是被拒绝，终端卡片会显示工作目录。
- **`grep` 与 ignore 文件**（#346，#366）：与上游 `grep` 沿用的 ripgrep 默认行为一致，`grep` 会跳过 `.rgignore`、`.ignore` 和（在 git 仓库内的）`.gitignore` 文件排除的内容，且不进入被忽略的目录。因此一个很大的被忽略的 `node_modules` 不再耗尽 20,000 个条目的遍历上限。与 ripgrep 的 `--glob` 一致，`include` glob 仍会选中被 ignore 文件排除的文件。`glob` 保持上游行为，会列出被忽略的文件。

### 已知限制

- **一次性大量输出会让 Linux 容器停止**（#373）。容器内的守护进程 computerd 0.3.1 在命令的进程退出时就结束这条命令，而此时管道里可能还有输出没读完。当 Durable Object 读取输出的速度慢于命令写出的速度时，退出之后才到达的输出会让 computerd 抛出异常并退出。在 staging 实例上，`seq 1 60000`（约 350 KB）几乎每次都这样失败：调用以内部错误失败，命令后面的部分没有执行，容器在 4 到 6 秒后重启。上游的修复（cloudflare/computer#260）尚未发布；computerd 与 Computer 包必须一起升级，所以 Edge 会在那次升级时带上修复。在此之前，请把大量输出重定向到容器内的文件，例如 `npm install > /tmp/install.log 2>&1; tail -n 50 /tmp/install.log`。轻量 shell 中的命令不受影响。
- 轻量 shell 一次性返回命令的完整输出而不是流式输出，所以输出超过 8 MiB（之前是 64 KiB）时仍会停止命令，显示为 `[stopped: …]`。
- spill 使用的工作区存储永远不会被释放（#358），所以每个流最多保存 16 MiB。写入中途失败的 spill 会留下无法访问的已存分块。
- 在仓库根目录对很大的 `node_modules` 运行 `glob` 仍可能超过 20,000 个条目的上限，因为上游的 `glob` 也会列出被忽略的文件。
- `grep` 在少数情况下与 ripgrep 不同：`?` 和字符类按字符而不是按字节匹配；一次搜索最多编译 5,000 个 ignore 模式，最多测试 5,000,000 次；超过 256 KiB 的 ignore 文件不生效；不读取全局 gitignore 和 `.git/info/exclude`。
- 通过会话历史工具，同一实例中的每个会话都能读取其他所有会话，因为它们按工作目录判断访问权限，而 Edge 的会话都从 `/workspace` 开始。`session_event_trace` 拒绝超过 10,000 个事件或 8 Mi 已存字符的会话，`session_trace` 拒绝存有超过 2,000 个会话的实例。在请求进行中关闭这些工具，该次响应中对它们的调用会以未知工具失败。
- 读取以早期格式存储的会话时，会先在内存中迁移它的整段日志（#371）。
- 本版本之前配置的 MCP 服务器要重新 probe 一次才会提供资源。
- 0.28.0 列出的其他限制仍然适用。

### 验证与升级

`pnpm run check` 通过 1,081 个测试。新测试覆盖：输出捕获（20 MiB 下内存占用不随输出增长、尾部、部分保存和仍在写入的 spill、取消与超时的约束）、ignore 规则及其优先级与预算、有界的会话读取、工具开关、MCP 资源请求与审批，以及 Shell 卡片设置。

集成测试在两个发布产物（Direct 与 Isolated）上运行。新增检查：
- 通过结构化报告完成的两轮 ralph 循环（Isolated）；
- 通过设置 API 打开和关闭会话历史工具，`session_search` 能找到较早的会话；
- 一个已 probe 的 MCP 服务器的文本资源，以及一个因超过上限而被拒绝的 2 MiB 资源；
- `grep` 跳过 `.ignore` 排除的目录，而 `glob` 会列出它；
- Shell 卡片设置的 2,048 字节上限应用到下一条命令。

Container 集成测试在本地 Docker 上运行：`seq 1 1000000`（约 6.9 MB）执行完成并产生了其后的副作用，尾部以最后几行结尾且不超过 64,000 字节，spill 文件的 SHA-256 与输出一致。在本地，只有人为放慢 Durable Object 读取输出的速度时容器才会停止，#373 就是这样复现的。

在 Workers 运行时中本地测得：
- `row-cost.probe.mjs` 对比 0.28.0：普通回合写入的行数相同（九个回合共 443 行 SQL、36 次 KV 与 alarm 写入）。
- `upgrade-from-release.probe.mjs` 升级由已发布的 0.28.0 创建的状态，通过 11 项检查。

发布产物仍在 Cloudflare 的 64 MiB 大小限制内（Direct 8.3 MB，Isolated 9.7 MB），本地启动约 110 到 125 ms，Cloudflare 的限制为 1 s。

在一个从 0.28.0 升级到 0.29.0-alpha.1 的 staging 实例上（Isolated，带 Linux 容器）：
- 在轻量 shell 中，`seq 1 20000` 内联保留了最后 64,000 字节，完整输出保存到了 spill 文件；
- 在容器中，`seq 1 200000` 曾经完整跑完，spill 文件的 MD5 与输出一致，其后的命令也执行了；之后反复出现的 350 KB 及以上的一次性输出让容器停止（#373），而 `seq 1 300000 > /tmp/big.log 2>&1; tail -n 2 /tmp/big.log` 五次运行全部通过；
- 用 `.ignore` 排除 `skipped/` 后，`grep` 只在它之外找到匹配，`glob` 仍列出 `skipped/e.txt`；
- 打开会话历史工具后，模型用 `session_search` 找到了较早会话中的记录并读取了匹配的事件；关闭后，`tools.session_search` 为 undefined；
- Shell 卡片设置的 3 秒超时和 2,048 字节输出上限应用到了下一条命令；
- 回合正常保存和读回，Worker 日志中除容器停止外没有其他错误。

staging 上没有测试 MCP 资源，因为该实例唯一的 MCP 服务器需要重新进行 OAuth 登录；集成测试覆盖了这部分。staging 上也没有运行 ralph。

用 `npx dsh-edge@latest upgrade` 升级并选择"Update it"，然后刷新页面。Web 页面会立即更新，但升级后它背后的实例可能还会运行旧版本几分钟。
