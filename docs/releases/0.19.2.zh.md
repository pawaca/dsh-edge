## dsh-edge 0.19.2

把上游 Harness 基线从 0.2.0-rc.1 升级到 **0.2.0-rc.2**（#254）。**未发布到 npm：** tag 已推送，但发布流程在 Windows 浏览器快照检查处停止，未能发布（提醒快照测试偶发超时；Windows 检查现已加入 Edge CI，#259）。这些改动由 [0.19.3](0.19.3.zh.md) 发布。0.19.1 也以同样方式停止，原因是一个已在 #256 修复的测试时序竞争。会话格式仍为 V4，所以从 0.19.0 升级不会迁移任何已存数据。从 0.18 升级仍会按 [0.19.0](0.19.0.zh.md) 所述把会话迁移到 V4，之后不支持退回 0.18。

### 变更

- **定时提醒到点后会被执行。** 上游 rc.2 把到点的提醒表述为用户的定时消息。0.19.0 中，模型被要求把提醒当作不可信内容来展示，所以像"搜索今天的新闻并总结"这样的提醒只会被转述。现在模型会去完成这个任务。提醒由所有者创建，或由 agent 按所有者的要求通过 `schedule_create` 创建。
- **Bash 路径安全。** `bash` 工具现在和上游一样，要求模型在任何删除或移动之前核对解析后的绝对目标路径，并在这类路径中用 `${VAR:?}` 保护变量，使未设置的变量让命令中止，而不是展开为空路径。
- **网页客户端**随上游 rc.2 更新：
  - 模型选择器可以在较长的列表中搜索；
  - 切换会话后计划审阅仍能打开；
  - 耗时显示为"Completed in …"；
  - 过程详情和深色主题样式有所优化。

### 已知限制

- 第一轮结束后立即归档的会话会显示生成的标题，但该标题不会被保存；Worker 重启后会改为显示首条消息的开头几个词（#253）。0.19.0 中已经如此，只影响标题。
- 0.19.0 列出的内容仍然适用。

### 验证与升级

`pnpm run check` 通过 844 个测试，浏览器快照测试现在会等待本轮过程控件变为可用后再操作（#256）。集成测试覆盖两个发布产物（Direct 和 Isolated），打包后的安装器通过 `pack:verify`。`upgrade-from-release.probe.mjs` 分别升级由已发布的 0.19.0 和 0.18.0 创建的数据，各通过 11 项检查。在 0.19.0 的数据上，本版约 0.6 秒启动，无需迁移。

用 `npx dsh-edge@latest upgrade` 升级，选择"Update it"。
