## dsh-edge 0.23.0-alpha.1

工作区 skill、图片卸载和子 agent 设置卡片，又补上三项上游 DeepSeek Harness 的能力。发布到 npm 的 `next` 渠道；`latest` 仍为 0.22.0。上游 Harness 基线仍为 0.2.0-rc.2，会话格式仍为 V4，所以从 0.22 升级不会迁移任何已存数据。图片卸载新增一种会话事件类型 `image/offload`，只在请求中的图片超出模型路由预算时写入。

### 新增

- **工作区 skill**（#289）：与上游一样，skill 可以是工作区里的文件。skill 是 `<name>/SKILL.md` 或 `<name>.md`，开头是 YAML frontmatter：`name` 和 `description` 必填，`whenToUse`、`metadata`、`disable-model-invocation`、`user-invocable` 可选。
  - Edge 在会话所在项目的 `.dsh/skills` 和 `.agents/skills` 中查找，并在 `/.dsh/skills` 和 `/.agents/skills` 中查找所有项目共用的 skill。Workers 没有用户主目录，所以这两个目录放在工作区根上。项目指会话工作目录往上最近一个包含 `.git` 的目录，没有则为工作目录本身。
  - 同名时项目 skill 优先于共用 skill，两者都优先于通过 `/api/skills` 存储的 skill；后者继续可用。
  - 你或 agent 现在可以用文件新建、编辑和删除 skill。新增、修改或删除的 skill 从下一个 turn 起生效。
  - `/` 菜单列出会话所在项目的 skill。已打开的页面会保留它的 `/` 列表，刷新后才更新，与上游桌面版一致。
  - 每个 skill 目录最多读取 100 个条目，超过 64 KiB 的 skill 文件会被跳过。每个 turn 只检查文件大小和修改时间，没变的 skill 不会重读。
- **图片卸载**（#287）：请求中的图片超出模型路由预算（默认每个请求 600 张）时，最早的图片会被标记为已卸载并重试请求，而不是让 turn 报错结束。模型会看到每张被卸载图片的占位说明。
- **子 agent 设置卡片**（#288）："设置 → 内置插件 → 设置"中新增上游的子 agent 卡片，可设置最大递归深度（默认 1）和常驻子 agent 的并行上限（默认 8）。保存后无需重启即对运行中的实例生效。

### 已知限制

- 子 agent 卡片只显示"限制"部分：选择子 agent 可用的模型将在后续版本提供。
- 不提供上游的 turn 大纲（每个 turn 的提问与回答预览）：它随每个 turn 增长，而 Edge 把一个会话的缓存值存为一条记录，长会话会超出上限。
- 不提供上游的 `/feedback` 命令：它把匿名用户 id 保存在本地文件中，Workers 无法保存。
- 子 agent 运行期间暂时无法发消息、中断或列出（上游的 `send_message`、`interrupt_agent` 和 `list_agents`）。
- `glob` 和 `grep` 不应用 `.gitignore` 文件，所以 `grep` 会搜索 ripgrep 本会跳过的被忽略文件。
- 文件写入保护只覆盖 `write` 和 `edit` 工具。在受保护的写入进行期间，由 shell 或容器命令写入的文件改动不会被发现，这与上游一致；在受保护的写入之前已完成的改动会被发现。
- 从 0.18 升级后不支持退回 0.18。
- Agent 预设页的介绍和模式说明提到了上游的 Creator 模式，Edge 不提供该模式。
- 0.18.0 中关于 Node 22 测试环境、本地 `dev:container` 清理以及指向 `/workspace` 之外的符号链接的限制仍然存在。

### 验证与升级

`pnpm run check` 通过 902 个测试。集成测试覆盖两个发布产物（Direct 和 Isolated），新增的检查包括：
- 工作区 `SKILL.md` 优先于 `/api/skills` 中的同名 skill；
- 扁平 skill 文件以相同大小改写后，下一个 turn 刷新目录；
- `/` 列表按各会话自己的项目列出 skill；
- 一张图片预算下的图片卸载，并在重启后从存储读回；
- `subagent` 设置命名空间。

浏览器快照固定了带三张卡片的设置标签页。打包后的安装器通过 `pack:verify`。`upgrade-from-release.probe.mjs` 分别升级由已发布的 0.22.0 和 0.18.0 创建的数据，各通过 11 项检查。尚未在 staging 实例上验证。

用 `npx dsh-edge@next upgrade` 升级测试实例，选择"Update it"。
