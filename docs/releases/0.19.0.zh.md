## dsh-edge 0.19.0

把 Edge 的上游 Harness 基线升级到 **0.2.0-rc.1**（原为 0.1.5-rc.2），并把它从 0.19.0 预发布版提升到稳定的 npm `latest` 频道。上游 0.2.0 改了会话格式、DeepSeek 连接方式、设置系统、定时提醒，以及大部分网页客户端；本版把 Edge 全部适配过来，保留已有实例的数据，并新增了找回丢失访问密钥的方法。**升级会把已存的会话迁移到新格式，之后不支持退回 0.18。** 完整细节见各预发布版说明（[alpha.1](0.19.0-alpha.1.zh.md)、[alpha.2](0.19.0-alpha.2.zh.md)）。

### 从 0.18 升级

- **会话在首次启动时迁移到 v4 格式**（#244）。启动时通过上游的格式目录在一个事务内迁移所有已存会话，只改写新格式有变化的行。按上游要求，子代理的父会话迁移时会带上子会话的目录信息。
  - 在已发布 0.18.0 的升级测试数据上（10 个会话、609 行事件）：写入 55 行，读取约 2,900 行，耗时 38–40 ms。再次启动不再写入。
  - 0.18 读不了 v4 会话。安装器会给每个部署的 Worker 版本打标签；更新一个当前版本早于 0.19 的 Worker 时，会提示会话将迁移到新格式、不支持回退。
- **定时提醒会保留**（#244）。0.18 中仍有效的提醒会一次性导入新的任务表，标题取提醒内容的第一行，并按原定时间触发。上游自身不迁移这些提醒。
- **设置、技能、MCP 服务器、文件和图片附件**存储不变。0.18 上在 Models 页面做的修改继续生效。
- **连接地址**（#246）：DeepSeek 连接现在只走 Anthropic 兼容的 Messages API。DeepSeek 的 OpenAI 兼容根地址对该 API 返回 404。
  - `https://api.deepseek.com`、`/v1`、`/beta` 会映射到 `https://api.deepseek.com/anthropic`，`DEEPSEEK_BASE_URL` 和 Models 页面保存的 Base URL 都适用（后者在启动时改写一次）。
  - 其他地址（例如网关）保持不变。如果它返回 404，这一轮的错误信息会附上提示：该地址可能不支持 Messages API，`https://api.deepseek.com/anthropic` 支持，Base URL 在 Models 页面或 `DEEPSEEK_BASE_URL` 中设置。提示不包含所配置地址的任何部分，因为地址中可能带有凭证。（0.19.0-alpha.1 的说明称提示会写出该地址，实际从未如此。）
- **模型**：新会话默认使用 DeepSeek-V4.1-Flash（`deepseek-flash`，支持图片）。模型列表为 V4.1 Flash 和 V4 Pro；上游去掉了 V4 Flash 和视觉预览版。已有会话继续使用原来的模型，这些模型 id 目前 API 仍然接受。

### 0.18.0 以来新增

- **重置丢失的访问密钥**（#249）：Worker 已存在时，安装器提供 **Update and reset the access key**。
  - 它部署该版本并使用新的 owner key（自动生成，或取自 `DSH_EDGE_ACCESS_KEY`），只显示一次。
  - 对话、文件和 DeepSeek key 都保留。旧密钥随即失效，所有已登录的浏览器都需要重新登录。
  - 登录页会说明如何找回丢失的密钥，并给出与部署所在发布渠道一致的命令。
- **上游对等检查**（#243）：上游的插件或工具如果既没被 Edge 使用、也没有附理由归类，`pnpm run check` 就会失败。升级基线时要审阅上游文档的变化；发布稳定版要求 wiki 覆盖上游的每一个子系统。
- **上游 0.2.0 网页客户端**（#244），包括会话置顶、后台任务面板、可打开文件、文档预览和子代理对话的右侧边栏，以及对话分组。

### 0.18.0 以来变更

- **设置**（#244）：上游新的配置表单由 Edge 自己的 Durable Object 设置服务提供，包括网页客户端的主题、语言、对话视图、忙碌时发送行为、预览提示和开发者工具。
- **定时提醒**（#244）：上游的提醒工具新增标题，每天、每周和 cron 计划，`schedule_update`，以及删除已失效的提醒。Edge 用 Durable Object SQLite 提供这些功能，送达仍走会话队列。
- **随上游生效的行为**（#244）：
  - 已归档的会话恢复之前不能运行。
  - 排队消息只能编辑文字。
  - 对话中的链接仍默认在浏览器新标签页打开；改一个设置就能用上游的内置浏览器。
- **计划审阅和提问**（#244）：`ask_user_question` 和 `exit_plan_mode` 等待所有者时不受 60 秒短工具时限约束。
- **`run_code`**（#244）：背后的运行时改为上游的 PTC 运行时。Edge 不提供新增的单次 `timeoutMs`。

### 0.18.0 以来修复

- **Isolated 模式下 shell 命令运行中点停止**（#245）：现在点停止后 2 秒内结束这一轮，工具调用显示为已中止；以前要等整条命令跑完，并报 `Error: [object Object]`。不退出的命令可能仍在后台跑完，和 0.18 一样。
- **macOS 上的安装器**（#247）：负载高时停止 Wrangler 不再报 `kill EPERM` 失败。

### 已知限制

- 升级后不支持退回 0.18。
- 0.18 的插件配置卡片（Agent loop、Web search）移到了上游插件管理器中，Edge 没有提供插件管理器。
- Agent 预设页的介绍和模式说明提到了上游的 Creator 模式，Edge 不提供该模式。
- 尚未接入的上游包包括：模型请求重试、文件先读后写保护、重复工具调用提醒、会话检查点，以及待办列表（#234）。[wiki 路线图](https://github.com/pawaca/dsh-edge/wiki/Roadmap-zh)列出了所有剩余缺口。
- 0.18.0 中关于 Node 22 测试环境、本地 `dev:container` 清理以及指向 `/workspace` 之外的符号链接的限制仍然存在。

### 验证与升级

`pnpm run check` 通过 844 个测试。集成测试覆盖两个发布产物（Direct 和 Isolated），包括 0.1.3 样本数据的升级路径；打包后的安装器通过 `pack:verify`。`upgrade-from-release.probe.mjs` 升级由已发布 0.18.0 创建的数据，全部 11 项检查通过。

这次升级也手动验证过两次：
- **本地，使用真实 DeepSeek key。** 10 个会话（含一个子代理子会话）的 id、标题、预设和对话记录都保留；旧会话能带着上下文继续对话，工具、PTC 和图片输入正常；在 0.18 上设的提醒升级后按时触发。
- **在一个 staging 实例上**（Isolated 加 Linux 容器），从 0.18.0 原地升级到 0.19.0-alpha.2，同时重置了访问密钥。DeepSeek key 保留；7 个会话全部迁移并能打开，旧会话能接上上下文；新会话默认使用 V4.1 Flash，并在容器中运行了 bash；新设的提醒按时触发；设置页正确显示了版本和容器状态。

[wiki](https://github.com/pawaca/dsh-edge/wiki) 覆盖了上游 0.2.0 的每一个子系统，0.19 改动过的页面都已更新。

用 `npx dsh-edge@latest upgrade` 升级，选择"Update it"；如果已经没有密钥，选择"Update and reset the access key"。现有 alpha 部署应使用 `@latest` 切换到稳定频道。从 0.18 升级会把已存的会话迁移到新格式，不支持回退。
