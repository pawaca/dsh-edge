# dsh-edge 0.2.0-alpha.2

English | [中文](https://github.com/pawaca/dsh-edge/blob/dsh-edge-v0.2.0-alpha.2/docs/releases/0.2.0-alpha.2.zh.md)

This prerelease focuses on a clearer first-run experience and a more portable release toolchain. It keeps the same DeepSeek Harness `0.1.0-rc.7` baseline, Worker behavior, and durable-data contracts as alpha.1.

## Highlights

- Adds a recognizable, dependency-free dsh-edge installer hero that clears the terminal frame before drawing, keeps the artwork naturally left-aligned, and labels the package version alongside the pinned Harness version, community-project boundary, and selected operation.
- Observes the public health endpoint after Wrangler accepts an upload, so the installer can distinguish a ready Worker from normal Cloudflare propagation delay.
- Explains that activation usually takes 10–30 seconds, waits for at most 45 seconds, and presents explicit ready, pending, or recovery guidance without sending owner or DeepSeek credentials.
- Keeps Wrangler acceptance as the installation success boundary: a delayed public route never turns an accepted deployment into a failed install.
- Updates GitHub Actions to `actions/checkout@v7` and `actions/setup-node@v7`, and migrates pnpm 11 workflows to the official `pnpm/setup@v2` successor.
- Makes release tooling work with both traditional JavaScript pnpm entrypoints and the standalone pnpm executable used by the new setup action.

## Install or upgrade the prerelease

Requires Node.js 22.14 or newer and your own DeepSeek API key.

```sh
npx dsh-edge@next install
```

Existing prerelease deployments can upgrade in place:

```sh
npx dsh-edge@next upgrade
```

The `next` dist-tag moves to alpha.2 while `latest` remains on 0.1.3. Durable Object, session, workspace, and VFS data remain compatible. Cloudflare's write-only secret behavior still requires entering the existing owner access key and DeepSeek API key during an upgrade.

## Scope and compatibility

Direct Shell and Dynamic Worker modes remain behaviorally aligned, and the pinned upstream assembly stays on `0.1.0-rc.7` with the same six audited patches. This release does not add authentication models, storage migrations, public API changes, or new upstream plugins.

The deployment remains intentionally single-owner. Attachments and images, remote MCP, Skills, Workflows, Jobs, and Subagents are not yet adapted to the Edge runtime. `web_fetch` remains disabled pending an explicit network-access policy.

## Release integrity

The npm package is published under the `next` dist-tag from the reviewed `dsh-edge-v0.2.0-alpha.2` tag. The release workflow verifies the exact tag and package version, rebuilds the pinned standalone assembly, exercises Direct and Dynamic Worker modes, checks 0.1.3 durable-state compatibility, runs browser/runtime snapshots, and installs the packed artifact outside the workspace before trusted publication. The matching GitHub prerelease carries the same tarball as an asset.
