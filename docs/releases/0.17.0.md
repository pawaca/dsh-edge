## dsh-edge 0.17.0

Promotes the Dynamic Worker tools from 0.17.0-alpha.1 to the stable npm `latest` channel. The upstream Harness baseline remains 0.1.5-rc.2.

### Changed since 0.16.0

- **Runtime providers** (#209): Direct Shell and Dynamic Worker are modeled as runtime providers with capabilities and plan requirements; the Worker and the installer derive runtime facts from one catalog. A capability that only some providers offer is absent, not broken, where its provider is unavailable.
- **`workflow` tool** (#210, Isolated only): the upstream orchestration tool. The model writes a script with `agent()`, `parallel()`, `pipeline()`, `phase()` and `log()` that fans work out across subagents. Each run executes in its own Dynamic Worker with no outbound network and a Worker Loader `cpuMs` limit. The Durable Object enforces the caps: at most 4 children at once and 100 per run, with bounded request, reply, progress and result sizes. Cancelling the turn disposes the isolate and cancels the children.
- **`run_code` tool** (#211, Isolated only): upstream `dsh-tools` PTC mode, enabled as `both` alongside the native tools. The model writes a TypeScript program that calls tools as `await tools.name(args)`. Types are stripped with sucrase, and each program runs in its own Dynamic Worker. Nested calls are ordinary tool dispatches, so approval and spill still apply. Per run: at most 200 nested calls, 256 KiB of arguments per call, 2 MiB per result, and 1 MiB of total output. The prompt carries a generated tool SDK section on every turn.
- **Turn context for isolate calls** (#212): calls from a workflow or code isolate back into the Durable Object run inside the tool call that started them, so file tools work from `run_code` and workflow children.
- **Installer**: the Isolated runtime choice now notes that it adds `workflow` and `run_code`.

### Validation and upgrade

Alpha.1 passed 534 tests, integration against both release artifacts, and local testing with a real model and the web UI. That testing covered 3- and 6-child workflows, including schema output and cancellation mid-run; `run_code` with bash, file tools, `web_fetch` and approval; and history replay. In that testing a 6-child workflow wrote about 135 session-event rows in batched writes. The stable release keeps that runtime unchanged.

Upgrade with `npx dsh-edge@latest upgrade`. Existing alpha deployments should use `@latest` to switch to the stable channel. The new tools appear only on Isolated deployments; Direct deployments are unchanged. This release adds no new storage schema or migration.
