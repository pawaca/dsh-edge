## dsh-edge 0.12.0-alpha.1

Alpha preview of scheduled reminders and bounded runtime scheduling. Published to npm’s `next` channel for testing; the stable `latest` channel is unchanged. The upstream baseline remains 0.1.2-rc.1.

### Added

- **Scheduled reminders in the original conversation** (#151): ask the Agent to create, list, or delete reminders using the upstream Schedule tools. Supports a delay, an absolute time with an explicit offset or time zone, and repeating intervals of at least 300 seconds. A Durable Object alarm wakes the session even when all browser tabs are closed. Reminders queue behind running work without cancelling or steering it; no new session or separate cron execution slot is created. Calendar cron expressions and external notifications are not included.
- **Durable reminder delivery**: reminder dispatch and queue admission commit together. Missed repeating intervals collapse to the latest occurrence. Limits are 128 active reminders per owner and a 4 KiB JSON-encoded prompt per reminder. Failed preparation or admission backs off per session for 30 seconds, persists across restarts, and allows healthy sessions to continue. Deleting the last reminder cleans up its retry state.

### Changed

- **One shared execution slot and a bounded short-tool pool** (#148): concurrent browser inputs use the durable main-session queue, with at most 128 unsettled inputs and 2 MiB of serialized input data per owner. Actual tools share two execution permits, at most 32 waiters, a 30-second queue deadline, and a 60-second cooperative execution deadline. Alarm recovery uses the existing slot; this release does not add subagents or background long-running tools.

### Fixed

- **Queue recovery** (#149): short-lived model failures no longer pause subsequent queued inputs. Interrupted residency still pauses pending inputs until the user explicitly resumes with a new message; uncertain external side effects are not replayed automatically. Pre-turn failures are logged and surfaced.
- **Dormant browser connections** (#150): wake-up restores Remote stream handling so sending a message from an already-open tab does not silently stall after the Durable Object becomes dormant.
- **Reminder failure isolation** (#151): a broken reminder session cannot block healthy queued inputs or other sessions’ due reminders. Malformed-tail repair rebuilds the reminder projection atomically; ambiguous dispatched reminders require manual recovery rather than risking duplicate delivery.

### Try the alpha

Upgrade an existing installation with `npx dsh-edge@0.12.0-alpha.1 upgrade`, or create a new installation with `npx dsh-edge@0.12.0-alpha.1 install`. Keep the same named Worker and runtime mode when upgrading to retain its Durable Object data. The upgrade asks for the owner access key again because Cloudflare secrets are write-only.

Suggested checks: create a one-minute reminder and close every tab; reopen the original conversation to see the response; send messages from two tabs while a task is busy; list and delete a reminder before it is due. A reminder asks the model to present its content, not to execute it as a new user command. No email or push notification is sent. A crash-paused session still requires explicit user recovery.
