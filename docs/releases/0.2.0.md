# dsh-edge 0.2.0

English | [中文](https://github.com/pawaca/dsh-edge/blob/dsh-edge-v0.2.0/docs/releases/0.2.0.zh.md)

This release establishes dsh-edge as a standalone community wrapper around the published DeepSeek Harness `0.1.0-rc.8` packages. It preserves the Cloudflare runtime and durable-data contracts released in 0.1.3 while removing the need to maintain a source fork or a GitHub build pipeline.

## Highlights

- Installs or upgrades a personal DeepSeek Harness instance directly from npm into a Cloudflare account, without cloning this repository.
- Supports the Free Direct Shell and paid Dynamic Worker modes with the same Web UI, HTTP/WebSocket protocol, tools, authentication, and Durable Object storage.
- Keeps conversations and the `/workspace` virtual filesystem in Durable Object SQLite while keeping owner and DeepSeek credentials in write-only Worker secrets.
- Adds a guided installer hero, temporary-account and existing-account paths, explicit cost and recovery output, and bounded observation of normal Cloudflare route activation.
- Uses the complete published Harness `0.1.0-rc.8` baseline, including interrupted assistant-prefix preservation, reasoning-continuation fixes, unified provider retries, and bounded multi-query DeepSeek Web Search.
- Exposes deployment version, runtime, storage, credential readiness, upgrade guidance, and owner sign-out through an Edge-owned plugin in the upstream Settings UI.

## Install or upgrade

Requires Node.js 22.14 or newer and your own DeepSeek API key.

```sh
npx dsh-edge install
```

Existing stable deployments can upgrade in place:

```sh
npx dsh-edge upgrade
```

If the installed version is `0.2.0-alpha.1`, `alpha.2`, or `alpha.3`, switch from the prerelease channel to stable once with:

```sh
npx dsh-edge@latest upgrade
```

Durable Object, session, workspace, and VFS data remain compatible with 0.1.3 and the 0.2 alphas. Cloudflare secrets are write-only, so an upgrade still asks for the existing owner access key and DeepSeek API key.

## Scope and compatibility

The deployment remains intentionally single-owner. Attachments and images, `web_fetch`, `@file` and `@session` references, remote MCP, Skills, Workflows, Jobs, and Subagents are not included in 0.2.0. Direct mode remains a just-bash environment rather than a Linux container; Dynamic Worker mode requires an eligible paid Cloudflare plan.

Every published Harness package is pinned to `0.1.0-rc.8`. The six retained Edge adaptations are version-bound and mechanically verified. Durable Object session storage remains on Edge schema v2; the upstream Node SQLite schema is not used and this release performs no durable-data migration.

## Release integrity

The npm package is published under the `latest` dist-tag from the reviewed `dsh-edge-v0.2.0` tag. The release workflow verifies the exact tag and package version, rebuilds the deterministic standalone assembly, exercises Direct and Dynamic Worker modes, checks 0.1.3 durable-state compatibility, runs browser/runtime snapshots, and installs the packed artifact outside the workspace before trusted publication. The matching GitHub Release carries the same tarball as an asset.
