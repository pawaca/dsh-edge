## dsh-edge 0.34.0

上游基线升级到 DeepSeek Harness 0.2.1-rc.4，这是一个只含修复的版本。发布到稳定的 npm `latest` 渠道，代码与 [0.34.0-alpha.1](0.34.0-alpha.1.zh.md) 相同，后者已在 staging 上验证（见下文）。会话格式仍为 V4。

### 变更

- **上游基线 0.2.1-rc.4**（#397）：所有 `@deepseek-ai/dsh-*` 包从 0.2.1-rc.3 升级。多数包只改动了版本号。
- **会话视图标签：**只有标签名太长、在标签里显示不全时，才显示完整名称的提示。“More conversation views”按钮的名称保持不变，当前视图被收进“更多”时按钮高亮；菜单把该视图标为当前视图。
- **不影响 Edge 的改动：**上游另外两项修复让 DeepSeek 账号 provider 和 MCP 资源列表在 ACP 模式下不把诊断信息写到 stdout。Edge 使用 API key 登录，它自己的 MCP 客户端只对声明了资源能力的服务器列出资源。

### 已知限制

0.33.0 列出的限制仍然适用。

### 验证

`pnpm run check` 通过 1,129 项测试。所有 Edge 补丁都能重新应用，其中两个为 Worker 打包内联 Harness 版本号的补丁（`dsh-llm`、`dsh-repeat-tool-reminder`）现在写入 0.2.1-rc.4。上游参考表仍为 200 个条目。

集成测试针对两种发布产物（Direct 和 Isolated）运行，Linux Container 集成测试也通过。快照没有变化。由于“更多”按钮不再写出当前视图名，窄窗口浏览器检查改为通过菜单中被标为当前的那一行确认视图已切换。

在 Workers 运行时中本地测得：
- `row-cost.probe.mjs` 对比 0.33.0：每一步写入和读取的行数都相同（九个普通回合共 443 行 SQL、36 次 KV 与 alarm 写入）。
- `upgrade-from-release.probe.mjs` 升级由已发布的 0.33.0 创建的状态，通过 11 项检查。

在从 0.33.0 升级到 0.34.0-alpha.1 的 staging 实例上（Isolated，带 Linux Container）：
- 就绪检查报告上游版本为 0.2.1-rc.4；
- 升级前的 54 个会话仍在列表中；
- 一个 DeepSeek-V4.1-Flash 回合正常完成；
- 模型目录列出 DeepSeek-V4.1-Flash 和 DeepSeek-V4-Pro 及其推理档位；
- "More conversation views" 按钮的名称保持不变；所有视图都在标签行中时，菜单只显示 "Every view is in the tab row"。

窄窗口下视图被收进“更多”由上文的浏览器检查验证，而不是在 staging 上验证。

用 `npx dsh-edge@latest upgrade` 升级并选择"Update it"，然后刷新页面。网页会立即更新，但升级后的几分钟内，背后的实例可能仍在运行上一个版本。
