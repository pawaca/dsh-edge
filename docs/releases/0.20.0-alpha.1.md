## dsh-edge 0.20.0-alpha.1

Mounts four upstream Harness plugins that change how the agent works: a reminder when it repeats the same tool call, retry of transient model-request failures, protection against overwriting files it has not read, and durability checkpoints before model requests and tool calls. Published to npm's `next` channel; `latest` remains on 0.19.3. The upstream Harness baseline stays 0.2.0-rc.2 and the session format stays V4, so upgrading from 0.19 migrates no stored data.

### Added

- **Repeated tool-call reminder** (#261): after 3, 5, and 8 identical consecutive tool calls, the agent receives a notice that it is repeating itself, before its next model request.
- **Model-request retry** (#262): a rate limit, server error, timeout, transport error, or empty response is retried within the same turn, up to five times, waiting 0.5–10 s or as long as the provider's `Retry-After` asks. Each retry is recorded in the session before the wait. Errors that a retry cannot fix, such as an unknown model (404), are not retried.
- **File write protection** (#263):
  - `edit`, and `write` over an existing file, are refused unless the agent has read that file in this session.
  - Both are refused when the file has changed since the agent read it, for example after a `bash` command wrote to it.
  - Writes and edits of the same file run one at a time, so of two concurrent changes from the same read, one succeeds and the other is refused as stale.
- **Durability checkpoints** (#265): the session log is stored before each model request, each top-level tool call, and each step. Before, events were stored up to about 100 ms later, so a tool could start before its call was stored, and a restart in that window lost the record of the call. This writes a few more rows: about 5 for a turn without tools and 22 for a turn with three tool calls.

### Known limitations

- Everything listed for 0.19.0 still holds.
- File write protection covers the `write` and `edit` tools. A shell or container command that writes a file during a guarded write is not detected, as in upstream; one that finished before the guarded write is.

### Validation and upgrade

`pnpm run check` passes 849 tests. Integration runs against both release artifacts (Direct and Isolated), with new checks for the reminder, a retried rate limit, refused unread and stale edits, and the checkpoint write batches. The packed installer passes `pack:verify`. `upgrade-from-release.probe.mjs` upgrades state created by the published 0.19.3 and by the published 0.18.0, passing 11 checks each. Started on 0.19.3 state, this release boots in about 0.6 s with no migration. Measured locally before the checkpoints were added, turns wrote as many rows as in 0.19.0, and an idle instance set no alarms.

Upgrade a test instance with `npx dsh-edge@next upgrade` and choose "Update it".
