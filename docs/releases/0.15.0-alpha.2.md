## dsh-edge 0.15.0-alpha.2

Fixes legacy-session upgrades and reduces migration writes after alpha.1. The upstream Harness baseline remains 0.1.5-rc.2. Published to npm's `next` channel; `latest` remains on 0.14.1.

### Fixed

- **Legacy session compatibility** (#179): normalize known historical cancellation records before the upstream V0 migration so existing sessions and workspaces can initialize after an upgrade. Validate all outdated session logs before writing migration results, then commit event data, session headers and summaries atomically.
- **Migration write volume** (#179): choose between replacing migrated sessions and rebuilding the compact event table according to the estimated row cost. The strategy query bounds event reads and avoids one SQL query per session. Large histories still require sufficient account quota; transaction rollback and database restoration do not refund consumed quota.
- **Verified installation** (#179): wait for session services and the DeepSeek adapter to initialize, and verify the exact uploaded Cloudflare Worker version before reporting success. Retry transient authentication failures during deployment propagation and validate owner-key length in UTF-8 bytes.
- **Recovery access** (#179): keep ordinary session and recovery routes available when model-adapter initialization fails, while the readiness endpoint reports that failure.

### Validation

- Local unit checks passed with 432 tests and two existing skips. Both Worker modes passed integration and packed-package checks; all six browser tests passed, with focused cancellation coverage also confirming that stopping a response does not display `[object Object]`.
- A local workerd migration benchmark reduced measured writes from 155,493 to 1,934 for the same legacy-history fixture, with identical resulting event content. This is a fixture measurement, not a guarantee for every database or the account's total billed usage.
- Linux and Windows CI passed for the merged fix.

This remains an alpha release. Evaluate upgrades on a test instance before upgrading a primary deployment, and check the account's remaining Durable Objects quota before a large migration.
