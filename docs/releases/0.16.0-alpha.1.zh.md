## dsh-edge 0.16.0-alpha.1

MCP Connectors 首个预览版——将外部 MCP 工具服务器接入你的 Edge 代理。发布至 npm 的 `next` 频道；`latest` 保持为 0.15.1。建议先在测试实例试用，再升级主要部署。上游 Harness 基线保持 0.1.5-rc.2。

### 新增

- **MCP 客户端** (#186, #189)：通过 Streamable HTTP 传输连接外部 MCP 服务器。Edge 使用 `@modelcontextprotocol/sdk@1.30.0` 实现的 `edge-mcp-client` 替换了上游 `dsh-mcp-client`——上游插件的 stdio 传输和子进程 `inject` 依赖与 Workers 不兼容。工具通过 `tools/list` 分页发现（每服务器最多 128 个，10 页），注册到 `ctx.tools`，模型视角与内置工具无异。配置时探测 + 按次连接；无持久连接。
- **认证** (#189, #199)：三种认证模式——`none`、`bearer`（token 通过 `CredentialProvider` 存储，不进入 MCP 配置）、`oauth`（OAuth 2.1，支持 PKCE、动态客户端注册、RFC 9728 受保护资源元数据 + RFC 8414 授权服务器元数据路径感知发现，120 秒偏移自动刷新 token）。
- **工具策略** (#192, #193)：每连接器策略——`allow_all`、`read_only`（默认）、`approve_all`。`read_only` 模式自动放行带 `readOnlyHint: true` 注解的工具或名称匹配 `get_*`、`list_*`、`read_*`、`search_*`、`find_*`、`fetch_*`、`describe_*` 模式的工具；其余需审批。
- **工具审批** (#185)：Edge 自有 `tools/pre-execute` 瀑布流拦截 `web_fetch`、所有 `mcp__*` 工具和 `mcp_call`。设置界面可在 `ask`（外部调用前询问）和 `never`（全部信任）间切换。每连接器 MCP 策略独立于全局模式判断。
- **SSRF 防护** (#194, #195, #199)：私有 IPv4/IPv6 地址段和 `.internal`/`.local`/`.localhost` 主机名被阻止；`localhost`/`127.0.0.1`/`::1` 明确放行以支持本地开发。HTTP 重定向被阻止。JSON Schema 校验使用 `@cfworker/json-schema`（Workers 兼容，无 `eval`）。
- **Meta-tool 模式** (#202)：当注册的 MCP 工具总数超过 20 个时，Edge 切换为两个元工具——`mcp_search`（跨所有服务器关键词搜索）和 `mcp_call`（按限定名调用），而非逐个注册。Meta-tool 模式激活时系统提示词扩展服务器摘要。
- **MCP 结果处理** (#197, #198)：MCP 2025-03-26 规范的 `outputSchema` 和 `structuredContent` 在 schema 通过 DSH 支持的 JSON Schema 子集时被转发。PNG/JPEG 图片内容块通过附件管道投影（需活跃模型支持图片输入）。
- **热替换** (#191)：重新探测服务器时替换其工具注册，无需重启会话或 DO。
- **设置界面** (#200, #201)：Edge Settings 中独立的"MCP Connectors"标签页，支持添加、移除、探测服务器，查看工具列表，设置认证方式，以及选择每连接器策略。OAuth 连接流程从界面启动。
- **存储** (#203)：工具目录按服务器存储于独立 DO storage key（`dsh-edge:mcp-tools:<name>`），配合内存缓存，与服务器配置 key 分离，避免配置写入时重新序列化整个目录。旧内嵌格式条目自动迁移。

### 限制

| 限制项 | 值 |
|---|---|
| 每服务器工具数 | 128 |
| 目录页数 | 10 |
| 目录大小 | 128 KB |
| 描述长度 | 512 字符 |
| 公开工具名 | 64 字符 |
| 服务器 instructions | 1024 字符 |
| 探测超时 | 30 秒 |
| 调用超时 | 60 秒 |
| Meta-tool 阈值 | 20 个工具 |

### HTTP API

| 方法 | 路径 | 用途 |
|---|---|---|
| GET | `/api/mcp-servers` | 列出已配置的服务器 |
| PUT | `/api/mcp-servers` | 保存服务器配置 |
| PUT | `/api/mcp-servers/:name/token` | 存储 bearer token |
| DELETE | `/api/mcp-servers/:name/token` | 清除 bearer token |
| POST | `/api/mcp-servers/:name/probe` | 探测服务器并刷新工具 |
| GET | `/api/mcp-servers/:name/tools` | 列出缓存的工具 |
| POST | `/api/mcp/oauth/start` | 发起 OAuth 流程 |
| POST | `/api/mcp/oauth/complete` | 完成 OAuth 授权码交换 |
| GET/PUT | `/api/approval-mode` | 读取/写入全局审批模式 |

### 验证

部署前运行 `pnpm run check` 和两种 Worker 模式的集成测试。浏览器和快照覆盖应在测试实例上验证。MCP 工具发现和调用需要可达的 Streamable HTTP MCP 服务器。

连接 MCP 服务器的持续运行和 OAuth token 生命周期管理仍是正式发布 0.16.0 前的 alpha 验证内容。
