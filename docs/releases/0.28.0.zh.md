## dsh-edge 0.28.0

支持上传非图片文件；Edge 自行处理的方法改用上游错误码；接入上游的 `/api/file` 路由；旧 spill 文件按有界方式清理。发布到稳定的 npm `latest` 渠道，变更与 [0.28.0-alpha.1](0.28.0-alpha.1.zh.md) 相同。上游基线仍为 0.2.1-rc.2，会话格式仍为 V4，所以从 0.27 升级不会迁移任何已存数据。

### 新增

- **文件上传**（#337，#356）：输入框现在可以添加任意文件，不再只限图片。文件流式发送到上游的上传路由，原样保存在工作区的 `/.dsh/attachments/v1/files/<prefix>/<digest>/<name>`。模型会被告知这个路径，并用文件工具读取；会话日志下载也包含这些文件。
  - 每个文件最多 64 MiB，上传必须声明长度，因此超限的文件在写入任何字节前就会被拒绝。
  - 通过上传路由发送的文件（输入框就是这样发送的），Worker 和 Durable Object 都不会把整个文件放进内存：字节按 512 KiB 分块写入和读回，经过时逐块计算哈希。base64 的 `fileUploads/upload` Remote 会在内存中解码文件，因此受 10 MiB 请求大小限制。
  - 上传凭证在 Durable Object 重启后仍然有效，所以输入中途停顿前上传的文件，发送消息时仍会被接受。
  - 已上传的文件对模型的写入和编辑工具只读。
- **对话中的工作区图片**（#347，#355）：上游的 `/api/file` 路由会返回消息里按路径引用的工作区文件，例如模型刚画的图表，内容从存储中流式读出。
- **每次升级基线时检查上游**（#340，#354）：上游对照检查现在也会比对 Edge 部分复用、替代或打补丁的每个包的 README 与类型声明，升级审查时也能看到这些包的变化。

### 修复

- **错误提示**（#344，#357）：Edge 自行处理的会话、工作区、设置、Agent 预设和凭据方法，现在返回上游的错误码与 details，Web 应用会为每种失败显示它自己的提示。例如，给纯文本模型发送图片时会显示"当前模型不支持图片"，而不是带错误码的英文原文；会话已创建但未挂到工作区时会被恢复，而不会被重复创建。
- **迟到的停止**（#357）：在回合刚结束时点"停止"，会像上游一样被接受，不再提示会话忙。
- **旧 spill 文件**（#338，#343）：保存在 `/workspace/.spill` 的长工具输出会在 30 天后删除。清理最多每天运行一次，若一轮尚未完成则每小时运行，每次写入的行数有上限。同名的两个 spill 不再互相覆盖。
- **用户提问与远程访问**（#339，#341）：注册了它们的上游 Remote，限时提问的回答和远程访问状态能够送达 Web 应用。
- **对照记录**（#336，#342）：根据源码审计修正了 27 个上游包的记录原因，README 写明了当前的缺口。

### 已知限制

- 工作区存储从不释放已删除或被覆盖文件的字节（#358）。spill 清理只会删除它们的条目，不会释放空间；上传中途中断时，已写入的分块会保留下来。
- 在 Linux Container 中运行的命令看不到已上传的文件；模型的文件工具和轻量 shell 可以看到。
- 另一个会话的回合正在运行时，向空闲会话上传会返回忙，和其他会话调用一样。
- shell 命令仍然可以修改已上传的文件；文件工具会拒绝修改，会话日志下载会发现被改过的副本。
- `glob` 和 `grep` 不应用 `.gitignore` 文件。
- 0.27.2 列出的其他限制仍然适用。

### 验证与升级

`pnpm run check` 通过 1,001 个测试。新测试覆盖：文件存储（按内容寻址、大小上限、写入失败或中止后的清理、读取时的完整性校验、上游的文件名规则）、只读保护、spill 清理及其在模拟 40 天中的补跑节奏，以及上游错误码。

集成测试在两个发布产物（Direct 与 Isolated）上运行。新增检查：
- 上传一个文本文件和一个生成的 3 MiB 文件、同名重传、base64 上传 Remote，以及拒绝缺失、超限和格式错误的上传；
- 模型按保存路径读取消息中的文件，以及会话导出逐字节包含这两个文件；
- 凭证在 Worker 两次重启后仍然有效，以及排队消息被移除时凭证随之作废；
- 两种 RPC 路由上的迟到停止。

真实 Chromium 中的浏览器快照通过输入框上传一个文本文件和一个 PDF，并检查给纯文本模型发图片时显示的本地化提示。

在 Workers 运行时中本地测得：
- `row-cost.probe.mjs` 对比 0.27.2：普通回合写入的行数相同（九个回合共 443 行 SQL、36 次 KV 与 alarm 写入）。第一个回合多一次 KV 写入，用于每日 spill 清理记录。
- `upload-cost.snapshot.mjs`：上传每 512 KiB 约写 5.3 行，所以一个 64 MiB 文件约 720 行；被拒绝的上传不写入任何行。
- `upgrade-from-release.probe.mjs` 升级由已发布的 0.27.2 和 0.18.0 创建的状态，各通过 11 项检查。

发布产物仍在 Cloudflare 的 64 MiB 大小限制内（Direct 8.3 MB，Isolated 9.6 MB），本地启动约 95 到 100 ms，Cloudflare 的限制为 1 s。

在一个从 0.27.2 升级到 0.28.0-alpha.1 的 staging 实例上（Isolated，带 Linux 容器）：
- 从输入框上传一个文本文件和一个生成的 3 MiB 文件；模型用 read 工具读出了文本文件里的标记，并报出了二进制文件的保存路径和准确长度，会话日志下载包含这两个文件；
- 停顿三分钟前上传的文件，在发送消息时仍被接受，Cloudflare 的分析数据显示实例在此期间进入了休眠；
- 给纯文本模型发图片时显示的是 Web 应用自己的提示，迟到的停止在两种 RPC 路由上都被接受；
- 模型写入工作区的 SVG 图表通过 `/api/file` 显示在对话中；
- Cloudflare 对该实例 Durable Object 的分析数据显示没有 CPU、内存或内部错误，整个测试共写入 542 行、读取 2,989 行。

用 `npx dsh-edge@latest upgrade` 升级并选择"Update it"，然后刷新页面。Web 页面会立即更新，但升级后它背后的实例可能还会运行旧版本几分钟。
