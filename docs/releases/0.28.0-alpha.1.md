## dsh-edge 0.28.0-alpha.1

Non-image file uploads, upstream error codes for the methods the Edge serves itself, upstream's `/api/file` route, and bounded cleanup of old spill files. Published to npm's `next` channel; `latest` remains on 0.27.2. The upstream baseline stays 0.2.1-rc.2 and the session format stays V4, so upgrading from 0.27 migrates no stored data.

### Added

- **File uploads** (#337, #356): the chat box now accepts any file, not only images. Files stream to upstream's upload route and are stored verbatim in the workspace at `/.dsh/attachments/v1/files/<prefix>/<digest>/<name>`. The model is told that path and reads the file with its file tools; the session log download includes the files.
  - Files are limited to 64 MiB each, and an upload must declare its length, so a larger one is refused before any byte is stored.
  - A file sent through the upload route (as the chat box does) is never held whole in memory by the Worker or the Durable Object: bytes are written and read back in 512 KiB chunks, hashed as they pass. The base64 `fileUploads/upload` Remote decodes its file in memory, so it is limited to the 10 MiB request size.
  - An upload's receipt survives a Durable Object restart, so a file uploaded before a pause in typing is still accepted when the message is sent.
  - Uploaded files are read-only to the model's write and edit tools.
- **Workspace images in chat** (#347, #355): upstream's `/api/file` route serves a workspace file a message names by path, such as a chart the model just drew, streamed from storage.
- **Upstream review at each baseline** (#340, #354): the upstream parity check now also compares the README and type declarations of every package the Edge partly serves, replaces, or patches, so an upgrade review sees changes to those packages too.

### Fixed

- **Error messages** (#344, #357): the session, workspace, settings, agent preset, and credential methods the Edge serves itself now answer with upstream's error codes and details, so the Web app shows its own message for each failure. For example, sending an image to a text-only model shows "The current model does not support images" instead of raw English with a code, and a session created but not attached to its workspace is recovered instead of created twice.
- **Late Stop** (#357): pressing Stop just as a turn ends is accepted, as upstream does, instead of reporting the session as busy.
- **Old spill files** (#338, #343): long tool output saved under `/workspace/.spill` is deleted after 30 days. The sweep runs at most once a day, or hourly while a pass is unfinished, with a bound on rows written per run. Two spills with the same name no longer replace each other.
- **User questions and remote access** (#339, #341): their upstream Remotes are registered, so a timed question's answer and remote-access status reach the Web app.
- **Parity records** (#336, #342): the recorded reason for 27 upstream packages was corrected from a source audit, and the README states the current gaps.

### Known limitations

- The workspace storage never frees the bytes of a deleted or overwritten file (#358). Spill cleanup frees their entries but not their space, and an upload interrupted midway keeps the chunks it already wrote.
- Commands that run in a Linux Container do not see uploaded files; the model's file tools and the lightweight shell do.
- Uploading to an idle session while another session's turn runs answers busy, as other session calls do.
- A shell command can still change an uploaded file; the file tools refuse to, and the session log download detects a changed copy.
- File uploads were tested locally and in the browser, not yet on a staging instance.
- `glob` and `grep` do not apply `.gitignore` files.
- The other limitations listed for 0.27.2 still hold.

### Validation and upgrade

`pnpm run check` passes 1,001 tests. New tests cover the file store (content addressing, the size limit, cleanup after a failed or aborted write, integrity checks on read, upstream's file-name rules), the read-only guard, the spill sweep and its catch-up cadence over a simulated 40 days, and the upstream error codes.

Integration runs against both release artifacts (Direct and Isolated). New checks:
- uploads of a text file and a generated 3 MiB file, a same-name re-upload, the base64 upload Remote, and refusals of missing, oversized, and malformed uploads;
- a prompt whose file the model reads by its saved path, and export of both files byte for byte;
- a receipt that survives two Worker restarts, and a receipt retired when its queued prompt is removed;
- late Stop on both RPC routes.

Browser snapshots in real Chromium upload a text file and a PDF through the chat box, and show the localized message for an image sent to a text-only model.

Measured locally in the Workers runtime:
- `row-cost.probe.mjs` against 0.27.2: plain turns write the same rows (443 SQL rows and 36 KV and alarm writes over nine turns). The first turn adds one KV write, for the daily spill-sweep record.
- `upload-cost.snapshot.mjs`: an upload writes about 5.3 rows per 512 KiB, so a 64 MiB file is about 720 rows; a refused upload writes none.
- `upgrade-from-release.probe.mjs` upgrades state created by the published 0.27.2 and 0.18.0, passing 11 checks each.

The release artifacts stay within Cloudflare's 64 MiB size limit (Direct 8.3 MB, Isolated 9.6 MB), and their startup takes about 95 to 100 ms locally, against Cloudflare's 1 s limit. Not yet validated on a staging instance.

Upgrade a test instance with `npx dsh-edge@next upgrade` and choose "Update it".
