## dsh-edge 0.16.0

Promotes the MCP Connectors runtime from 0.16.0-alpha.1 to the stable npm `latest` channel. The upstream Harness baseline remains 0.1.5-rc.2.

### Changed since 0.15.1

- **MCP Connectors** (#186, #189, #191–#203): connect external MCP tool servers to your Edge agent via Streamable HTTP transport. Edge uses a purpose-built `edge-mcp-client` with `@modelcontextprotocol/sdk@1.30.0` — the upstream `dsh-mcp-client` is replaced because its stdio transport and subprocess `inject` requirements are incompatible with Workers. Tools are discovered via paginated `tools/list`, registered on `ctx.tools`, and appear identically to built-in tools.
- **Authentication** (#189, #199): three auth modes — `none`, `bearer` (token stored via `CredentialProvider`), and `oauth` (OAuth 2.1 with PKCE, Dynamic Client Registration, RFC 9728/8414 path-aware discovery, automatic token refresh).
- **Tool policy** (#192, #193): per-connector policy — `allow_all`, `read_only` (default), `approve_all` — with `readOnlyHint` annotation support and glob-based auto-allow patterns.
- **Tool approval** (#185): Edge-owned `tools/pre-execute` waterfall gates `web_fetch`, `mcp__*` tools, and `mcp_call`. Settings UI toggles between `ask` and `never`. Per-connector MCP policy is consulted independently of the global mode.
- **SSRF protection** (#194, #195, #199, #205): private IPv4/IPv6 ranges, IPv4-mapped IPv6 (`::ffff:<private>`), FQDN trailing-dot normalization, and `.internal`/`.local`/`.localhost` hostnames are blocked; `localhost`/`127.0.0.1`/`::1` are allowed for development. HTTP redirects are blocked. JSON Schema validation uses `@cfworker/json-schema`.
- **Meta-tool mode** (#202): when total MCP tools exceed 20 at session startup, Edge registers `mcp_search` + `mcp_call` instead of individual tools, with a server summary in the system prompt.
- **MCP result handling** (#197, #198): `outputSchema`, `structuredContent`, and image projection (PNG/JPEG via attachment pipeline) from the MCP 2025-03-26 spec.
- **Hot-swap** (#191): re-probing a server replaces tool registrations without restarting the session or DO. Stale meta-tool entries are purged on dispose and re-probe.
- **Settings UI** (#200, #201): independent "MCP Connectors" tab for server management, tool lists, auth, per-connector policy, and OAuth connect flow.
- **Storage** (#203, #205): per-server tool catalog keys with memory cache, byte-accurate 128 KB catalog cap with trim loop, and transparent migration from the embedded format.

### Fixed since alpha.1

- **SSRF hardening** (#205): block IPv4-mapped IPv6 addresses in both dotted and URL-parsed hex forms; widen link-local coverage to full fe80::/10; normalize FQDN trailing dots before suffix checks.
- **Catalog cap** (#205): switch from UTF-16 string length to `TextEncoder` byte length; add trim loop and single-entry schema strip fallback so the 128 KB limit holds for CJK content.
- **Meta-tool cleanup** (#205): purge stale `toolMeta` entries on server dispose and re-probe so renamed/removed tools are immediately rejected by `mcp_call`.

### Validation and upgrade

Alpha.1 passed 478 tests, typecheck, and six rounds of automated code review. The stable release retains that runtime with the review-driven hardening fixes above.

Upgrade with `npx dsh-edge@latest upgrade`. Existing alpha deployments should use `@latest` to switch to the stable channel. This release introduces no new storage schema or migration beyond what alpha.1 established.
