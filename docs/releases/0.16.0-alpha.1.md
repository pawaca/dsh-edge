## dsh-edge 0.16.0-alpha.1

First preview of MCP Connectors — connect external MCP tool servers to your Edge agent. Published to npm's `next` channel; `latest` remains on 0.15.1. Use this alpha on a test instance before upgrading a primary deployment. The upstream Harness baseline remains 0.1.5-rc.2.

### Added

- **MCP client** (#186, #189): connect to external MCP servers via Streamable HTTP transport. Edge replaces the upstream `dsh-mcp-client` with a purpose-built `edge-mcp-client` using `@modelcontextprotocol/sdk@1.30.0` directly — the upstream plugin's stdio-only transport and subprocess `inject` requirements are incompatible with Workers. Tools are discovered via `tools/list` pagination (up to 128 per server, 10 pages) and registered on `ctx.tools` so the model sees them identically to built-in tools. Config-time probe + per-call connect; no persistent connections.
- **Authentication** (#189, #199): three auth modes — `none`, `bearer` (token stored via `CredentialProvider`, never in MCP config), and `oauth` (OAuth 2.1 with PKCE, Dynamic Client Registration, RFC 9728 Protected Resource Metadata + RFC 8414 Authorization Server Metadata path-aware discovery, automatic token refresh at 120s skew).
- **Tool policy** (#192, #193): per-connector policy — `allow_all`, `read_only` (default), `approve_all`. `read_only` auto-allows tools with `readOnlyHint: true` annotations or names matching `get_*`, `list_*`, `read_*`, `search_*`, `find_*`, `fetch_*`, `describe_*`; everything else prompts for approval.
- **Tool approval** (#185): Edge-owned `tools/pre-execute` waterfall gates `web_fetch`, all `mcp__*` tools, and `mcp_call`. Settings UI toggles between `ask` (prompt before external calls) and `never` (trust all). Per-connector MCP policy is consulted independently of the global mode.
- **SSRF protection** (#194, #195, #199): private IPv4/IPv6 ranges and `.internal`/`.local`/`.localhost` hostnames are blocked; `localhost`/`127.0.0.1`/`::1` are explicitly allowed for local development. HTTP redirects are blocked. JSON Schema validation uses `@cfworker/json-schema` (Workers-compatible, no `eval`).
- **Meta-tool mode** (#202): when total registered MCP tools exceed 20, Edge switches to two meta-tools — `mcp_search` (keyword search across all servers) and `mcp_call` (invoke by qualified name) — instead of registering each tool individually. The system prompt is extended with a server summary when meta-tool mode is active.
- **MCP result handling** (#197, #198): `outputSchema` and `structuredContent` from the MCP 2025-03-26 spec are forwarded when the schema passes the DSH-supported JSON Schema subset. Image content blocks (PNG/JPEG) are projected through the attachment pipeline when the active model supports image input.
- **Hot-swap** (#191): re-probing a server replaces its tool registrations without restarting the session or DO.
- **Settings UI** (#200, #201): independent "MCP Connectors" tab in Edge Settings for adding, removing, probing servers, viewing tool lists, setting auth, and choosing per-connector policy. OAuth connect flow launches from the UI.
- **Storage** (#203): tool catalogs are stored in per-server DO storage keys (`dsh-edge:mcp-tools:<name>`) with an in-memory cache, split from the server config key to avoid re-serializing entire catalogs on config writes. Old embedded-format entries are migrated transparently.

### Limits

| Limit | Value |
|---|---|
| Tools per server | 128 |
| Catalog pages | 10 |
| Catalog size | 128 KB |
| Description length | 512 chars |
| Public tool name | 64 chars |
| Server instructions | 1024 chars |
| Probe timeout | 30 s |
| Call timeout | 60 s |
| Meta-tool threshold | 20 total tools |

### HTTP API

| Method | Path | Purpose |
|---|---|---|
| GET | `/api/mcp-servers` | List configured servers |
| PUT | `/api/mcp-servers` | Save server configurations |
| PUT | `/api/mcp-servers/:name/token` | Store bearer token |
| DELETE | `/api/mcp-servers/:name/token` | Clear bearer token |
| POST | `/api/mcp-servers/:name/probe` | Probe server and refresh tools |
| GET | `/api/mcp-servers/:name/tools` | List cached tools |
| POST | `/api/mcp/oauth/start` | Start OAuth flow |
| POST | `/api/mcp/oauth/complete` | Complete OAuth code exchange |
| GET/PUT | `/api/approval-mode` | Read/write global approval mode |

### Validation

Run `pnpm run check` and both Worker-mode integration tests before deploying. Browser and snapshot coverage should be verified on a test instance. MCP tool discovery and invocation require a reachable Streamable HTTP MCP server.

Sustained operation with connected MCP servers and OAuth token lifecycle remain part of alpha evaluation before the stable 0.16.0 release.
