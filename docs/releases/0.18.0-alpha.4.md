## dsh-edge 0.18.0-alpha.4

Two fixes found while testing 0.18.0-alpha.3 by hand: the owner can now choose the preset and the model new sessions start on. Published to npm's `next` channel; `latest` remains on 0.17.0. The upstream Harness baseline remains 0.1.5-rc.2. Everything in [0.18.0-alpha.3](0.18.0-alpha.3.md), [0.18.0-alpha.2](0.18.0-alpha.2.md), and [0.18.0-alpha.1](0.18.0-alpha.1.md) still applies.

### Fixed

- **Default agent preset** (#240): choosing a preset in Settings → Agent presets showed `settings namespace "agent-presets" is not registered`, and new sessions always started in Standard mode.
  - The choice now works as upstream: new sessions start on the chosen preset, and the "In use" badge follows it.
  - Only presets the deployment offers can be chosen. If a deployment later stops offering PTC mode, a stored PTC default reads as Standard mode.
- **Default model** (#240): new sessions always started on DeepSeek-V4-Flash, whatever the owner had chosen before.
  - As upstream, the latest model chosen in any session is where new sessions start.
  - `DEEPSEEK_MODEL` (default `deepseek-v4-flash`) applies until the owner first chooses a model.
  - If saving the choice fails, the previous default is kept.

### Known limitations

- The deployment default stays DeepSeek-V4-Flash. Upstream notes that DeepSeek-V41-Flash (`deepseek-flash`) can fail until the DeepSeek API enables it, so switching to it is left to the owner.
- Everything listed for 0.18.0-alpha.3 still holds.

### Validation and upgrade

`pnpm run check` passes 778 tests. Integration runs against both release artifacts:
- After a model is chosen in one session, a new session reports that model.
- On the isolated build, choosing PTC mode as the default moves the "In use" mark, and a new session starts in PTC mode.

Upgrade a test instance with `npx dsh-edge@next upgrade` and choose "Update it". This release adds no storage migration; the default preset is stored in the existing settings document.
