## dsh-edge 0.18.0-alpha.2

修复手动测试 0.18.0-alpha.1 时发现的问题：容器命令遇到非 UTF-8 输出不再整条失败；工具默认改为普通调用，`run_code` 改为可选预设；系统提示词现在会告诉模型当前日期、工作目录，以及所在档位能做什么。本版发布至 npm 的 `next` 频道，`latest` 仍为 0.17.0。上游 Harness 基线保持 0.1.5-rc.2。[0.18.0-alpha.1](0.18.0-alpha.1.zh.md) 的内容仍然适用。

### 修复

- **非 UTF-8 命令输出**（#233）：容器里的程序输出的是原始字节。修复前，下面任何一种情况都会让整条命令以"shell output was not valid UTF-8"失败：
  - GBK 编码的网页；
  - 二进制文件；
  - `head -c` 在输出中间切断了一个中文字符。

  现在像终端一样解码：无法解码的字节显示为 `�`，命令照常返回真实结果。
- **容器清理命令**（#231）：离开 Container 模式后，安装器会查出保留下来的 Container application 的 id，打印可直接运行的 `npx wrangler containers delete <id>`。

### 变更

- **默认普通工具调用，PTC 模式改为可选**（#235）：自 0.17.0 起，付费部署同时提供普通工具和 `run_code`，模型因此把大多数步骤（连单条 bash 命令）都包成一段程序。现在所有部署默认使用普通工具调用，和上游一致。
  - 付费部署的新建会话预设选择器里多了上游的 **PTC 模式**（`ptc`，程序化工具调用）。选了它的会话只使用 `run_code`，由程序调用其他工具，适合批量处理。
  - 与上游一致，PTC 模式不提供 `workflow`；默认预设照常可用。
  - 预设在会话第一轮之前选择，之后锁定。
  - 已有会话保持默认预设，改用普通工具继续；历史中的 `run_code` 记录照常回放。
- **系统提示词**（#236）：
  - 写明工作目录。
  - 免费档写明轻量 shell 能做什么；任务需要 git、node、python 或网络时，引导用户添加"Work on code projects"。
  - bash 指引要求检查退出码，并写明超时上限。alpha.1 测试中，模型两次超过了这个未说明的上限。
  - 容器部署提示读网页用 `web_fetch`，不要用 `curl`。
  - plan mode 采用上游规则。
  - 去掉了泛泛的"powered by DeepSeek Harness"开头。
- **当前日期**（#236）：模型现在知道所有者时区下的今天日期。时区随每条消息从浏览器带来，每个实例存一份，只在变化时写入。日期以一条简短的上下文消息送达，只在日期变化时出现，每个会话每天最多一条，不影响缓存的提示词前缀。会话搜索会忽略这类消息。
- **安装器文案**（#231）：提示在网页询问时填写 DeepSeek key，并说明容器默认 10 分钟的闲置时长可以在设置里调整。

### 已知限制

- 升级后，在所有者发出第一条新消息之前触发的提醒使用 UTC 日期。午夜前后可能差一天，下一条消息之后会永久纠正。
- 0.18.0-alpha.1 列出的限制仍然存在：Node 22 测试失败、本地 `dev:container` 残留容器、符号链接不在分流范围内。

### 验证与升级

`pnpm run check` 通过 774 个测试。集成测试针对两种发布产物运行。在 isolated 测试中，默认会话不提供 `run_code`，PTC 会话只提供 `run_code`，能运行程序，并在之后锁定预设。Container 集成测试在 CI 中运行，包括真实的 GBK 和 `head -c` 输出。定时提醒探测确认：Worker 重启后触发的提醒仍然使用所有者的时区。

用 `npx dsh-edge@next upgrade` 升级测试实例，选择"Update it"。本版没有存储迁移。新增两项存储：会话的预设选择记录在会话头中，所有者时区存在一个 Durable Object 键中。
