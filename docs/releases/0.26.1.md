## dsh-edge 0.26.1

Two fixes found in a source review of the Edge's upstream parity decisions. Published to the stable npm `latest` channel. The upstream Harness baseline stays 0.2.0-rc.2 and the session format stays V4, so upgrading from 0.26.0 or 0.24 migrates no stored data. Upgrading from 0.18 still moves sessions to V4 as described in [0.19.0](0.19.0.md).

There is no 0.25: version numbers follow release order, and that number was mistakenly held back for the move to the upstream 0.2.1 baseline. The 0.26.0 notes now say so.

### Fixed

- **Failed commands shown as succeeded** (#306): in deployments with the Linux container, a command that failed in the container showed as succeeded in the chat's terminal card. So did a failing command the lightweight shell could not finish, and a cancelled command that had not stopped yet. The Edge wrote its note about where the command ran after the exit status, and the Web client reads the exit status only from the last line. The exit status now comes last, as in upstream.
- **Out-of-date agent instructions** (#307): the instructions the Edge gives the model had not kept up with 0.24 and 0.26.
  - They now name the model the session runs on, as upstream's presets do, so a model from another provider knows which model it is. Switching a session's model changes the instructions from the next step on.
  - They no longer tell the model to track subagents with job tools; since 0.24 it manages them with `list_agents`, `send_message`, and `interrupt_agent`.
  - A subagent now gets upstream's note that it was delegated and that operations needing approval are rejected automatically, so it reports the limitation instead of retrying. Subagents also get the current date, and every session gets upstream's note on its approval policy.

### Known limitations

- To keep credentials out of the settings, which are stored in plain text:
  - each provider must name its own API key, and the name may not be one that belongs to DeepSeek or another Edge feature (`DEEPSEEK_*`, `MCP_TOKEN_*`, `DSH_EDGE_*`);
  - a Base URL may not contain credentials, a query, or a fragment;
  - extra headers are limited to `HTTP-Referer`, `Referer`, `X-Title`, `OpenAI-Organization`, `OpenAI-Project`, and `anthropic-beta`, so a gateway that needs a second credential header (such as an authenticated Cloudflare AI Gateway's `cf-aig-authorization`) cannot be configured yet.
- Providers that sign in through a local login or read local credential files are not offered: GitHub Copilot, OpenAI Codex, and Amazon Bedrock or Google Vertex through local credentials.
- Session titles are still generated with DeepSeek.
- Images sent to a subagent from the subagent panel are not verified on the Edge.
- Up to 8 subagents can stay loaded at once (upstream's default, changeable on the Subagent card). Model requests beyond the Workers limit of six simultaneous connections wait for a free connection.
- Upstream's turn outline (each turn's prompt and response preview) is not offered: it grows with every turn, and the Edge stores a session's cached values as one record, so a long session would outgrow it.
- Upstream's `/feedback` command is not offered: it keeps an anonymous user id in a local file, which Workers cannot store.
- `glob` and `grep` do not apply `.gitignore` files, so `grep` searches ignored files that ripgrep would skip.
- File write protection covers the `write` and `edit` tools. A shell or container command that writes a file during a guarded write is not detected, as in upstream; one that finished before the guarded write is.
- Rolling back to 0.18 after an upgrade from it is not supported.
- The Agent presets page intro and mode guide mention upstream's Creator mode, which the Edge does not offer.
- The 0.18.0 limitations about the Node 22 test environment, local `dev:container` cleanup, and symlinks outside `/workspace` still hold.


### Validation and upgrade

`pnpm run check` passes 912 tests, with a unit test that parses the rendered bash result the way the Web client does. Integration runs against both release artifacts (Direct and Isolated); it now checks that a background subagent's first request carries the delegation note, the approval note, and the date, and that both the parent's and the child's instructions name a model. The packed installer passes `pack:verify`. `upgrade-from-release.probe.mjs` upgrades state created by the published 0.26.0, 0.24.0, and 0.18.0, passing 11 checks each.

Upgrade with `npx dsh-edge@latest upgrade` and choose "Update it", then reload the page. The Web page updates at once, but the instance behind it may keep running the previous version for a few minutes after an upgrade, so fixes in the instance can take a little longer to apply.
