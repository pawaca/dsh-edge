## dsh-edge 0.21.0-alpha.2

为 agent 加入了三项上游 Harness 能力（#234）：任务列表、`AGENTS.md` 说明，以及 `glob` 和 `grep` 搜索工具。本版发布至 npm 的 `next` 频道，`latest` 仍为 0.20.0。这是这些变更首次发布：[0.21.0-alpha.1](0.21.0-alpha.1.zh.md) 已打 tag，但其发布流程在发布到 npm 之前停止（见“验证与升级”）。上游 Harness 基线仍为 0.2.0-rc.2，会话格式仍为 V4，所以从 0.20 升级不会迁移任何已存数据。

### 新增

- **任务列表**（#268）：agent 用上游的 `todo_write` 工具维护会话的任务列表，Web 客户端在待办面板中显示它。每次更新都会替换整个列表；可以有多个任务同时进行，因为子 agent、后台命令和 workflow 会并行工作。
- **`AGENTS.md` 说明**（#269）：在第一次请求之前，agent 会收到从项目根目录到会话工作目录逐级的 `AGENTS.md` 和 `CLAUDE.md` 文件（以及它们的 `.local.md` 覆盖文件），从工作区读取。项目根目录是最近一个包含 `.git` 的目录，没有则为工作目录。当 `read`、`write` 或 `edit` 进入更深的目录时，该目录的说明会加入下一次请求。用户全局文件是 `/.dsh/AGENTS.md`，因为 Workers 没有用户主目录。
- **`glob` 和 `grep`**（#270）：agent 用上游的 `glob`（文件路径，最旧的在前）和 `grep`（按文件分组的匹配行）搜索工作区，而不是 shell 的 `find` 和 `grep`。超过 100 条路径或 250 条匹配的结果会另存为文件，agent 可以读取。Workers 无法运行上游使用的 ripgrep 程序，所以 Edge 在工作区上运行同样的工具：
  - `grep` 的正则使用 RE2 语法，以线性时间匹配，所以病态正则不会卡住实例。RE2 不支持环视和反向引用，与 ripgrep 的默认引擎一样。
  - 两者都跳过 `.git` 等版本控制目录；`grep` 还跳过隐藏文件、二进制文件和超过 4 MiB 的文件。
  - 结果中的路径相对于会话工作目录，即使该目录写成 `/workspace/./project` 或带结尾的 `/`（#272）。
  - 一次搜索最多遍历 20,000 个条目，`grep` 最多保留 20,000 行匹配或 20 MB 文本；超出上限时搜索会失败，并提示缩小路径或模式。搜索会在 30 秒的工具超时时停止。

### 已知限制

- `glob` 和 `grep` 不应用 `.gitignore` 文件，所以 `grep` 会搜索 ripgrep 本会跳过的被忽略文件。
- 文件写入保护只覆盖 `write` 和 `edit` 工具。在受保护的写入进行期间，由 shell 或容器命令写入的文件改动不会被发现，这与上游一致；在受保护的写入之前已完成的改动会被发现。
- 从 0.18 升级后不支持退回 0.18。
- 0.18 的插件配置卡片（Agent loop、Web search）移到了上游插件管理器中，Edge 没有提供插件管理器。
- Agent 预设页的介绍和模式说明提到了上游的 Creator 模式，Edge 不提供该模式。
- 0.18.0 中关于 Node 22 测试环境、本地 `dev:container` 清理以及指向 `/workspace` 之外的符号链接的限制仍然存在。

### 验证与升级

0.21.0-alpha.1 的发布流程在 Windows 单元测试处失败：搜索工具用主机的路径模块拼接结果路径，在 Windows 上会使用 `\`（#272）。已部署的 Worker 始终使用 `/`，从未受影响。现在路径在所有主机上都以同样方式生成，Edge CI 的 Windows 任务也像发布流程一样运行完整检查，所以这类失败会在打 tag 之前拦下。

`pnpm run check` 通过 874 个测试。集成测试覆盖两个发布产物（Direct 和 Isolated），新增了 `todo_write` 调用及其 `todos` projection、根目录和子目录的 `AGENTS.md` 说明，以及在工作区上调用 `grep` 和 `glob` 的检查，其中包括一次超出上限、完整结果被另存的 `grep`。单元测试覆盖了搜索工具的 glob 规则、RE2 正则和各项上限。打包后的安装器通过 `pack:verify`。`upgrade-from-release.probe.mjs` 分别升级由已发布的 0.20.0 和 0.18.0 创建的数据，各通过 11 项检查。

用 `npx dsh-edge@next upgrade` 升级测试实例，选择"Update it"。
