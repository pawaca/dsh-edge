## dsh-edge 0.27.0-alpha.1

升级到上游 DeepSeek Harness 0.2.1-rc.2 基线，并带来上游的自动化任务页、会话日志下载、轮次大纲和 `/feedback`。发布到 npm 的 `next` 渠道；`latest` 仍为 0.26.1。会话格式仍为 V4，所以从 0.26 升级不会迁移任何已存数据。

### 新增

- **上游基线 0.2.1-rc.2**（#324）：所有上游包从 0.2.0-rc.2 升级到 0.2.1-rc.2。
  - 模型获得上游的 `working_directory` 工具，可以读取和修改会话的工作目录，每次提问时也会被告知当前目录。
  - 上游的时间上下文会按浏览器的时区告诉模型当前时间，最多每 10 分钟一次。没有浏览器参与时（已送达的提醒、HTTP 轮次 API），它会说明时区未知。
  - 所有子代理都可以继续对话；`subagent` 工具不再接受 `run_in_background`，新增 `cwd`。
  - Web 应用会遮盖消息中形如 `sk-…` 的密钥文本（#326）。遮盖只影响显示：保存的消息和模型收到的请求仍是原文。
  - DeepSeek V4.1 Flash 模型显示上游的 `1017` 标签。
- **自动化任务页**（#329）：侧边栏中上游的这个页面会列出每条提醒及其会话和状态，可以修改提醒的名称、指令和时间，删除提醒，并查看它的每次送达记录。提醒被创建、修改、删除或送达时，列表会自动刷新。
  - 每条提醒保留 30 天内最新的 200 条送达记录，与上游相同，删除提醒时一并删除。本版之前创建的提醒，其更早的送达记录显示为不可用。
- **会话日志下载**（#318、#328）：会话标题栏的“Download session log”菜单项和 `/export` 命令会下载上游格式的会话归档，包括其子代理会话。Edge 一边压缩一边分页读取日志，所以长会话不再需要整个放进内存，也没有大小上限。
- **DeepSeek 搜索与抓取 API**（#327）：网页搜索卡片可以把网页搜索和抓取切换到 DeepSeek 自己的 API，使用 Models 页面里的 DeepSeek 密钥。之后由 DeepSeek 抓取网页，Worker 不再自己读取第三方网页。该开关默认关闭，因为这些 API 可能与模型 token 分开计费。
- **轮次大纲**（#312）：聊天视图的轮次列表，来自上游的轮次大纲。
- **`/feedback`**（#310）：上游的命令和会话反馈对话框会把反馈记录到会话中。
- **Harness shell 变量**（#311）：bash 命令能看到 `DSH_SHELL=1`、`DSH_SESSION_ID` 和 `DSH_HOME=/.dsh`。Worker 的密钥和绑定不会进入命令。

### 修复

- **冷启动后列表中的会话缓存信息**（#315）：重启后尚未加载的会话，现在在会话列表中也会显示缓存的信息（统计、目标、待办、模型）。之前要打开会话后才会出现。
- **更小的会话缓存存储**（#316）：随对话增长的缓存值改为从会话日志重建，不再存储。一个 600 轮的会话，存储的缓存从 90 KB 降到 2 KB，每次 Durable Object 启动要加载的数据也随之减少。

### 已知限制

- 不支持回退到 0.26：如果 0.27 在某个会话中记录了工作目录变更，0.26 就无法读取该会话。
- 新实例在设置 DeepSeek 密钥之前不会列出任何模型（上游变更）。
- DeepSeek 搜索与抓取 API 只用替身服务测试过，尚未对 `api.deepseek.com` 实测。
- 自动化任务页允许编辑子代理会话的提醒，而上游会拒绝。模型的工具已经拒绝为子代理创建提醒，所以实际上不存在这类提醒。
- 尚未在 Edge 上确认：会话侧边栏和标题栏是否会为有活动提醒的会话显示标识。
- 暂不提供上游的会话搜索工具（`dsh-tool-session-query`）。
- 为了不让凭据进入以明文存储的设置：服务商 API 密钥名不能属于 DeepSeek 或其他 Edge 功能（`DEEPSEEK_*`、`MCP_TOKEN_*`、`DSH_EDGE_*`）；Base URL 不能包含凭据、查询参数或片段；额外请求头仅限白名单，因此还无法配置需要第二个凭据请求头的网关。
- 不提供通过本地登录或读取本地凭据文件接入的服务商。
- 会话标题仍由 DeepSeek 生成。
- `glob` 和 `grep` 不应用 `.gitignore` 文件。
- 从 0.18 升级后不支持回退到 0.18。
- Agent presets 页面的介绍和模式指南提到了上游的 Creator 模式，Edge 不提供该模式。
- 0.18.0 中关于 Node 22 测试环境、本地 `dev:container` 清理和 `/workspace` 之外符号链接的限制仍然存在。

### 验证与升级

`pnpm run check` 通过 979 个测试，新增的单元测试覆盖：会话日志导出器（归档与上游逐项一致；导出期间日志被改写时导出会失败，而不会混入不同轮次）、提醒送达记录及其上限、自动化任务服务、DeepSeek 搜索与抓取服务商，以及轮次大纲的大小。

集成测试针对两种发布产物（Direct 和 Isolated）运行，新增检查：下载 4.4 MiB 的会话日志、真实提醒送达后通过网关调用自动化任务服务、`/feedback`、shell 变量，以及冷启动列表中的缓存信息。真实 Chromium 中的浏览器快照覆盖了提醒送达后的自动化任务页，以及形如密钥的消息的遮盖。

在本地 Workers 运行时中测得：
- `upgrade-from-release.probe.mjs` 原地升级由已发布的 0.26.1 和 0.18.0 创建的状态，各通过 11 项检查。
- 针对 0.26.1 的 `row-cost.probe.mjs`：普通轮次写入的行数相同（九个轮次共 443 个 SQL 行、36 次 KV 和闹钟写入）；第一轮多写 2 行，用于时间上下文。每条送达的提醒多写 1 行，用于它的送达记录。
- 下载一个 408 个事件的会话日志，每个事件约读取 1.06 行，不写入任何行。

发布产物都在 Cloudflare 64 MiB 的大小限制之内（Direct 8.1 MB，Isolated 9.5 MB），本地启动约 95 到 120 ms，Cloudflare 的限制为 1 s。尚未在预发布实例上验证。

使用 `npx dsh-edge@next upgrade` 升级测试实例，并选择“Update it”。
