## dsh-edge 0.14.1

Durable session write batching for streamed and background-agent workloads. The upstream baseline remains 0.1.2-rc.1.

### Fixed

- **Durable Object write amplification** (#170): stop forcing one persistence flush for every streamed session event. Events now share the upstream 200 ms write-behind window, allowing consecutive assistant chunks to be packed into one physical event row instead of consuming several Durable Object row writes per token chunk.
- **Durable-before-visible delivery** (#170): publish WebSocket events only after their batch is durable while preserving sequence order across idle mutations, renames, active turns, background subagents, and detached session lifecycles.
- **Mux replay/live boundary** (#170): stabilize all pending delivery queues before registering a multiplexed event socket, including queues from cold sessions that have already detached. New subscribers no longer receive delayed events at or below their advertised `lastSeq` baseline.
- **Delivery failure isolation** (#170): keep a failed per-session delivery barrier terminal so a later batch or replacement session lifecycle cannot publish higher sequence events past a missing durable event.

### Validation

- Added focused queue and physical SQLite packing coverage plus Direct and Dynamic Loader release-artifact integration. A 100-chunk streamed response persists as one packed `text-chunks` row while retaining the exact ordered WebSocket and history surfaces.
