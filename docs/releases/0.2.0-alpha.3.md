# dsh-edge 0.2.0-alpha.3

English | [中文](https://github.com/pawaca/dsh-edge/blob/dsh-edge-v0.2.0-alpha.3/docs/releases/0.2.0-alpha.3.zh.md)

This prerelease upgrades the complete published DeepSeek Harness baseline from `0.1.0-rc.7` to `0.1.0-rc.8`. It is intentionally a compatibility release: the Cloudflare runtime, single-owner authentication model, public routes, and Durable Object schema remain unchanged.

## Highlights

- Preserves a visible assistant text or reasoning prefix when a live turn is cancelled, using rc.8's canonical `assistant/message` interruption marker. The Edge persistence adapter round-trips that marker through cold Durable Object storage.
- Adopts rc.8's bounded multi-query Web Search flow and its provider-side concurrency while retaining dsh-edge's request-scoped DeepSeek credential handling.
- Adopts DeepSeek reasoning-continuation fixes and the unified five-retry provider default from the upstream runtime.
- Moves with rc.8's client renderer and slot-based Harness branding composition while keeping the dsh-edge deployment and owner-session page as a separate community-owned plugin.
- Reports `/workspace` through the new upstream host-home contract and uses the upstream DeepSeek request-image bound internally, without advertising image input in Edge.

## Install or upgrade the prerelease

Requires Node.js 22.14 or newer and your own DeepSeek API key.

```sh
npx dsh-edge@next install
```

Existing prerelease deployments can upgrade in place:

```sh
npx dsh-edge@next upgrade
```

The `next` dist-tag moves to alpha.3 while `latest` remains on 0.1.3. Cloudflare's write-only secret behavior still requires entering the existing owner access key and DeepSeek API key during an upgrade.

## Scope and compatibility

Every published Harness package is pinned to the exact `0.1.0-rc.8` baseline. The same six audited, version-bound Edge adaptations were rebased; no new upstream patch was added. The assembled Web graph adopts the required renderer and official Harness brand plugins. The new attachment/image and `@file`/`@session` reference plugins are deliberately excluded because the corresponding host capabilities are not yet available on Edge.

The rc.8 Node SQLite schema 17 layout is not the storage format used by dsh-edge. Durable Object session storage remains on Edge schema v2, so this release performs no data migration and preserves the existing 0.1.3 rollback boundary. Direct Shell and Dynamic Worker modes remain behaviorally aligned.

Session export, attachments and images, remote MCP, Skills, Workflows, Jobs, and Subagents remain deferred for the post-alpha.3 ROI review. `web_fetch` remains disabled pending an explicit network-access policy.

## Release integrity

The npm package is published under the `next` dist-tag from the reviewed `dsh-edge-v0.2.0-alpha.3` tag. The release workflow verifies the exact tag and package version, rebuilds the deterministic rc.8 standalone assembly, exercises Direct and Dynamic Worker modes, checks 0.1.3 durable-state compatibility, runs browser/runtime snapshots, and installs the packed artifact outside the workspace before trusted publication. The matching GitHub prerelease carries the same tarball as an asset.
