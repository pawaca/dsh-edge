## dsh-edge 0.26.0

可以像上游 DeepSeek Harness 一样，在 Models 页面添加其他服务商的模型。本版发布至稳定的 npm `latest` 频道，变更与 [0.26.0-alpha.1](0.26.0-alpha.1.zh.md) 和 [0.26.0-alpha.2](0.26.0-alpha.2.zh.md) 相同。没有 0.25 版本：这个编号当初被误留给升级到上游 0.2.1 基线，今后也不会使用。本版仍基于 0.2.0-rc.2。会话格式仍为 V4，所以从 0.24 升级不会迁移任何已存数据。从 0.18 升级仍会按 [0.19.0](0.19.0.zh.md) 所述把会话迁移到 V4。

### 新增

- **其他模型服务商**（#300）："设置 → Models"现在可以通过上游的 `dsh-llm-pi-ai` 添加 DeepSeek 以外的服务商。
  - 服务商可以使用 OpenAI chat completions、OpenAI responses 或 Anthropic messages 协议，Base URL 可以是任意 HTTP(S) 地址。OpenRouter、Cloudflare Workers AI 或 AI Gateway、自建的 OpenAI 兼容网关等都可以接入。
  - 保存之前，页面可以列出端点提供的模型；也可以手动填写模型。
  - 服务商保存后立即可用，无需重启。它的模型会出现在模型菜单中，可以作为新会话的默认模型（与上游一样，即最近一次选择的模型），使用这些模型的会话所启动的子 agent 也会使用它们。
  - 每个服务商的 API key 在同一页面填写，由 credentials 服务保存在 Durable Object 存储中，不会写入设置。
  - DeepSeek 照常使用，包括以 Worker secret 提供的 `DEEPSEEK_API_KEY`。

### 修复

- **DeepSeek 设置立即生效**（#300）：在 Models 页面为 DeepSeek 保存的重试策略现在会作用于正在运行的实例。以前要等实例重启后才生效。
- **Web 客户端中的乱码**（#302）：部分文字显示为乱码，例如模型思考时的 `Deep diving for 14s Â·Â·Â·`，或 Agent presets 页面上的 `agentâ€™s`。页面的字符编码声明位置太靠后，浏览器找不到它，于是用错误的编码读取页面及其脚本，任何非英文文字（包括中文）都可能受影响。现在编码声明排在最前面。
- **设置默认 agent 预设**（#303）：在"设置 → Agent presets"中把某个预设设为新会话默认时，会报错 `settings namespace "agent-preset-registry" is not registered`。Edge 现在把这个选择保存在上游页面写入的位置。用早期版本选定的默认值会保留。

### 已知限制

- 设置以明文存储，为了不让凭据进入设置：
  - 每个服务商必须指定自己的 API key 名，且不能使用属于 DeepSeek 或其他 Edge 功能的名字（`DEEPSEEK_*`、`MCP_TOKEN_*`、`DSH_EDGE_*`）；
  - Base URL 不能包含账号密码、查询参数或片段；
  - 附加请求头只能是 `HTTP-Referer`、`Referer`、`X-Title`、`OpenAI-Organization`、`OpenAI-Project` 和 `anthropic-beta`，所以需要第二个认证头的网关（例如开启认证的 Cloudflare AI Gateway 所需的 `cf-aig-authorization`）暂时无法配置。
- 不提供通过本地登录或读取本地凭据文件认证的服务商：GitHub Copilot、OpenAI Codex，以及通过本地凭据使用的 Amazon Bedrock 或 Google Vertex。
- 会话标题仍由 DeepSeek 生成。
- 从子 agent 面板发给子 agent 的图片尚未在 Edge 上验证。
- 最多同时保持加载 8 个子 agent（上游默认值，可在子 agent 卡片中修改）。超出 Workers 六个并发连接上限的模型请求会等待空闲连接。
- 不提供上游的 turn 大纲（每个 turn 的提问与回答预览）：它随每个 turn 增长，而 Edge 把一个会话的缓存值存为一条记录，长会话会超出上限。
- 不提供上游的 `/feedback` 命令：它把匿名用户 id 保存在本地文件中，Workers 无法保存。
- `glob` 和 `grep` 不应用 `.gitignore` 文件，所以 `grep` 会搜索 ripgrep 会跳过的被忽略文件。
- 文件写入保护只覆盖 `write` 和 `edit` 工具。在受保护的写入进行期间由 shell 或容器命令写入的文件不会被发现，与上游一致；在受保护的写入之前已经完成的则会被发现。
- 从 0.18 升级后不支持退回 0.18。
- Agent 预设页的介绍和模式说明提到了上游的 Creator 模式，Edge 不提供该模式。
- 0.18.0 中关于 Node 22 测试环境、本地 `dev:container` 清理以及指向 `/workspace` 之外的符号链接的限制仍然存在。

### 验证与升级

`pnpm run check` 通过 912 个测试，新增的单元测试包括：
- 保存服务商后无需重启即可使用，重启后仍然保留；
- 拒绝带账号密码、查询参数或片段的 Base URL，拒绝白名单之外的请求头，拒绝缺少或使用保留名的 key 名，拒绝 DeepSeek 已占用的服务商 id；
- DeepSeek 的重试策略立即生效；
- 页面的编码声明排在最前面，以及早期版本保存的默认预设会被保留。

集成测试覆盖两个发布产物（Direct 和 Isolated），新增的检查包括：
- 列出草稿端点的模型；
- OpenAI 兼容和 Anthropic messages 两种服务商各用自己的 key 跑一个 turn；
- 子 agent 使用父 agent 的服务商运行；
- 最近一次选择的模型成为新会话的默认模型；
- 重启后服务商和 key 仍能正常运行 turn；
- 按 Agent presets 页面的方式把 PTC 模式设为默认。

独立构建检查会拒绝编码声明不在前 1024 字节内的 Web 页面。发布产物都在 Cloudflare 64 MiB 的体积上限之内（Direct 7.3 MB，Isolated 8.6 MB），本地启动耗时约 100 到 160 ms，Cloudflare 的上限是 1 秒。打包后的安装器通过 `pack:verify`。`upgrade-from-release.probe.mjs` 分别升级由已发布的 0.26.0-alpha.2、0.24.0 和 0.18.0 创建的数据，各通过 11 项检查。

在 staging 实例上：
- 使用 0.26.0-alpha.1，在 Models 页面添加了 Z.ai 服务商：能从端点列出它的模型，并能正常运行 turn；
- 使用 0.26.0-alpha.2，Web 客户端不再出现乱码，在 Agent presets 页面设置默认预设也成功了。

用 `npx dsh-edge@latest upgrade` 升级，选择"Update it"，然后刷新页面。Web 页面会立即更新，但升级后背后的实例可能还会运行旧版本几分钟，所以实例里的修复可能要稍后才生效。
