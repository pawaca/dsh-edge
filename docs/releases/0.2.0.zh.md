# dsh-edge 0.2.0

[English](https://github.com/pawaca/dsh-edge/blob/dsh-edge-v0.2.0/docs/releases/0.2.0.md) | 中文

该版本将 dsh-edge 确立为基于 DeepSeek Harness `0.1.0-rc.8` 已发布 package 的独立社区 wrapper。它保留 0.1.3 已发布的 Cloudflare runtime 与持久化数据约定，同时不再要求维护源码 fork 或 GitHub 构建流水线。

## 主要变化

- 直接从 npm 把个人 DeepSeek Harness 实例安装或升级到 Cloudflare 账户，无需克隆本仓库。
- Free Direct Shell 与付费 Dynamic Worker 两种模式使用相同的 Web UI、HTTP/WebSocket 协议、工具、认证和 Durable Object 存储。
- 对话与 `/workspace` 虚拟文件系统存储在 Durable Object SQLite 中，owner 与 DeepSeek 凭据则保留在只写 Worker secret 中。
- 增加引导式安装器 Hero、临时账户与已有账户路径、明确的费用和恢复信息，以及对 Cloudflare 路由正常激活过程的有界观察。
- 使用完整发布的 Harness `0.1.0-rc.8` 基线，包括保留被中断的 assistant 前缀、reasoning continuation 修复、统一 provider 重试和有界的多查询 DeepSeek Web Search。
- 通过上游 Settings UI 中的 Edge 自有 plugin 展示部署版本、运行时、存储、credential readiness、升级指引和 owner 登出。

## 安装或升级

需要 Node.js 22.14 或更高版本，以及你自己的 DeepSeek API key。

```sh
npx dsh-edge install
```

已有稳定部署可以原地升级：

```sh
npx dsh-edge upgrade
```

如果当前安装的是 `0.2.0-alpha.1`、`alpha.2` 或 `alpha.3`，请执行一次以下命令，从预发布渠道切换到稳定版：

```sh
npx dsh-edge@latest upgrade
```

Durable Object、session、workspace 和 VFS 数据与 0.1.3 及 0.2 alpha 保持兼容。Cloudflare secret 只能写入、不能读回，因此升级时仍需重新输入现有 owner access key 与 DeepSeek API key。

## 范围与兼容性

部署继续有意采用 single-owner 模式。0.2.0 不包含附件与图片、`web_fetch`、`@file` 与 `@session` 引用、remote MCP、Skills、Workflows、Jobs 和 Subagents。Direct 模式仍是 just-bash 环境而非 Linux 容器；Dynamic Worker 模式需要符合条件的 Cloudflare 付费套餐。

所有已发布 Harness package 均固定在 `0.1.0-rc.8`。保留的六项 Edge 适配都有版本边界并经过机械验证。Durable Object 会话存储继续使用 Edge schema v2；上游 Node SQLite schema 不适用于这里，该版本不执行持久化数据迁移。

## 发布完整性

npm package 从经过 Review 的 `dsh-edge-v0.2.0` tag 发布到 `latest` dist-tag。发布 workflow 会核对精确的 tag 与 package version，重新构建确定性的 standalone 装配，验证 Direct 与 Dynamic Worker 两种模式、0.1.3 持久化数据兼容性和 browser/runtime snapshot，并在可信发布前从 workspace 外安装打包产物。配套 GitHub Release 会携带完全相同的 tarball asset。
