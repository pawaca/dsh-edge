## dsh-edge 0.15.0-alpha.1

上游基线升级至 0.1.5-rc.2。发布至 npm 的 `next` 频道供测试；稳定的 `latest` 频道保持不变。

### 变更

- **上游基线 0.1.5-rc.2**（#169）：所有 `@deepseek-ai/dsh-*` 依赖从 0.1.2-rc.1 升级至 0.1.5-rc.2。带来 Session Format V3、基于 SessionHandle 的持久化 API、动态 System Prompt 支持和 DeepSeek-V41-Flash 模型。
- **SessionPersistence 重写**（#169）：`DurableObjectSessionPersistence` 基于新的 `SessionHandle` API 重新实现。旧的 `PersistenceCoordinator`/`PersistenceBackend` 委托被替换为每 session 的 handle，handle 拥有 append、flush 和 close。写入所有权追踪防止并发写入。实时 session 事件通过 handle 缓冲路由。DO SQL 存储层（表结构、事件编码、摘要物化）保持不变。
- **Session Format V0→V3 惰性迁移**（#171）：以 format V0（0.1.2-rc.1 时代格式）存储的 session 在首次打开时透明迁移至 V3，使用上游 `dsh-session-format-catalog` 迁移链。迁移在 DO SQL 事务内运行。
- **Persona 配置**（#169）：`SystemPrompt` 插件配置中 `persona:` 重命名为 `personaPrefix:`。

### 新增

- **DeepSeek-V41-Flash**（上游）：新的默认模型，支持文本 + 图像输入和会话内 system prompt 更新。

### 补丁

- **已移除**：`dsh-session-persistence`（上游删除了 coordinator）、`dsh-message-feedback`（上游改用事件溯源）。
- **已重基**：`dsh-api-gateway`、`dsh-llm`、`dsh-tool-web`、`dsh-web-search-deepseek`（简单重基）、`dsh-api-session-controller`、`dsh-web-fetch-http`、`dsh-workspace`（因上游变更需要重写）。

### 试用 Alpha 版

使用 `npx dsh-edge@0.15.0-alpha.1 upgrade` 升级现有安装，或使用 `npx dsh-edge@0.15.0-alpha.1 install` 创建新安装。

建议检查：验证现有 session 在 V0→V3 迁移后能正常打开和继续；验证新 session 使用正确的格式；测试跨 turn 的后台子代理。
