# dsh-edge 0.3.0-alpha.2

English | [中文](https://github.com/pawaca/dsh-edge/blob/dsh-edge-v0.3.0-alpha.2/docs/releases/0.3.0-alpha.2.zh.md)

This corrective prerelease keeps the model and image capabilities introduced in alpha.1 while removing an unnecessary R2 activation barrier for existing Workers Free deployments.

## Highlights

- Detects Workers created before image support and asks once where new images should live: bounded Durable Object storage, which needs no R2 setup, or a private R2 bucket.
- Defaults that legacy-upgrade choice to Durable Object storage with a clear 64 MiB per-instance limit.
- Checks R2 before collecting Worker secrets. Cloudflare error `10042` now shows the account-specific activation URL and lets a safe legacy upgrade retry, switch to DO, or cancel without restarting the installer.
- Preserves every existing attachment marker or authoritative R2 binding; no deployment with image references is silently moved between backends.
- Keeps new permanent installations on private R2 and explains that R2 Standard has an included monthly free tier but requires its separate usage-based subscription to be enabled first.
- Updates the read-only `agent.cordis.yml` projection to distinguish the deployment-default model from per-session selection and to list the runtime-derived upstream DeepSeek catalog.
- Removes Wrangler's known Node `punycode` deprecation warning from concise installer errors while leaving complete diagnostics available with `--verbose` and in Wrangler logs.

## Install or upgrade

Requires Node.js 22.14 or newer and your own DeepSeek API key.

```sh
npx dsh-edge@next install
```

Upgrade an existing Worker in place:

```sh
npx dsh-edge@next upgrade
```

A Worker already marked `temporary-do` or `private-r2` keeps that backend without another prompt. Only a pre-0.3 Worker with neither an attachment marker nor an R2 binding receives the one-time choice. Because that release could not store image references, either initial backend is safe. If R2 is not enabled, the same guided run can switch that still-unpinned Worker to DO; new or R2-pinned deployments must activate R2 and retry or cancel. The choice is pinned after deployment and automatic migration remains out of scope.

## Limits and compatibility

Durable Object image storage is capped at 64 MiB per owner instance. R2-backed deployments require an enabled R2 subscription and remain subject to Cloudflare usage billing beyond the included Standard free tier. Both backends accept PNG and JPEG only, at most 4 images per message, 3.5 MiB per image, 7 MiB per message, 40 million pixels, and 2,000 pixels per side.

Vision Exp remains experimental and may not be enabled for every DeepSeek account. The deployment remains single-owner; the other deferred Edge capabilities listed in alpha.1 are unchanged.
