## dsh-edge 0.16.0

将 MCP Connectors 运行时从 0.16.0-alpha.1 提升至 npm `latest` 稳定频道。上游 Harness 基线保持 0.1.5-rc.2。

### 自 0.15.1 以来的变更

- **MCP Connectors** (#186, #189, #191–#203)：通过 Streamable HTTP 传输连接外部 MCP 工具服务器。Edge 使用 `@modelcontextprotocol/sdk@1.30.0` 实现的 `edge-mcp-client` 替换了上游 `dsh-mcp-client`——上游插件的 stdio 传输和子进程 `inject` 依赖与 Workers 不兼容。工具通过分页 `tools/list` 发现，注册到 `ctx.tools`，模型视角与内置工具无异。
- **认证** (#189, #199)：三种认证模式——`none`、`bearer`（token 通过 `CredentialProvider` 存储）、`oauth`（OAuth 2.1，支持 PKCE、动态客户端注册、RFC 9728/8414 路径感知发现，自动刷新 token）。
- **工具策略** (#192, #193)：每连接器策略——`allow_all`、`read_only`（默认）、`approve_all`——支持 `readOnlyHint` 注解和 glob 模式自动放行。
- **工具审批** (#185)：Edge 自有 `tools/pre-execute` 瀑布流拦截 `web_fetch`、`mcp__*` 工具和 `mcp_call`。设置界面可在 `ask` 和 `never` 间切换。每连接器 MCP 策略独立于全局模式判断。
- **SSRF 防护** (#194, #195, #199, #205)：私有 IPv4/IPv6 地址段、IPv4 映射 IPv6（`::ffff:<私有>`）、FQDN 尾部点号规范化，以及 `.internal`/`.local`/`.localhost` 主机名被阻止；`localhost`/`127.0.0.1`/`::1` 放行以支持开发。HTTP 重定向被阻止。JSON Schema 校验使用 `@cfworker/json-schema`。
- **Meta-tool 模式** (#202)：当会话启动时 MCP 工具总数超过 20 个，Edge 注册 `mcp_search` + `mcp_call` 代替逐个注册，并在系统提示词中扩展服务器摘要。
- **MCP 结果处理** (#197, #198)：MCP 2025-03-26 规范的 `outputSchema`、`structuredContent` 和图片投影（PNG/JPEG 通过附件管道）。
- **热替换** (#191)：重新探测服务器时替换工具注册，无需重启会话或 DO。dispose 和 re-probe 时清除过期的 meta-tool 条目。
- **设置界面** (#200, #201)：独立的"MCP Connectors"标签页，支持服务器管理、工具列表、认证、每连接器策略和 OAuth 连接流程。
- **存储** (#203, #205)：每服务器工具目录 key 配合内存缓存，字节精确的 128 KB 目录上限（含 trim loop），旧内嵌格式自动迁移。

### alpha.1 中包含的修复

以下审查驱动的加固修复在 alpha.1 开发期间（#205）完成，属于其已发布的运行时。稳定版提升未引入运行时变更。

- **SSRF 加固**：阻止 IPv4 映射 IPv6 地址（支持点分和 URL 解析的十六进制形式）；将链路本地覆盖扩展至完整 fe80::/10；在后缀检查前规范化 FQDN 尾部点号。
- **目录上限**：从 UTF-16 字符串长度切换为 `TextEncoder` 字节长度；增加 trim loop 和单条目 schema 剥离兜底，确保 128 KB 限制对 CJK 内容有效。
- **Meta-tool 清理**：在服务器 dispose 和 re-probe 时清除过期 `toolMeta` 条目，使重命名/移除的工具立即被 `mcp_call` 拒绝。

### 验证与升级

Alpha.1 通过 478 项测试、类型检查和六轮自动化代码审查。稳定版保留该运行时不变。

使用 `npx dsh-edge@latest upgrade` 升级。已有 alpha 部署应使用 `@latest` 切换到稳定频道。此版本不引入 alpha.1 之外的新存储 schema 或迁移。
