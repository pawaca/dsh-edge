## dsh-edge 0.17.0-alpha.1

为 Isolated（Dynamic Worker）运行时带来两个多步骤工具的首个预览版：`workflow`（用一个脚本编排多个子 agent）和 `run_code`（运行调用其他工具的 TypeScript 程序）。本版发布至 npm 的 `next` 频道，`latest` 仍为 0.16.0。建议先在测试实例上试用，再升级主要部署。上游 Harness 基线保持 0.1.5-rc.2。

### 新增

- **运行时 provider**（#209）：Direct Shell 与 Dynamic Worker 被建模为运行时 provider，各自带有能力与套餐要求。Worker 和安装器从同一份目录推导运行时信息。只有部分 provider 提供的能力，在对应 provider 不可用时直接缺席，而不是以损坏的状态出现。这一项本身不改变任何行为。
- **`workflow` 工具**（#210，仅 Isolated）：即上游的 `dsh-tool-workflow` 编排工具。模型编写一个脚本，用 `agent()`、`parallel()`、`pipeline()`、`phase()`、`log()` 把工作分发给多个子 agent。
  - 每次运行都在独立的 Dynamic Worker 中执行脚本，没有出站网络，并受 Worker Loader `cpuMs` 上限约束。之所以这样做，是因为 workerd 禁止上游引擎依赖的进程内 `eval`、`new Function` 和 `node:vm`。
  - `agent()`、`phase()`、`log()` 经 RPC 桥回到 Durable Object，由 DO 执行各项上限：同时最多 4 个子 agent，单次运行最多 100 个。请求、回复、进度和结果的大小也都有上限。
  - 取消当前轮次时，会销毁隔离环境并取消所有子 agent。
- **`run_code` 工具**（#211，仅 Isolated）：即上游 `dsh-tools` 的 PTC 模式，以 `both` 方式启用，与原生工具并存。模型编写 TypeScript 程序，用 `await tools.name(args)` 调用工具。
  - 程序先用 sucrase 去除类型，再在独立的 Dynamic Worker 中运行。
  - 每次嵌套调用都是一次普通的工具派发，审批和 spill 照常生效。
  - 单次运行的上限：嵌套调用最多 200 次，每次调用的参数最多 256 KiB，单次结果最多 2 MiB，总输出最多 1 MiB。
  - 每轮 prompt 都会附带一段生成的工具 SDK 说明，会额外消耗输入 token。

### 修复

- **隔离环境回调的轮次上下文**（#212）：workflow 或代码隔离环境回调 Durable Object 时，现在会在发起它的那次工具调用的上下文中执行。修复之前，`run_code` 里调用文件工具会报错："File operations are only available during an active turn"。

### 上限

| 项目 | workflow | run_code |
|---|---|---|
| 隔离环境 CPU（`cpuMs`） | 30 秒 | 30 秒 |
| 并发子 agent / 嵌套调用 | 4 | 4 |
| 单次运行的子 agent / 嵌套调用总数 | 100 | 200 |
| 墙钟时间 | 受驻留期限约束（10 分钟） | 5 分钟 |
| 结果 | 1 MiB | 总输出 1 MiB |

### 验证与升级

`pnpm run check` 共 534 个测试全部通过。集成测试在两种发布产物上都跑过：Direct 产物断言这两个工具都不存在；Isolated 产物跑了一个 5 个子 agent 的 workflow，以及一个先写文件再读回的 `run_code` 程序。本地用真实模型测试了：
- 3 个和 6 个子 agent 的 workflow，包括结构化输出和中途取消
- `run_code` 调用 bash、文件工具和 `web_fetch`，以及审批流程
- 刷新页面后的历史回放
- UI 渲染

一次 6 个子 agent 的 workflow 约写入 135 行 session 事件。本地 workerd 不执行 `cpuMs`，该上限只能在生产环境验证。

测试实例可用 `npx dsh-edge@next upgrade` 升级。新工具只出现在 Isolated 部署中，Direct 部署不受影响。本版没有新增存储结构或迁移。
