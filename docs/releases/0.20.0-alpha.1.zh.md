## dsh-edge 0.20.0-alpha.1

挂载了四个改变 agent 工作方式的上游 Harness 插件：重复同一工具调用时的提醒、模型请求临时失败的重试、防止覆盖未读过的文件，以及在模型请求和工具调用之前的持久化检查点。本版发布至 npm 的 `next` 频道，`latest` 仍为 0.19.3。上游 Harness 基线仍为 0.2.0-rc.2，会话格式仍为 V4，所以从 0.19 升级不会迁移任何已存数据。

### 新增

- **重复工具调用提醒**（#261）：连续 3、5、8 次完全相同的工具调用之后，agent 会在下一次模型请求前收到一条提醒，告诉它正在重复自己。
- **模型请求重试**（#262）：遇到限流、服务端错误、超时、网络错误或空响应时，在同一轮内重试，最多 5 次，等待 0.5–10 秒，或按服务端 `Retry-After` 要求的时长。每次重试都会在等待之前记入会话。重试无法解决的错误不会重试，例如模型不存在（404）。
- **文件写入保护**（#263）：
  - `edit`，以及用 `write` 覆盖已有文件，要求 agent 在本会话中读过该文件，否则会被拒绝。
  - 文件在 agent 读过之后被改动过（例如被一条 `bash` 命令写入）时，两者同样会被拒绝。
  - 对同一文件的写入和编辑逐个执行，所以基于同一次读取的两个并发改动，一个成功，另一个会因文件已过期被拒绝。
- **持久化检查点**（#265）：每次模型请求、每次顶层工具调用和每一步之前，先保存会话日志。之前事件最多晚约 100 毫秒才保存，所以工具可能在其调用保存之前就已开始执行，若恰好在这个窗口内重启，就会丢失这次调用的记录。这会多写少量行：不调用工具的一轮约多 5 行，调用 3 次工具的一轮约多 22 行。

### 已知限制

- 从 0.18 升级后不支持退回 0.18。
- 0.18 的插件配置卡片（Agent loop、Web search）移到了上游插件管理器中，Edge 没有提供插件管理器。
- Agent 预设页的介绍和模式说明提到了上游的 Creator 模式，Edge 不提供该模式。
- 尚未接入的上游包包括待办列表（#234）；[wiki 路线图](https://github.com/pawaca/dsh-edge/wiki/Roadmap-zh)列出了所有剩余缺口。
- 0.18.0 中关于 Node 22 测试环境、本地 `dev:container` 清理以及指向 `/workspace` 之外的符号链接的限制仍然存在。
- 文件写入保护只覆盖 `write` 和 `edit` 工具。在受保护的写入进行期间，由 shell 或容器命令写入的文件改动不会被发现，这与上游一致；在受保护的写入之前已完成的改动会被发现。

### 验证与升级

`pnpm run check` 通过 849 个测试。集成测试覆盖两个发布产物（Direct 和 Isolated），新增了提醒、限流后重试、拒绝未读和已过期编辑，以及检查点写入批次的检查。打包后的安装器通过 `pack:verify`。`upgrade-from-release.probe.mjs` 分别升级由已发布的 0.19.3 和 0.18.0 创建的数据，各通过 11 项检查。在 0.19.3 的数据上，本版约 0.6 秒启动，无需迁移。在加入检查点之前于本地实测，每一轮的写入行数与 0.19.0 相同，空闲的实例不会设置 alarm。

用 `npx dsh-edge@next upgrade` 升级测试实例，选择"Update it"。
