## dsh-edge 0.19.3

把上游 Harness 基线从 0.2.0-rc.1 升级到 **0.2.0-rc.2**（#254），并修复了生成的会话标题在重启后丢失的问题（#253）。本版发布至稳定的 npm `latest` 频道。这是 0.19.0 之后第一次发布到 npm：0.19.1 和 0.19.2 已打 tag，但它们的发布流程在 Windows 浏览器快照检查处停止，未能发布（#256、#259）。会话格式仍为 V4，所以从 0.19.0 升级不会迁移任何已存数据。从 0.18 升级仍会按 [0.19.0](0.19.0.zh.md) 所述把会话迁移到 V4，之后不支持退回 0.18。

### 变更

- **定时提醒到点后会被执行。** 上游 rc.2 把到点的提醒表述为用户的定时消息。0.19.0 中，模型被要求把提醒当作不可信内容来展示，所以像"搜索今天的新闻并总结"这样的提醒只会被转述。现在模型会去完成这个任务。提醒由所有者创建，或由 agent 按所有者的要求通过 `schedule_create` 创建。
- **Bash 路径安全。** `bash` 工具现在和上游一样，要求模型在任何删除或移动之前核对解析后的绝对目标路径，并在这类路径中用 `${VAR:?}` 保护变量，使未设置的变量让命令中止，而不是展开为空路径。
- **网页客户端**随上游 rc.2 更新：
  - 模型选择器可以在较长的列表中搜索；
  - 切换会话后计划审阅仍能打开；
  - 耗时显示为"Completed in …"；
  - 过程详情和深色主题样式有所优化。

### 修复

- **生成的标题可能在重启后退回**（#253）。一轮结束后才生成的标题会立即显示在会话列表中，但要在一个短暂的写入窗口（约 250 毫秒）之后才保存；如果 Worker 恰好在这个窗口内重启（例如部署），就会退回到备用标题。现在标题一变化就会保存，每个会话在每个窗口内最多立即保存一次，连续改名仍会合并写入。受影响的始终只有标题。

### 已知限制

0.19.0 列出的内容仍然适用。

### 验证与升级

`pnpm run check` 通过 847 个测试。集成测试覆盖两个发布产物（Direct 和 Isolated），打包后的安装器通过 `pack:verify`。`upgrade-from-release.probe.mjs` 分别升级由已发布的 0.19.0 和 0.18.0 创建的数据，各通过 11 项检查。在 0.19.0 的数据上，本版约 0.6 秒启动，无需迁移。Edge CI 现在会在每次改动时运行发布流程中的 Windows 集成测试和浏览器快照检查（#259），本版的提交在打 tag 之前已经通过了这些检查。

用 `npx dsh-edge@latest upgrade` 升级，选择"Update it"。
