# dsh-edge 0.2.0-alpha.2

[English](https://github.com/pawaca/dsh-edge/blob/dsh-edge-v0.2.0-alpha.2/docs/releases/0.2.0-alpha.2.md) | 中文

这个预发布版本主要改善首次使用体验，并增强发布工具链的可移植性。DeepSeek Harness 基线仍为 `0.1.0-rc.7`，Worker 行为和持久化数据契约与 alpha.1 保持一致。

## 主要变化

- 安装器新增不依赖第三方包的 dsh-edge Hero，明确展示产品用途、package version、社区项目边界和当前操作。
- Wrangler 接受上传后观察公开健康检查端点，让安装器可以区分 Worker 已就绪和 Cloudflare 正常传播延迟。
- 提示激活通常需要 10–30 秒，最多等待 45 秒，并在不发送 owner 或 DeepSeek 凭证的前提下展示明确的已就绪、等待中或恢复指引。
- Wrangler 接受上传仍是安装成功边界：公开路由延迟不会把已接受的部署误判为安装失败。
- GitHub Actions 更新到 `actions/checkout@v7` 和 `actions/setup-node@v7`，pnpm 11 workflow 迁移到官方后继方案 `pnpm/setup@v2`。
- 发布工具现在同时兼容传统的 pnpm JavaScript 入口和新版 setup action 使用的独立 pnpm 可执行文件。

## 安装或升级预发布版本

需要 Node.js 22.14 或更高版本，以及你自己的 DeepSeek API key。

```sh
npx dsh-edge@next install
```

已有预发布部署可以原地升级：

```sh
npx dsh-edge@next upgrade
```

`next` dist-tag 将指向 alpha.2，`latest` 仍停留在 0.1.3。Durable Object、session、workspace 和 VFS 数据保持兼容。由于 Cloudflare secret 只写不可读，升级时仍需重新输入现有 owner access key 和 DeepSeek API key。

## 范围与兼容性

Direct Shell 与 Dynamic Worker 两种模式继续保持行为一致；固定的上游装配仍使用 `0.1.0-rc.7` 和原有六个经过审计的 patch。这个版本不引入新的认证模型、存储迁移、公开 API 变化或上游插件。

部署仍有意保持 single-owner。附件与图片、远程 MCP、Skills、Workflows、Jobs 和 Subagents 尚未适配 Edge runtime。`web_fetch` 在具备明确的网络访问策略前继续保持禁用。

## 发布完整性

npm package 从经过 Review 的 `dsh-edge-v0.2.0-alpha.2` tag 发布到 `next` dist-tag。发布 workflow 会核对精确的 tag 与 package version，重新构建固定的 standalone 装配，验证 Direct 与 Dynamic Worker 两种模式、0.1.3 持久化数据兼容性和 browser/runtime snapshot，并在可信发布前从 workspace 外安装打包产物。配套 GitHub prerelease 会携带完全相同的 tarball asset。
