## dsh-edge 0.30.0-alpha.1

有 Cloudflare Images 绑定时，图片可以更大、格式更多；`@file` 补全会搜索整个工作目录；另有几项 Edge 行为改为与上游完全一致：重命名与分叉、会话存储契约、凭据变更通知以及 `/` 技能菜单。发布到 npm 的 `next` 渠道；`latest` 仍为 0.29.0。上游基线仍为 0.2.1-rc.2，会话格式仍为 V4；会话摘要新增一列，在启动时添加。

### 新增

- **图片优化**（#348，#381）：Worker 带有 Cloudflare Images 绑定（`IMAGES`，安装器会为自有账户启用）时，图片可以是 PNG、JPEG、WebP 或 GIF（取第一帧），单边最多 8,192 像素、最多 6,400 万像素，每张最多 7 MiB，每条消息最多 8 张，合计最多 7 MiB。
  - 不超过 2048 × 2048 像素和 4 MiB、且没有 EXIF 旋转的 PNG 或 JPEG 按原样保存，与上游一致，不做任何转换。
  - 其他图片只转换一次：缩放到上游的像素预算，按 EXIF 方向转正，保存为 JPEG；可能含透明度时保存为 WebP。
  - 没有该绑定时限制不变（PNG 或 JPEG，单边 2,000 像素，每张 3.5 MiB，每条消息 4 张）。之后即使移除绑定，按较大限制保存的图片仍可读取。
- **递归 `@file` 补全**（#353，#380）：与上游本地 provider 一样，裸片段会在工作目录下的所有文件中模糊排序，因此 `@rdm` 能找到 `docs/README.md`。带 `/` 的查询仍然列出那个目录，现在也可以是工作目录内的绝对路径。索引跳过 `.git`、`node_modules`、`dist`、`build` 以及其他依赖和构建输出目录。
- **`run_code` 说明自己的运行环境**（#352，#376，仅 Isolated）：工具描述告诉模型，每次调用都在全新的隔离环境中运行，没有文件、网络或模块导入，并列出它的限制（200 次工具调用、每个工具结果 2 MiB、输出 1 MiB、300 秒、30 秒 CPU 时间）。

### 变更

- **凭据变更会刷新页面**（#351，#375）：保存或删除密钥时会发出上游的 `credentials/reference-updated`，已打开的 Models 页面、模型菜单或网页搜索卡片无需重新加载就会更新。
- **重命名和分叉与上游一致**（#349，#377）：在首条提示的标题仍在生成时重命名，现在以用户的标题为准；以前自动标题会覆盖它。带 `atSeq` 的分叉精确地在该事件处截断，不带时取上游规则下最近一个已完成回合的前缀；不存在的事件会被拒绝。
- **会话存储契约**（#350，#378）：Durable Object 存储现在应用上游自己的检查。当前版本不认识的事件类型（例如回滚之后）会被拒绝而不是重放；追加必须连续且能无损序列化；有界读取只读取它需要的行。为了让写入打开时的检查不必扫描日志，会话摘要会记录已存储的事件类型；本版本之前存储的会话会在下次写入时扫描一次。
- **`/` 技能菜单**（#353，#380）：`skills/list` 统一由上游的技能目录回答。Edge 在列出之前会重新检查会话的技能根目录，因此新写入的技能会出现；已经运行过回合的会话也不会再因 "File operations are only available during an active turn" 而失败。

### 已知限制

- `@file` 补全在一个工作目录中的第一次裸查询会读取索引，每个条目约读取 3.5 行 Durable Object 数据，最多 10,000 个条目（上游为 50,000）和 1,000,000 个路径字符；之后的查询约读取 2 行。与上游一样，索引只在工具返回结果后刷新，因此上传的文件或通过属主 API 写入的文件，要到下一次工具调用之后才能被裸查询找到；带 `/` 的查询始终实时读取目录。最多保留 4 个工作目录的索引。
- 图片转换计入账户的 Cloudflare Images 额度（免费计划每月 5,000 次不同的转换，超出后报错 9422）。转换失败时，符合无绑定限制的图片按原样保存，更大的图片会被拒绝并给出原因。Images 的 EXIF 旋转目前只依据 Cloudflare 文档确认，尚未在已部署的实例上验证；本地开发环境不会旋转。
- Web 客户端把图片放在 10 MiB 的提示请求体中发送，因此单张图片限制为 7 MiB，而上游允许 20 MiB。
- 新建会话与上游存储契约仍有两处已有差异：头部行在创建时写入，空的新建会话会作为空白会话保留（#379）。
- 0.29.0 列出的其他限制仍然适用。

### 验证与升级

`pnpm run check` 通过 1,113 项测试。新增测试覆盖凭据通知（包括网页搜索卡片的浏览器快照）、`run_code` 描述、标题生成期间的重命名和分叉截断、存储契约（读取校验、连续性、无损 JSON、记录的事件类型和一次性扫描）、`@file` 索引（排序、上限、共享、过期、淘汰以及一次只读一个），以及图片规范化（四种格式的头部解析、不经转换的直通、转换及其失败处理）。

集成测试针对两种发布产物（Direct 和 Isolated）运行。新增检查：
- `$events` 在设置和删除凭据后收到 `credentials/reference-updated`；
- 标题生成被挂起时重命名，保留用户的标题；精确和默认的分叉截断；拒绝不存在的 `atSeq`；
- 按 Web 客户端的方式调用 `skills/list`，包括在已运行过回合的会话上，列出之后新写入的技能；
- `@ndlref` 找到嵌套文件，以及绝对路径的目录查询；
- `run_code` 描述（Isolated）。

新增的快照测试在绑定了 Images 的本地 Worker 上运行提示路由：一张 4K PNG 被保存为 2730 × 1536 的 JPEG。

在 Workers 运行时中本地测得：
- `row-cost.probe.mjs` 对比 0.29.0：普通回合写入的行数相同（九个回合共 443 行 SQL、36 次 KV 与 alarm 写入）。冷恢复读取 615 行，0.29.0 为 604 行，多出的是启动时对新摘要列的检查。在 200 个条目的目录树上，第一次裸 `@file` 查询读取 741 行，之后每次 2 行（0.29.0 为 15 行）。
- `upgrade-from-release.probe.mjs` 升级由已发布的 0.29.0 创建的状态，通过 11 项检查。

发布产物仍在 Cloudflare 的 64 MiB 大小限制内（Direct 8.3 MB，Isolated 9.7 MB）。尚未在 staging 实例上验证。

用 `npx dsh-edge@next upgrade` 升级测试实例，并选择"Update it"。
