# dsh-edge 0.2.0-alpha.1

[English](https://github.com/pawaca/dsh-edge/blob/dsh-edge-v0.2.0-alpha.1/docs/releases/0.2.0-alpha.1.md) | 中文

这是独立 dsh-edge wrapper 的第一个预发布版本。它保留已经发布的 0.1.3 Cloudflare runtime 与持久化数据约定，同时用精确依赖已发布 package 的装配替代 DeepSeek Harness 源码 fork。

## 主要变化

- 直接从 npm 安装，不需要克隆仓库、连接 GitHub 或配置 Cloudflare Builds。
- 在同一个 package 中提供 Workers Free Direct Shell 模式，以及可选的 Workers Paid Dynamic Worker 模式。
- 运行上游 DeepSeek Harness Web UI、agent loop、HTTP/WebSocket 协议、持久会话、workspace VFS、bash 工具与 DeepSeek Web Search。
- 将上游 Harness 依赖闭包固定在 `0.1.0-rc.7`，并保留 6 个经过审计、绑定精确版本的装配 patch。
- 保持 0.1.3 Durable Object、session/event、workspace 与 VFS 格式不变。
- 增加 Edge 设置页，展示已安装版本、npm 更新渠道、版本说明、升级指引、运行时诊断与 owner session 管理。

## 安装或升级预发布版本

需要 Node.js 22.14 或更高版本，以及你自己的 DeepSeek API key。

```sh
npx dsh-edge@next install
```

已有 0.2 预发布部署继续使用相同渠道：

```sh
npx dsh-edge@next upgrade
```

Alpha 期间，稳定的 `latest` 渠道仍停留在 0.1.3。升级会保留 Durable Object 数据；但 Cloudflare secret 只能写入，升级时需要重新输入已有 owner access key 与 DeepSeek API key。

## 当前范围

部署有意采用 single-owner 模式。附件与图片、远程 MCP、Skills、Workflows、Jobs 和 Subagents 尚未适配 Edge 运行时。`web_fetch` 在具备明确的 SSRF、私网地址与重定向策略前保持关闭。Direct Shell 不是 Linux 容器，不能暴露给不受信任用户。

## 发布完整性

npm package 从经过 Review 的 `dsh-edge-v0.2.0-alpha.1` tag 发布到 `next` dist-tag。手动请求 workflow 会把该 tag 转交给锚定在默认分支的发布自动化；未 Review 的 tag revision 无法替换获得 npm 发布权限的 workflow。发布 workflow 会在 publication 前重新构建并验证固定版本的 standalone 装配、两种 Worker 模式、0.1.3 持久化数据兼容性、browser/runtime snapshot 与已安装 tarball。配套 GitHub prerelease 会携带完全相同的 tarball asset。
