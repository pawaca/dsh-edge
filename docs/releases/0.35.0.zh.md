## dsh-edge 0.35.0

从 Edge 0.34.0 / Harness 0.2.1-rc.4 升级到 DeepSeek Harness 0.2.2-rc.1 的 Edge 正式版本。沿用 0.35.0-alpha.1 已验收的运行时代码；精确固定的上游基线仍是预发布版本。

### 变更

- 将已发布的 Harness 依赖闭包精确固定到 0.2.2-rc.1，刷新上游对等表，并组装新增浏览器插件及其声明的资源文件。
- 适配 Host Schedule API，包括 RRULE、版本冲突、暂停/恢复、立即执行和投递历史；保留原会话目标、SQL 任务存储及 DO 闹钟。自动创建新会话的目标仍不可用。通过对话创建任务，不支持的手动创建表单已禁用。修改已暂停任务不会恢复投递。
- 增加有界“复制为 Markdown”：最多 2,048 个事件，输入及输出分别限制为 4 MiB。超限返回 HTTP 413，并引导使用流式“下载会话日志”。每个 DO 只允许一个复制占用名额直到响应完成；超出并发的请求返回带 Retry-After 的 429，停滞响应在 30 秒后超时。
- 保留 Trajectory，原始 JSON 仅保存在活跃实例中：每条结果 256 KiB、每个会话 1 MiB、全局 4 MiB。超限、已淘汰或冷会话的结果明确显示不可用。
- 增加文件系统 patch/delete/move 提供方接口和删除记录。apply_patch 工具仍未启用，Edge 继续执行先读后写策略。
- 将模型/预设服务、native/PTC 工具执行器、暂存图片上传和文件流式读取接入新的公开接口。列表摘要遵循上游摘要键；统计和待办等完整投影仍由专用 Session API 提供。即使禁止为子代理选择其他模型，模型发现仍可展示继承的模型路线。
- 修正启动性能检查，使其测量每个已提升的 Worker 产物，避免 Wrangler 回退到源码配置。
- 限制每次 alarm 的处理批次并复用恢复截止时间；先分页再查询任务执行状态，用已有 due 索引避免反复扫描全部任务。
- RPC、命令排队、MCP 和 OAuth 操作结束后释放请求超时定时器，使空闲 Durable Object 可以休眠。空闲/重连浏览器回归现已默认执行。
- 模型目录过期后在访问时刷新，保留 TTL 和并发加载合并，不使用空闲后台定时器。

### 兼容性与限制

保留已有会话和工作区状态。这不代表仅替换二进制即可安全降级：旧基线可能无法读取新增 RRULE 任务或普通分叉中的继承投递确认。恢复时需要升级前的状态备份。

Web Fetch 保留 Workers fetch、逐跳 URL 检查和现有 strictly-public 平台标记。URL 检查本身不固定 DNS。有限 staging 验收中的公网抓取已通过；解析到私网的 DNS 边界仍未验证。每次生产部署仍需核对账户预算及可用恢复流程。

完整逐包处置、限额、验证结果和剩余门槛见[基线适配记录](../upgrades/0.2.2-rc.1.zh.md)。

### 验收与已知容量限制

- 从正式版 0.34.0 创建的状态原地升级，本地 11 项检查全部通过。alpha 真实发行产物的 Direct、Dynamic 和 Container 验证通过。
- 本地九回合对照中，SQL 写行 441，0.34.0 为 443；KV/alarm 写操作均为 36。同一候选版本内，批处理将 128 次任务执行的 alarm 回调从 128 降至 4、setAlarm 从 385 降至 9；这组优化对照不是与 0.34.0 比较。
- 有限 staging 验收覆盖真实模型对话、文件与附件、Container 命令、Markdown、Trajectory 及任务生命周期，包括原生浏览器控件。被动观察确认日程 alarm 触发 DO 重建，仅投递一次并完成回复，投递比计划时间晚约 0.77 秒。
- 长历史容量仍有已知风险：本地组合负载堆采样达到 170.1 MiB，旧版对照达到 172.9 MiB。GC 时机不同，不能据此精确比较内存退化；两者都不能证明满足 Workers 内存限制。有限 staging 场景最高周期采样约 83.7 MiB，未记录 CPU/内存超限或 fatal-internal 错误，但不代表最坏容量。本版不宣称解决历史驻留压力，也不承诺未经验证的安全历史长度或会话数量阈值。

长历史容量风险独立于基线升级跟踪。新增恢复工具和生产部署不属于本次发布改动。
